## 적용 조건

Decision Queue(결정 대기 목록)·추가 결정 요청·권고 목록을 작성하거나 사용자 GO 뒤 실행할 때 적용한다.

## 핵심 원칙

사용자가 이미 명시·결정한 사항을 다시 묻지 말 것. 사용자 결정은 그대로 실행한다. 「이미 명시·결정한 사항」 = 사용자 원문 메시지, 또는 출처(원문·요청 대장 행)가 붙은 기록의 결정이다 — 출처 없이 「사용자 결정」 으로만 적힌 기록은 원문을 한 번 찾아, 찾으면 그대로 실행하고(재질의 아님) 못 찾으면 「근거 미발견」 으로 두고 그 기록을 기본값으로 진행하며 결정 대기에 「근거 미발견 결정」 으로 올려 묻는다(묻는 때 = 아래 「질문 시점」 · blocking 판정 = [[feedback_flow_interruption]] · 원본 = [[feedback_confirmed_items_policy]] 원칙 1).

**질문 시점** — 멈출 일은 계획 §11 「멈출 일 미리 점검」에서 미리 묻고, 실행 중 조금이라도 애매한 것(승인 범위 안의 nonblocking)은 멈추지 말고 합리적 기본값으로 진행하고 결정 대기 목록에 적어 **모든 작업이 끝난 뒤 최종 보고에서 한 번에** 묻는다(중간에 멈춰 팝업으로 묻지 않는다 · [[feedback_flow_interruption]]).

## 이유

사용자가 이미 결정한 사항을 다시 묻는 것은 지시 불이행이며 사용자 시간의 직접 손실이다. 결정을 다시 올리는 순간 사용자는 같은 판단을 두 번 해야 하고 그 사이 작업은 멈춘다. 같은 회피가 "사용자 작성 대기" placeholder 로 나타나면 미완이 사용자에게 그대로 넘어간다.

## 실행 방법
1. **사용자 결정 추적**: 사용자가 이전 메시지에서 "X 하자" / "X가 답" / "X로 진행" / "X 이다"라고 동의·확인한 형태로 결정한 사항은 그 즉시 실행 명단에 등록.
2. **Decision Queue 작성 시점에 점검**: 작성 직전에 모든 항목을 사용자 이전 메시지 **및 지침 문건(헌법·스킬·커맨드·memory)에 이미 정해진 방식**과 cross-check:
   - 지침·헌법·memory 에 이미 정해진 방식 → 결정 항목이 아니라 그대로 실행(재질의 X · [[feedback_execute_explicit_choice_not_judgment]]).
   - 사용자가 이미 결정 → Decision Queue 에서 제거, "확정 사항"으로 분류.
   - 사용자가 결정 안 함 → Decision Queue 에 보존.
   - 결정 안 함 + 실행 승인된 범위의 nonblocking 구현 선택 → 합리적 기본값과 가정을 명시하고 진행.
   - 결정 안 함 + blocking 선택 → 실행 전에 평문으로 확인.
3. **침묵은 결정이 아님**: 응답 없음·부정하지 않음·제안 뒤 침묵을 동의나 GO로 해석하지 않는다.
4. **"일 다 끝내놔" 류 GO 사인 시**: 본 세션에서 작업 가능한 모든 것 완수. 사용자가 명시적으로 자기 영역으로 유보한 부분만 예외.
5. **사용자 컨벤션을 핑계로 한 실행 회피 금지**: 사용자가 1차 초안을 자기 컨벤션에 맞춰 작성하라고 지시했으면 그대로 작성한다 — "사용자가 제거한 함수라 재작성해도 같은 결과"라는 회피를 하지 않는다. 적용 경계: 사용자가 보존을 지시했거나 소유권 규범이 보호하는 대상([[feedback_code_ownership_scope]])에는 적용하지 않는다 — 사용자가 스타일 차이로 지운 코드를 자기 컨벤션으로 다시 초안화하라는 지시는 보존 지시가 아니므로 이 경계에 걸리지 않는다. 충돌하면 소유권 규범이 우선하고, 애매하면 평문으로 확인한다.

## 예외·금지

- 사용자가 이미 결정한 항목을 Decision Queue 나 추가 권고 목록에 다시 올리지 않는다.
- 지침·헌법·memory 에 이미 정해진 방식을 결정 항목으로 올려 재질의하지 않는다 — 그대로 실행한다(정해진 것과 어긋난다고 보면 실행 전 평문으로 한 번 제기).
- 사용자가 명시적으로 자기 영역으로 유보한 부분은 대신 작성하지 않는다.
- 실행 승인을 받은 범위의 nonblocking 구현 선택만 합리적 기본값으로 진행한다.
- 사용자 작성 대기·try/except placeholder로 본 세션에서 가능한 작업을 떠넘기지 않는다.
- 파괴적·비가역 작업과 사용자만 결정 가능한 blocking 선택의 **평문 사전 확인**은 [[feedback_flow_interruption]] 을 따른다.
- 실행 중 애매한 nonblocking 을 멈춰 묻지 않는다 — 기본값으로 진행하고 결정 대기에 적어 최종 보고에서 일괄 묻는다(멈출 일은 계획 §11 에서 미리).
