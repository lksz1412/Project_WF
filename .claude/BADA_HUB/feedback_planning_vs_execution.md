## 적용 조건

사용자가 기획·의견·계획 검토를 요청한 단계에 적용한다.

## 핵심 원칙

기획(planning) 논의 중에는 auto mode가 활성화되어 있어도 코드 작업을 시작하지 말 것. 사용자의 명시적 GO 사인(예: "이대로 진행해", "작업 시작해") 후에만 실행한다.

- **침묵·무응답**: 응답 없음·부정하지 않음·제안 뒤 침묵은 GO나 실행 승인이 아니다.

## 이유

사용자가 기획안을 함께 다듬는 단계에서 AI가 미리 코드 작업을 시작하면 기획이 바뀔 때마다 코드를 다시 갈아엎어야 한다. 재작업 + 토큰 낭비의 직접 원인이다.

## 실행 방법
- 사용자 메시지가 "어떻게 생각해?" / "이렇게 해도 될까?" / "어때?" 같은 의견 묻기 형태일 때 → 답변만, 코드 작업 X.
- 사용자가 "이제 가서 할 일은 1, 2, 3, … 정도가 되겠지?" 처럼 정리 / 확인 요청일 때 → 검증 + 답변만, 코드 작업 X.
- 사용자가 "그럼 이대로 가자" / "작업 시작해" / "진행해" 같이 명시적 GO 사인에만 코드 실행.
- Auto mode의 "prefer action over planning"은 기획 자체가 끝난 후에만 적용된다 — 기획 진행 중에는 사용자 의사가 우선한다.
- 실행 여부가 실제로 모호할 때만 한 박자 멈추고 지금 작업을 시작해도 되는지 한 번 확인한다.
- 제시안(계획 초안·기획 의견·방향 제안)을 요청받으면 답하기 전에 그 프로젝트의 판 이력 파일(운용 문서가 가리키는 판 요약 파일 · 판마다 상세 기록은 필요한 판 항목만) · 진행 중 계획의 마스터 플랜 이력 파일 · 지난 Phase 요청 대장 파일을 (있으면) 읽는다 — 지난 판·갱신·결정에서 정한 것을 뒤집거나 되풀이하지 않으려고(자리·읽는 때 원본 = `skill:skill_LKS_original_plan-execution` 1b 「판 이력」·「이력 파일」 · 요청 대장 파일 = `skill:skill_LKS_original_plan-execution` 의 `references/record-formats.md` 「사용자 요청 대장」).

## 예외·금지

- 사용자의 명시적 GO 전에는 코드·문서·설정 변경을 시작하지 않는다.
- auto mode의 action 선호를 기획 단계 실행 근거로 사용하지 않는다.
- 의견·정리·계획 검토 요청을 실행 승인으로 해석하지 않는다.
- 파괴적·비가역 작업과 사용자만 결정 가능한 blocking 선택의 **평문 사전 확인**은 [[feedback_flow_interruption]] 을 따른다.
