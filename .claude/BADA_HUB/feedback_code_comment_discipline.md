## 적용 조건

코드 작성·수정과 안정 버전(zip) 확정 전 검수에 적용한다. 전 프로젝트 공통.

## 핵심 원칙

코드 주석은 "해당 코드의 현상태를 이해하는 데 필요한 핵심 정보"로 한정한다.

- 허용 (과학 계산 헬퍼 함수부 — 사용자 지정 기준):
  - 함수 바로 위/안 1줄: 구현 수식·변수 의미·참조 식별자 매칭(예: `# w_j = n·R·T/F [eq:logistic]`).
  - 분기/경로에 그 분기의 의미 1줄(예: `# lag_length 배열 → numpy 점화식 (시변계수)`).
  - 짧은 섹션 구분자(`# --- 볼츠만 상수 (SI) ---`), 간결한 워크플로 docstring.
  - load-bearing 출처는 한 줄까지 — **어디서 가져온 코드인가**(출처)는 허용하고 **거기서 무엇을 바꿨는가**(변경 내러티브)는 금지한다. 예: `(1.0.2 에서 이식 — 식별자·시그니처·수치 보존)` 는 허용, `(1.0.3 에서 계수 수정)` 는 금지.

## 이유

버전 작업 이력은 md 본문에 별도로 기록되므로 코드 본문에 중복 기입하는 것은 잘못이며, 현상태 이해에 불필요한 주석은 제거 대상이라는 사용자 지시가 근거다. 특정 모듈들이 주석/이력으로 비대해진 직접 사례가 있었다. 원본 하나를 처음부터 이 기준으로 유지하는 것이 해법이다.

## 실행 방법

코드 작성·수정 시 위 기준으로만 주석을 작성한다. 기존 위반 주석은 리팩토링/버전 확정 게이트에서 md(CHANGELOG·DESIGN_NOTES·result)로 이관 후 제거한다. 검수 ID 등 주석 정보는 commit message·result 문건에만 둔다.

## 예외·금지

- 금지 (코드에 기입하지 말 것 — 관리 대장 CHANGELOG·result 소관):
  - 버전 작업 이력·변경 내러티브(vX.Y.Z에서 무엇을 고쳤다 류)를 코드에 기입 X — CHANGELOG/result md에 이미 기록됨.
  - Phase/Step 번호·설계 결정 에세이·Correction 사연·검수 ID 주석 — 코드에 기입 X(예: "(검수 HIGH-1 반영)" 같은 검수 ID 주석은 다는 것이 금지 대상 · 붙여넣을 템플릿이 아니다).
  - 리뷰어에게 말 걸기·수정 응답 주석을 코드에 기입 X.
  - **단계 예외 없음** — 초기(알파·프로토타입) 단계라도 in-file 버전 이력 누적을 허용하지 않는다(단계 무관·이력은 md). "초기라 잠깐 넣어둔다"도 금지 — 알파 단계 in-file 이력 허용은 원본과 정면 충돌이므로 폐기한다.
- **버전 확정 시 '코멘트 정리 게이트' 의무**: 안정 버전(zip) 확정 직전, 위 기준으로 전 파일 주석을 정리하는 게이트를 둔다(이력 주석 발견 = FAIL → 이력 주석을 md로 이관 후 삭제).
