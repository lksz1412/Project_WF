## 적용 조건

기존 파일의 **수정(내용 변경·덮어쓰기)·이동·이름변경·삭제**가 일어나는 모든 작업에 적용한다(이동·이름변경은 원 경로의 소실이므로 수정·삭제 계열이다).

- **보호 대상 = 사용자 작업물** — 사용자 파일·사용자 소유 폴더·기존 산출물. 세션 스크래치패드·OS 임시 디렉터리 같은 **휘발 임시공간은 사용자 작업물이 아니므로 조항 대상이 아니다**(이것은 예외 조항이 아니라 보호 대상의 정의다). 위치가 임시 디렉터리라도 사용자가 두고 쓰는 파일은 사용자 작업물이다 — 휘발인지 애매하면 보호 대상으로 취급한다.
- **신규 파일 생성**(존재하지 않는 경로에 새 파일)은 기존 작업물을 훼손할 수 없으므로 이 조항의 규제 대상이 아니다. 단 **기존 파일 경로에 Write = 덮어쓰기 = 수정**으로 규제된다. 산출물을 어디에 두는가는 별도 규범(프로젝트 구조·원천 보호)이 관할한다.
- 경량·읽기 전용 일회성 작업에는 ①(본격 작업의 git 폴더 강제)을 적용하지 않는다(git 셋업 오버헤드 면제). 단 그 작업에 기존 파일의 수정·삭제가 있으면 ③·④는 그대로 적용된다 — 경량이라는 이유로 git 밖 수정이 자유로워지는 것이 아니다.

이 memory 가 작업물 보호의 **규범 원본**이고, git init·사본·복원의 **단계별 절차·명령**은 `skill:skill_LKS_original_project-scaffold` 가 소유한다.

## 핵심 원칙 — 판단을 기계 규칙으로 내린다

"여기가 보호영역인가?"를 매번 판단에 맡기면 판단이 흔들리는 그 한 번에 작업물이 비가역적으로 파손된다. 이 조항은 그 판단을 **체크 가능한 기계 규칙**으로 내린다: **수정·삭제는 git 안에서만, 위험 전에는 커밋, 밖은 읽기만.** git 안인지는 `git rev-parse --is-inside-work-tree` 한 번으로 판정된다 — 추정·재량이 낄 자리가 없다.

**① git 우선.** 본격 작업(코드 변경·문서 빌드·데이터 빌드)은 git 폴더 안에서 한다. **로컬 git이면 충분하다** — GitHub·원격 push 는 불요. git 폴더는 그 자체로 매 커밋이 복원 지점이 된다.

**② 위험 전 커밋 — 이 조항의 심장.** 파괴·비가역 작업 **직전에 반드시 commit** 해 복원 지점을 확보한다(복원 지점 먼저 → 진행). 평문 사전 확인은 계획 §11 「멈출 일 미리 점검」에서 받으므로 실행 중 멈춰 묻지 않는다 — 파괴·비가역이 §11 에 있거나 복원 지점을 만들 수 있으면 복원 지점 먼저 → 진행 → 기록(최종 보고)이고, §11 에 없고 복원 지점도 만들 수 없을 때만 실행 중 멈춘다. 판정 규칙: **헌법이 평문 사전 확인을 요구하는 "파괴·비가역 작업"(대량 삭제·일괄 치환·in-place 변환·`git reset --hard`·`git clean -fdx`·force-push·이력 조작 등)이면 전부 ② 대상이다** — 사전 확인과 사전 커밋은 같은 조건에서 함께 적용되는 한 쌍이다(어느 하나가 다른 하나를 대체하지 않는다 — ⑥). 단 **일괄 치환·in-place 변환**은 이미 전부 커밋된 git 안(clean status)일 때에 한해 git 복원으로 온전히 되돌아가는 가역 통상 수정이라 별도 확인 정지 대상이 아니다(⑥ 후단 — git 안 가역 편집은 흐름을 끊지 않는다). 대량 삭제·`git reset --hard`·`rm -rf .git`·`git clean -fdx`·force-push·이력 조작은 **clean status 여부와 무관하게** 복원 지점을 먼저 만든다 — 대량 삭제와 `git reset --hard`(추적 파일)는 사전 커밋이 복원 지점이고, `rm -rf .git`·`git clean -fdx`·force-push·이력 조작은 git 으로 못 되돌리므로 저장소 밖 사본·백업이 복원 지점이다(사전 커밋으로 대신하지 않는다). §11 에 없고 그 복원 지점도 못 만들 때만 멈춰 확인한다 — `rm -rf .git`·`git clean -fdx`(미추적물)·force-push·이력 조작은 git 으로 못 되돌리고, `git reset --hard`·대량 삭제는 미커밋 변경·미추적 신규 파일을 함께 쓸어가면 그 부분이 복원 불가이며, 오지정(잘못된 경로·범위) 피해가 즉시 광범위해 확인 한 번이 복원 시도보다 싸다. `git status --porcelain` 이 비어 있지 않은 채 위험 작업에 들어가지 않는다. **커밋 없이 지른 위험은 git 도 못 구한다 — ②가 무너지면 ⑤ 복원도 없다.** (분업 문맥에서 이 커밋은 commit 권한자 master 몫이다 — 아래 실행 방법·[[feedback_session_division]].)

**③ git 밖 = 읽기만.** git 폴더 밖의 기존 파일은 읽기만 한다. 수정·삭제가 필요하면 경로는 둘뿐이다:

- **(a) 프로젝트 폴더**(작업물이 사는 폴더) → 그 폴더를 `git init` 하고 현재 상태를 초기 commit 한 뒤 작업한다.
- **(b) 사용자 데이터·시스템 파일 등 git화가 부적절한 대상** → git repo 안에 **사본**을 떠서 사본 위에서 작업한다(원본 무손상). 사본의 최초 commit = 원본 상태 보존.
- ★**(a)의 `git init` 은 프로젝트 폴더 전용이다**(그 문맥에선 복원 지점 확보를 위한 정상·권장 행동 — 회피 대상이 아니다). 금지되는 것은 **사용자 홈·Downloads·데이터 공간을 사본 대신 리포화**하는 것(월권)이다 — 그 대상은 (b) 사본만. 프로젝트인지 사용자 데이터인지 애매하면 **(b) 사본이 기본값**이다.
- **사용자가 시킨 오토메모리(`~/.claude/projects/<키>/memory/`) 갱신은 ③ 밖**이다(Claude 자기노트 · 사용자 지시 갱신) — 예외가 아니라 적용 대상 밖이다.

**④ 유일 예외.** **사용자가 특정 파일을 명시 지정한 수정·삭제**만 git 밖에서 직접 허용한다 — 그때도 **백업 먼저**(사본 확보 후 작업). 예외는 이 하나뿐이며 늘리지 않는다. "스크래치라서"는 예외가 아니라 애초에 보호 대상 밖이고, "인도(delivery)라서"는 신규 파일 생성(비규제)이거나 **사용자가 그 경로 반영을 지시·승인한** 덮어쓰기(= ④ 그 자체)다 — 지시·승인 없는 목적지 덮어쓰기는 ④로 세탁되지 않으며, 어느 쪽도 새 예외를 요구하지 않는다.

**⑤ 실제 침범 시.** 보호 대상을 실제로 침범했으면(git 밖 무허가 수정·삭제, 또는 git 안팎 불문 보호 대상의 의도치 않은 훼손):

- **(git · 복원 지점 있음)** 침범 없는 직전 커밋으로 **복원한 뒤**, 침범을 일으킨 경로·지시를 교정하고 **재진행**한다(같은 경로 그대로의 재진행은 재침범이다). 복원 사실은 보고에 명시한다(침묵 금지).
- **(비-git 또는 복원 지점 없음)** 그 작업을 **중지하고 보고**한다 — 복원 불능 상태로 계속 가면 훼손이 누적된다.
- ★**"복원 후 재진행"은 ②가 성립해 침범이 완전 가역일 때만 성립한다.** 위험 전 commit 이 없었거나 복원이 부분적·불완전하면, git 안이라도 **비-git 처럼 중지·보고**로 떨어진다(가능하면 트리 전면 `reset` 대신 국소 복원 우선 — 미커밋 정상 작업 유실 주의).
- 이것은 헌법 GO-후 정지 조건 「보호영역 침범」의 **실행절차(구체화)** 이지 대체가 아니다. 침범이 git 복원으로 완전히 원복되면 정지 사유가 해소되어 재진행하고, 원복 불능이면 정지가 유지된다.

**⑥ 중첩 — git 은 undo 일 뿐, 파괴 확인 면제가 아니다.** 이 조항은 기존 "파괴·비가역 작업 평문 사전 확인"을 **대체하지 않고 함께** 적용된다 — 그 평문 사전 확인은 계획 §11 「멈출 일 미리 점검」에서 받는다(실행 중 멈춰 묻지 않고, §11 에 없고 복원 지점도 못 만드는 것만 그때 멈춰 확인). repo 안이라도 `rm -rf .git`·`git clean -fdx`·force-push·비가역 셸 명령은 파괴적이다 — §11 에 적어 승인받는 것이 기본이다. §11 에 없으면 복원 지점을 먼저 만들고 진행해 최종 보고에 적는다 — 단 `rm -rf .git`·`git clean -fdx`·force-push·이력 조작은 git 으로 못 되돌리므로 복원 지점은 저장소 밖 사본·백업이다(사전 커밋으로 대신하지 않는다 · force-push 가 지우는 원격 이력은 그 사본에 따로 남긴다). 그것도 못 만들면 멈춰 확인한다. git 이력이 있다는 이유로 이 확인을 건너뛰지 않는다. 확인 대상은 파괴·비가역 작업뿐이며(git 안에서 커밋된 파일의 가역 수정·삭제는 확인 없이 진행한다), 파괴·비가역이면 연속 작업 중이라는 이유로도 생략하지 않는다.

**읽기는 언제나 허용.** 이 조항은 수정·삭제만 제약한다. git 밖 파일을 읽는 것은 항상 가능하며(오히려 전문 정독 의무의 대상 — [[feedback_full_file_read_required]]), "밖은 손도 대지 마"로 오독하면 정상 작업이 마비된다. 읽기 자유 ≠ 정독 면제.

## 이유

- 기존 보호 규범(원천 보호·코드 소유권·결과 문건 보호)은 "무엇을 보호하는가"를 정하지만, 이행이 **판단**에 걸려 있는 한 판단이 어긋난 단 한 번에 작업물이 비가역 파손된다. 이 조항은 보호를 **기전**(git 복원 지점)으로 내려, 판단 실패를 복구 가능한 사건으로 바꾼다.
- ②가 심장인 이유: ⑤의 "이전 커밋 복원"은 위험 **전에** 커밋했을 때만 작동한다. 복원 지점 없는 git 은 비-git 과 같다.
- 사용자 데이터 공간 "사본 대신 리포화" 금지의 이유: 프로젝트 폴더의 git init 은 정상 작업 셋업(복원 지점 확보)이지만, 사용자 홈·데이터 폴더의 리포화는 사용자 소유 공간에 대한 무단 구조 변경이고 `.git` 잔재를 남긴다. 사본이 안전한 기본값이다.
- git 안이라는 안심이 `git clean -fdx`·force-push 같은 비가역 셸의 사전 확인을 건너뛰게 하면 repo 도 못 구한다 — git 은 undo 일 뿐이다(⑥).

## 실행 방법

1. **판정**: 작업 전에 대상 경로가 git 안인지 밖인지 먼저 판정한다 — 추정하지 않고 실제로 확인한다.
2. **경로 결정**(git 밖 기존 파일의 수정·삭제가 필요할 때): 프로젝트 폴더 → ③(a) `git init` + 초기 commit / 사용자 데이터 → ③(b) repo 사본 / 사용자가 그 파일을 명시 지정 → ④(백업 먼저). 애매하면 ③(b).
3. **위험 전 commit**: 평문 사전 확인이 필요한 파괴·비가역 작업이면 전부 commit 을 선행하고(그 평문 사전 확인은 계획 §11 에서 받으므로 실행 중에는 복원 지점 먼저 → 진행), 작업 트리에 미커밋 변경이 남아 있지 않은지 확인한다. 복원 조작 자체도 파괴적이므로 **복원 전에도 현 상태를 스냅샷으로 commit** 한 뒤 복원한다.
4. **복원**: 침범 없는 커밋을 찾아 **파일 단위 국소 복원을 우선**한다(트리 전면 복원은 미커밋 정상 작업까지 지운다). 복원 결과는 diff 로 확인하고, 복원이 부분적·불완전하면 계속하지 말고 중지·보고한다(⑤).
5. **분업 문맥의 귀속**: ②의 commit 은 **commit 권한자인 master 몫**이다 — 위험 작업을 master 가 직접 수행하든 서브에 dispatch 하든, 그 전에 master 가 commit 한다. 서브에게 commit 을 시켜 ②를 이행하지 않으며, 서브는 brief 에 없는 위험 지점을 만나면 실행하지 말고 반환·보고한다.
- 각 단계의 명령·절차는 `skill:skill_LKS_original_project-scaffold`, 유닛 문맥의 격리(worktree·branch)·롤백은 `skill:skill_LKS_original_multi-session-orchestration` 을 따른다.

## 예외·금지

- **예외는 ④ 하나뿐** — 사용자 명시 지정 파일의 수정·삭제(백업 먼저). 읽기·신규 파일 생성·경량 일회성·휘발 스크래치·사용자가 시킨 오토메모리(`~/.claude/projects/<키>/memory/`) 갱신은 예외가 아니라 **적용 대상 밖**이라 예외로 세지 않는다(carve-out 팽창 = 기계규칙 사망).
- git 밖 기존 파일을 명시 지정 없이 수정·삭제하지 않는다 — ③(a)/(b) 경로로 우회한다.
- 사용자 홈·데이터 공간을 사본 대신 리포화하지 않는다 — 그 대상은 ③(b) 사본. 프로젝트 폴더의 ③(a) `git init` 은 금지가 아니라 권장이다.
- 위험 작업을 commit 없이 실행하지 않는다.
- 커밋하지 않은 변경을 버리고 다른 판(커밋된 판·다른 가지·빈 상태)으로 덮어쓰거나 지우는 명령(어떤 명령이든 그 효과로 판정)(머지하지 않은 가지를 지우는 것 포함)은 사용자가 그 명령을 쓰라고 하거나 그 일을 지시하기 전에는 쓰지 않는다 — 지금 맡은 일을 하려고 파일을 고치거나 생성물을 다시 만드는 것은 여기에 들지 않는다(승인 창 목록에는 넣지 않는다 — 흐름 보호). 예외 = ⑤ 침범 복원(실행 방법 4 · 복원 전 스냅샷 커밋 뒤 파일 단위 국소 복원)은 그 절차대로 한다.
- git 안이라는 이유로 파괴·비가역 평문 사전 확인을 생략하지 않는다(⑥) — 그 확인은 계획 §11 「멈출 일 미리 점검」에서 받는다(실행 중 멈춰 묻지 않음 · §11 에 없고 복원 지점도 못 만들 때만 그때 멈춰 확인). 확인은 **평문**으로 한다(팝업·Workflow 아님 — [[feedback_flow_interruption]]).
- 침범을 복원·보고 없이 덮고 진행하지 않는다.
- **§0 우선:** 사용자가 백업 생략·git 밖 직접 수정을 명시 지시하면 이 조항이 그 지시를 무효화하지 않는다 — §0(사용자 지시 우선)·[[feedback_execute_explicit_choice_not_judgment]]대로 우려를 평문으로 1회 제기한 뒤 사용자 재결정에 따른다.
