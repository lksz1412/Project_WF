## 적용 조건

이전 결정·근거를 재사용하거나 보고서·분석 결과를 작성할 때 적용한다.

## 핵심 원칙

**1. 사용자 결정 재논의 금지.** 이전 세션·HANDOVER·메모리에 기록된 사용자 결정 가운데 출처(사용자 원문·그 결정을 적은 요청 대장 행)가 붙은 것은 의사결정 원본으로 존중하고 미해결 문제로 재보고하지 않는다. 출처 없이 「사용자 결정」 으로만 적힌 기록은 확정 결정으로 다루지 않는다 — 원문(세션 기록·요청 대장·인계 chain)을 한 번 찾아(찾기 전 = 미검증) 찾으면 그대로 존중하고(재질의 아님), 못 찾으면 「근거 미발견」 으로 두되 묻기 전까지는 그 기록을 기본값으로 두고 결정 대기에 「근거 미발견 결정」 으로 올려 묻는 때(계획 단계 = 계획 §11 · 실행 중 = 최종 보고 · blocking 판정 = [[feedback_flow_interruption]])에 묻는다. 사용자가 명시적으로 재검토 요청 시에만 다시 논의한다. 사실 주장의 확정 여부는 아래 4-tier와 원천 검증을 별도로 적용한다.

**2. 추측 보고 금지.** 보고서·분석 결과 작성 시 문서 근거가 없는 항목은 추측으로 채우지 말 것. 4-tier 표기 중 적절한 것으로 명시.

**3. 보고 표기 4-tier:**

| Tier | 의미 | 후속 조치 |
|---|---|---|
| 확정 | 문서·코드·원천 근거로 검증됨 | 그대로 사용 |
| 근거 미발견 | 찾았으나 문서·코드 어디에도 근거 없음 | 사용자에게 보고, 추측으로 채우지 말 것 |
| 추정 | 가설 보유 + 근거 일부만 있음 + 검증 미실시 | 검증 시 확정 또는 근거 미발견으로 이동 |
| 미검증 | 검증 가능했으나 시간·스코프 제약으로 안 함 | "검증 안 함" 명시, PASS에 포함 X |

- "확정"으로 보고하려면 근거 출처를 동봉한다 — 코드면 파일:라인, 문서면 절·식 번호.
- "추정"과 "미검증"의 차이: 추정 = 가설은 있다 / 미검증 = 가설조차 없거나 검증 자체를 안 함. 둘을 PASS로 묶어 보고 금지.
- 사용자 결정을 기다리는 사항은 4-tier 와 따로 **결정 대기**(Decision Queue)에 적고 `PQ-<프로젝트>-<번호>` 로 추적한다(4-tier 외 직교 · 자리 = 그 스텝 이력 · 서브 work_log · Phase Result 「Decision Queue」 항목 → 최종 보고). 사용자에게 보일 때는 코드만 던지지 않고 그 항목의 내용을 풀어 붙인다([[feedback_decision_request_clarity]]).

**4. 세션 시작 시 확정 사항 점검.** 인계 문건 + 메모리에서 이미 결정된 사안 식별 후 재논의 트리거에서 제외.

**5. 확정 결정 간 충돌·전제 붕괴 시 표면화.** 두 사용자 확정 결정이 서로 모순되거나, 확정 결정이 딛고 선 사실 전제가 원천 검증에서 거짓으로 드러나면, 어느 한쪽을 말없이 채택·실행하지 않는다. 모순 지점·무너진 전제를 결정 항목으로 평문 표면화하고 재결정을 기다린다. 이는 1번 "재논의 금지"의 위반이 아니라 새로 발견된 모순의 보고이며, 재논의 금지의 예외다. no-requery(재질의 금지)와 fact-verify(사실 재검증)가 충돌할 때의 tiebreak가 이 표면화다.

## 이유

다수 세션에서 반복된 사례가 근거다.
- 대표 사례:
  - 사용자가 이미 정황·확정한 하드웨어 사양 결정을 AI가 그대로 "문제점"으로 재보고.
  - 기존 논의 이력을 참조하지 않아 이미 해결된 사안을 미해결로 보고 → 사용자 시간·신뢰 손실.
- 4-tier 는 보고 어휘를 통일해 확정과 추정이 한 덩어리로 섞이는 것을 막는다.
- 본 규칙은 환각 방지([[feedback_full_file_read_required]] 「예외·금지」)의 변형으로, **보고서·분석 결과의 표기 방식**에 한정된 행동 규범이다.

## 실행 방법
- 보고서·분석 작성 시 매 항목 4-tier 중 어디인지 점검 + 근거 출처 동봉.
- 근거 없으면 "근거 미발견" 표기(찾았는데 없음) vs "미검증" 표기(안 찾음) 구분.
- "추정" 항목은 검증 plan 함께 제시(어느 파일·식·문서를 보면 확정/근거미발견으로 이동 가능한지).
- 확정 사항 목록은 프로젝트 메모리·인계 문건의 「확정 사항(재논의 금지)」 절에서 참조한다.
- 결정 대기 사항은 PQ (Pending Question) 코드로 추적(PQ-<프로젝트>-<번호> · 자리 = 핵심원칙 3 의 결정 대기 · 보고에서는 코드 옆에 내용을 풀어 쓴다).
- 사용자가 "재검토 / 다시 봐줘" 등 명시 요청한 경우에만 확정 사항 재논의 진입.

## 예외·금지

- 사용자가 명시적으로 재검토를 요청한 경우에는 확정 사항을 다시 검토할 수 있다.
- 근거가 없는 항목을 "확정"으로 분류하지 않는다.
- "추정"과 "미검증"을 PASS에 포함하지 않는다.
- 출처(원문·요청 대장 행)가 붙은 이전 인계·메모리의 사용자 결정은 재질의하지 않는다 · 출처 없는 「사용자 결정」 기록은 핵심원칙 1 대로 원문부터 찾는다. 검증이 필요한 사실 주장은 그 기록만으로 확정하지 않고 필요한 원천을 직접 확인한다.
- 확정 결정끼리 모순되거나 그 사실 전제가 무너지면 말없이 한쪽을 고르지 않는다. 모순·붕괴 전제를 표면화하고 재결정을 기다린다(핵심원칙 5).
