## 적용 조건

산출물(문서·코드·데이터·덱)을 실제로 구성·수정하는 모든 본격 작업에 적용한다. GO 이후 각 step 안에서 산출물을 만들어 갈 때의 작업 방식이다. 단일 명령·단순 조회·1-line fix 같은 경량 작업에는 강제하지 않는다.

계획·단계 실행의 상위 골격은 `skill:skill_LKS_original_plan-execution`(계획서 저장·Phase/step 구조·Result/Ledger)이 관할하며, 본 memory 는 그 안에서 **한 단위를 어떻게 만드는가**의 규율만 담는다.

## 핵심 원칙 — 자연 작업 단위별 단위 루프 (통째 배치 금지)

산출물은 **자연 작업 단위** 하나씩 만든다. 자연 작업 단위 = 절·모듈·함수·문단·데이터블록 — 작업유형이 정하는 최소 응집 단위다. 각 단위는 다음 6단계 루프를 돈다:

1. **그 단위 전문 정독**(head → tail) — [[feedback_full_file_read_required]] 원칙 적용, 부분 read 라도 전 영역 cover.
2. **구성·수정** — 논리·정합 순검하며 작성.
3. **그 단위 자체검수.** (검수가 붙는 작업이면 정한 게이트만 · 코너 케이스·폴백·경계 조건 찾기는 검수 몫 · 검수가 없는 작업이면 여기서 함께)
4. **앞 단위·기반 정합** — 선행 산출물·기준식·인터페이스와 어긋나지 않는지 대조. 이 단위를 고칠 때 옆·뒤 방향으로 영향받는 곳(같은 규칙·부르는 곳·잠근 시험)은 [[feedback_change_impact_analysis]] 의 영향 지도로 먼저 찾는다.
5. **빌드·검증.**
6. **ledger 행에 사유 기록** — 무엇을 왜 만들었나/무수정이면 왜 무수정인가(양식·저장 위치는 `skill:skill_LKS_original_plan-execution`).

단위마다 이 루프를 돌아야 품질·정합이 **단위별로** 걸러진다.

- **검수 입도 = 자연 단위 — 통째로 쓰고 완료로 치지 않는다.** 새 파일을 도구 한 번(Write)에 쓰는 것은 괜찮지만, 단위마다 위 루프(정독·자체검수·앞 단위 정합·검증·사유 기록)를 끊어 돈 뒤에만 완료로 친다 — 단위마다 끊어야 오류가 단위별로 잡힌다. 단, 단위를 끊는 것은 품질을 거르는 입도를 정하는 일이지 단위마다 사용자 확인을 받으라는 뜻이 아니다 — GO 후엔 한 단위가 끝나면 곧바로 다음 단위로 자동 진행해 흐름을 끊지 않는다.
- **복붙·재사용·무수정 ≠ 완료.** 기존 결정을 참조할 수 있어도 새 산출물에 필요한 실질 작성·정합 검토를 생략할 수 없다. 무수정 단위도 "왜 무수정인지" 정독 근거(행범위 + 사유)를 남겨야 PASS. 비정상적으로 빠른 완료 = 복붙·skim 재확인 신호.
- **완결성(orphan 0).** 추가된 모든 것은 (a) 앞에서 도입(intro) + (b) 뒤에서 사용(downstream 인용·대입·환원) — 둘 다여야 spine(최종식·핵심 산출)에 물린다. 한쪽이라도 없으면 연결 문장 신설 또는 trim. 댕그러니 매달린 orphan 금지.
- **통합 산출물 규율.** 부분들이 하나의 문건·시스템으로 묶이면(책·통합보고서·통합코드) 부분 간 인계·recap·전달 비계를 두지 않는다(독자·호출자는 앞 부분을 이미 가짐). 논문식 결론 절을 따로 두지 않고, 필요한 결론은 쓰는 자리에서 식 번호·함수로 inline 참조한다.
- **품질 목표**: 논리 깊이 = 리뷰 논문급, 형식 = 교과서급(전제부터 친절한 단계 전개), 완전 무결 직전("턱밑")까지. — 본격 산출물의 목표 수위다(경량·단순 응답은 요청 깊이 · 헌법 「품질·원천·git」 요지의 원본).

## 이유

산출물을 챕터·파일 단위로 통째 Write 하면 누적 오류가 그 안에 묻힌다 — 어디서 논리가 어긋났는지, 어떤 단위가 앞 단위와 불일치하는지 사후에 분리할 수 없다. 자연 단위마다 정독·검수·정합·빌드를 끊어 걸면 결함이 발생 지점에서 잡히고, 다음 단위가 오염된 기반 위에 쌓이는 것을 막는다.

복붙·무수정을 완료로 계수하면 "빠르게 끝난 것처럼 보이지만 실제 정합 검토는 없는" 산출물이 통과한다 — 무수정 근거(행범위+사유)를 강제하는 것이 이 우회를 닫는다. orphan 규율은 도입만 되고 안 쓰이거나(dead) 근거 없이 등장한(unfounded) 요소가 spine 에 물리지 않은 채 남는 것을 막는다.

## 실행 방법 — 단위별 체크리스트 8항목

각 자연 단위 완료 전 다음 8항목을 확인한다:

1. **정독 행범위 기록** — 그 단위에서 실제 읽은 파일·행 범위(정독 사후 증명).
2. **논리·정합 순검** — 부호/차원/극한/정의역 (코드면 시그니처/호출체인/silent path).
3. **도메인 일관성** — 용어·기호·정수코드 표기.
4. **접근성** — 새 개념·식·구조는 전제부터 단계 전개, 비유 의존 금지.
5. **추가는 앞 도입·뒤 사용** — orphan 0 확인.
6. **통합문건 규율** — 타 부분 recap/transmit 0.
7. **인계 식별자 보존** — 식 번호·함수명·라벨 유지.
8. **수정/무수정 사유 한 줄** — ledger 행에 근거 남김.

- 저작 시점의 정독·자체검수는 관점별로 전문을 N회 돌지 말고 1회 정독에 모든 관점을 동시에 싣는다([[feedback_full_file_read_required]]). 본작업을 마친 뒤의 감사는 이 조항이 아니라 §3 가변 청크 검수를 따른다(갈래별 강도·라운드·한 번에 고침·재검증 원본 = [[feedback_chunked_review]] 「검수 구분」·「재검증」).
- 코드 단위는 편집 후 호출체인·시그널·silent path 를 본문으로 재확인한다([[feedback_post_edit_runtime_verification]]).

## 예외·금지

- **금지 — 통째 배치 완료.** 챕터·파일을 단위 루프 없이 한 번에 쓰고 "완료" 보고하지 않는다(기준 = 도구 호출 횟수가 아니라 단위마다의 검수).
- **금지 — 정독 근거 없는 복붙·무수정 완료.** 참조·재사용은 가능하나 정합 검토·정독 근거 없이 완료로 계수하지 않는다.
- **금지 — orphan 방치.** 앞 도입 또는 뒤 사용 중 한쪽이라도 없는 요소를 그대로 남기지 않는다.
- **금지 — 통합 산출물에 부분 간 recap·전달 비계 삽입.**
- **경계** — 11-section 계획서 양식·cumulative step·5-stage 루프·Result 12항목·Ledger 12-column·gate 설계·3-Pass audit 는 `skill:skill_LKS_original_plan-execution` 이 소유하고, 본 memory 는 단위 루프 규율을 소유한다.
