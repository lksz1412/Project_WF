## 적용 조건

문건(지시·인계·참조·매뉴얼·코드·지침·기록)을 읽고 검토·수정·판단·보고할 때 적용한다 — 발주문·브리핑·결정을 위해 읽는 것도 여기에 든다. 코드만이 아니라 지시문·인계·매뉴얼·지침·기록 같은 텍스트에도 같이 적용한다 — 문건 종류로 빼지 않는다. 영향 지도·잔재 확인·통합 대조도 전문 정독 대상이며, 검색은 정독 뒤 빠진 곳 확인용 보조다.

## 핵심 원칙

- **대상 전문(head → tail)을 다 읽는다.** 부분 read(offset/limit)도 허용되지만, 합쳐서 모든 영역을 커버해야 한다. grep 결과의 매칭 라인만 보고 끝내지 않는다.
- **처음 몇 줄과 마지막 몇 줄만 읽고 중간을 추론으로 채우지 않는다.** 도구 출력 한계가 있으면 구간을 나누어 1행부터 끝행까지 읽는다.
- **검토 관점도 grep 으로 대체하지 않는다.** 문체·구어체·전보체·논리 같은 prose 검토를 패턴 매칭으로 훑는 것 자체가 정독 의무 위반이다. 내용·문체·논리 판단이 들어가는 검토는 전부 전문 정독으로 한다.
- **1회 정독에 모든 관점을 싣는다.** 저작 시점의 1회 통독으로 커버되는 분량에서는 관점별로 같은 전문을 N회 돌지 않는다. 단 A1·A2 본격 산출물의 본작업 뒤 검증은 크기와 무관하게 이 조항 대상이 아니라 [[feedback_chunked_review]] 의 검증이 관할한다 — 그 라운드는 중복 작업이 아니며 생략하지 않는다(검증 강도 = 그쪽 「검수 구분」의 변경 갈래 · 라운드 정독 입도[처음 읽는 라운드만 전독 · 이후 필요한 곳 + 기계 검사 · 새 서브는 전독] = 그쪽 「정독 입도」 · 재검증 범위 = 그쪽 「재검증」).
- **의미·흐름까지 검수한다:**
  - 호출 측이 정의 측 시그니처와 인자 개수·순서·이름이 정합한지
  - 시그널 emit 의 payload 와 connect 슬롯의 인자가 정합한지
  - `self.<attr>` 가 `__init__` 또는 그 이전 라인에서 정의된 뒤 사용되는지
  - import 누락, 옛 이름 잔재, 옛 enum 코드 잔재
  - silent failure / except 없이 return / 빈 fallback 으로 동작이 가려진 지점
- **검수 결과를 인벤토리로 먼저 정리하고 통합 패치로 처리한다.** 표면 1건을 고치고 "다 했다"고 보고하면 남은 잠재 문제가 그대로 누락된다.

## 이유

글의 일부만 읽고 중간을 추론으로 채우면 그 추론이 그대로 환각이 된다. 읽은 범위를 적어 두지 않으면, 특히 컴팩션 뒤에 앞뒤만 읽고 중간을 지어낸 것을 가려낼 근거가 없다 — 그래서 읽은 파일·줄 범위를 기록으로 남긴다. 컨벤션을 일괄 변경한 뒤 호출 측 다수가 누락됐는데 "import 통과"만으로 회귀 없음을 보고했고 다음 세션의 정적 분석이 잔재를 찾아낸 사고가 그 전형이다 — import 통과를 OK 로 결론내고 호출 측 본문을 보지 않은 것이 원인이었다. 문건 검토도 같다: grep 패턴으로 훑은 라운드가 빈손인 사이, 같은 범위를 전문 통독한 1회가 확정 결함을 찾아냈다.

## 실행 방법

- 코드 수정 작업의 첫 단계는 대상 파일 Read(필요 시 offset+limit 반복)로 전문을 커버하는 것이다.
- **영향 지도·연계 확인 정독은 목적을 걸고 읽는다** — 통독으로 끝내지 않고, 먼저 변경 목록(이미 고친 것·앞으로 고칠 것·같은 뜻 다른 표현)을 세운 뒤 그 목록을 대조하며 전문을 읽어 이어진 곳·놓친 연계·같은 뜻 다른 표현을 잡는다(찾는 법 원본 = [[feedback_change_impact_analysis]]).
- grep·ruff·pyflakes 같은 정적 분석은 전문 정독 뒤 빠진 곳 확인용 보조로만 쓴다. grep 허용 범위 = 빌드 로그 카운트(err/Overfull/undef)·식별자 출현 수 같은 기계적 게이트와 정독 뒤 보조뿐이다.
- import·parse·smoke 통과는 회귀 검증의 시작이지 끝이 아니다. 시그널·시그니처·silent path 까지 본문 정독으로 잡는다.
- 검수 Agent 에게 위임할 때도 같은 정독 지시를 sub prompt 에 명시한다. 판단·고침은 원문을 직접 읽은 세션이 한다 — 서브가 읽고 줄여 넘긴 요약을 근거로 판단하지 않는다(원본 = [[feedback_session_division]] 「읽기를 서브에 맡기고 요약으로 판단하지 않는다」).
- **읽은 범위를 기록한다(원본).** 판단·고침·보고의 근거로 읽은 파일과 줄 범위(예: `CLAUDE.md:1-141` · 큰 파일은 창마다)를 그 스텝 이력에 적는다 — 서브는 work_log(검수 서브는 보고)에 적고 master 는 그것을 스텝 이력에 옮긴다. 컴팩션·세션 재개 뒤에는 복구 읽기(규칙 파일 재독 + 6-check)로 읽은 범위도 적는다(서브는 규칙 파일 재독 + 서브 몫 재독 범위)([[feedback_compaction_recovery]]). 이 기록이 없으면 그 스텝은 미완이다(양식 자리 = `skill:skill_LKS_original_plan-execution` 2c 「근거·판단」).
- **DB성 자료·실험 데이터**(json 데이터 파일·JSON dump·DB export·payload·대용량 dict·측정 로그)는 통째 read 에서 뺀다(그 밖의 예외 = 아래 「예외」) — md 문건·작업 기록·작업 로그(work_log·스텝 이력)는 DB성 자료가 아니다(애매하면 전문) — grep 이 아니라 **Python 으로 필요한 값만** 뽑아 근거를 확보한다: schema·top-level key·레코드 count·대표 sample 1~2건·대상 key/ID 를 실제 파일에서 확인하고, 데이터 domain/type 을 먼저 식별한 뒤 흐름(입력 → 중간 DB → 최종 payload → 소비처)을 매핑한다. 사용자가 전체 검독을 명시하면 구간을 나눠 끝까지 읽고 읽은 파일·key·sample 을 기록한다.

## 예외·금지

- **예외.** 전문 정독에서 빼는 것은 DB성 자료·실험 데이터처럼 통째로 읽을 필요 없는 자료(위 항목 · json 데이터 파일 포함 · md 문건·작업 기록·작업 로그는 아님 · Python 으로 필요한 값만)와 지침이 일부만 읽으라고 정한 자리(그 지침 문구대로 — 예: 판마다 상세 기록의 필요한 판 항목 · 어댑터가 정한 절)뿐이다. 작업에 쓰는 문건은 종류(지시·인계·참조·매뉴얼·코드·지침·기록)로 빼지 않는다(헌법 「전문 정독」 예외와 동일).

- **A/B 비교는 실차 선판정 후 비대칭 정독.** 두 산출물(버전 A/B·후보 A/B·같아야 할 두 파일)을 **비교**하는 작업은 양쪽을 다 전독하지 않는다: ① 먼저 두 산출물을 `tools/ab_precompare.py` 로 **전처리**(코멘트[통짜·인라인·독스트링] 제거 + 공백 정규화)한 뒤 diff 한다 — 코멘트·공백 차이는 비교 노이즈라, 제거하고 봐야 "실제 내용이 다른가"가 드러난다 · ② 전처리 diff 가 비면(노이즈성 차이뿐) — **exit 0 을 "비교 종결(양쪽 전독 불요)" 근거로 쓰는 것은 파서 근거가 견고한 화이트리스트 유형에서만이다: `.py`(tokenize+ast)·`.json`. 그 밖 휴리스틱 스캐너 유형(`.js`/`.ts`·`.c`/`.cpp`·`.go`·`.rs`·`.sh`/`.bash`·`.yaml`/`.toml`/`.ini`·`.m`(MATLAB)·`.md`/`.html`·미지원)은 정규식·heredoc·char 리터럴·유의미 공백처럼 스캐너가 완전히 풀지 못하는 구성이 있어, exit 0 이어도 기준 쪽을 전독한다**(노이즈 제거 diff 는 exit 1 표시엔 그대로 유효 — 실차 시 깨끗한 diff 를 준다 · 도구가 `[WARN]`[미지원·MATLAB best-effort·파싱 실패]을 내면 유형 불문 전독). 즉 exit 0 을 "건너뛰기"로 신뢰하는 것은 화이트리스트뿐이고 나머지는 오판 방향을 "다른 걸 같다"(위험)가 아니라 "전독"(안전)으로 둔다 · ③ 전처리 diff 가 남으면 실차 → **한쪽(기준)만 head→tail 전독**, 다른 쪽은 **diff + 그 차이의 의미 판정에 필요한 앞뒤 문맥만** 발췌 검토. **경계:** (a) 실차 판정은 기계 전처리·diff 로만 — 눈대중·추측으로 "같다/다르다" 단정 금지(이건 "비교 대상이 다른가"에 국한 · 기준 쪽은 여전히 전독하므로 「grep 로 정독 대체 금지」와 무충돌) · (b) 기준 쪽 전독 생략 불가(환각 차단·첫 커버 전독) · (c) 컴팩션·context 소실 시 기준 전독 재확립 · (d) "비교"가 아니라 각 산출물을 독립 이해·검수해야 하면 이 조항 아님(양쪽 각각 정독) · (e) fail-safe(②) — exit 0 "건너뛰기" 종결은 화이트리스트(`.py`·`.json`)에서만 · 그 밖 휴리스틱 유형·`[WARN]` 은 diff 공집합이어도 기준 전독(휴리스틱 스캐너의 false "동일" 을 규범이 구조적으로 막는다 — 도구 개별 버그에 의존하지 않는다). 검수 라운드 정독 입도(첫 커버 전독 · 이후 필요한 곳)와 같은 결 = [[feedback_chunked_review]] 「정독 입도」.

- 본문 중간을 보지 않은 채 작업을 진행하지 않는다.
- 도구 출력 한계를 이유로 임의 생략하지 않는다 — 사용자만 정할 수 있는 blocking 우선순위가 있을 때만 질문한다.
- 경로·key·sample 근거 없이 "그 필드 없음 / 이미 됨 / 미지원" 을 단정하지 않는다.
- 자기 변명·메타 발언을 출력하지 않는다. 같은 지적을 다시 받으면 즉시 행동을 바꾼다.
