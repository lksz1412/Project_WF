## 적용 조건

모든 신규·재개·인계 세션 진입 시 즉시 적용한다(헌법 「세션 시작」·「project 진입」 한 줄의 상세 원본). 특히 재개·인계 세션은 이전 맥락을 놓치기 쉬우므로 진입 시점에 아래 정독 의무를 먼저 이행한다 — 단 컴팩션·세션 재개(fork 포함) 직후면 [[feedback_compaction_recovery]] 의 한 순서(규칙 파일 재독 → 6-check → 나머지 복구 읽기)가 맨 앞이고, 이 정독 의무는 그 뒤에 잇는다.

## 핵심 원칙

1. **정독 의무**: 작업지시문(사용자 메시지 전문 — 누락·축약 X) + 변경 대상 파일(head→tail 전 영역, 부분 read는 합쳐 cover) + 사용자가 명시한 문건(HANDOVER·MANUAL·사진·CHANGELOG·프로젝트 CLAUDE.md) 전문 정독. **정독이 끝나기 전 계획 작성 X.**
2. **인계 chain 추적**: 인계 문건이 있으면 무조건 정독하고, 문건 최상단 chain 리스트를 따라 거슬러 올라간다. "지난 세션이 했다"가 아니라 **"지난 세션 결과물을 직접 확인했다"가 기준**(git log·CHANGELOG·과거 인계 검색·발췌 의무).
3. **멀티트랙 인계**: 동시 활성 작업라인이 둘 이상이면(예: 내용 트랙 + 구조 트랙) 각 트랙의 최신 인계를 모두 식별·정독하고 트랙 간 교차 의존을 매핑한 뒤 작업한다 — 단일 선행 chain만 가정 X.
4. **프로젝트-local 우선**: 프로젝트 루트 CLAUDE.md·가이드가 있으면 정독하고, 그 "건드릴/건드리지 말 파일·매 세션 반복 지시·운용 프로토콜"을 본 세션에 강제한다. 글로벌 규칙과 충돌하면 프로젝트-local 우선. 프로젝트 한정 정보는 글로벌로 자동 승격 X(타 프로젝트 오염 회피).
5. **신규 문건 양식·위치 사전 확인**: 새 산출물(계획서·result·핸드오프) 생성 전 같은 종류 기존 문건의 제목·구조·저장 위치를 먼저 정독하고 그에 맞춰 만든다(임의 양식·임의 위치 금지 — 잘못된 폴더 생성 후 삭제·재작성 사고 회피).

## 이유

세션 진입 정독을 건너뛰어 인계 chain을 놓치거나(이전 세션 결과를 "했다더라"로 처리), 멀티트랙 중 한 트랙만 보고 작업하거나, 기존 양식을 안 보고 새 문건을 임의 위치·임의 형식으로 만든 사고가 반복됐다.

## 실행 방법

- 세션 진입 직후 위 다섯 항목을 순서대로 이행하고, 정독 완료 전에는 계획·편집을 시작하지 않는다.
- 근거 부재 시 "근거 미발견" 명시(추정 금지).
- 작업 중 새 정보·결정 패턴이 누적되면 프로젝트 CLAUDE.md에 추가 제안(지킬 규칙·경계만 · 판·릴리스 이력은 따로 둔 판 요약 파일로 — `skill:skill_LKS_original_plan-execution` 1b 「판 이력」).

## 예외·금지

- "지난 세션이 했다"는 자기·타 세션 보고를 실물 확인 없이 신뢰하지 않는다.
- 정독 미완 상태로 계획서 작성·코드 편집을 시작하지 않는다.
