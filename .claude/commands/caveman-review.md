`skill:skill_LKS_custom_caveman-korean-review` 를 실행해 **코드 리뷰를 수행한다.**

## 리뷰 대상

$ARGUMENTS

비어 있으면 현재 작업 트리의 변경분(`git diff` + 스테이징분)을 대상으로 한다.

## 진행

1. 대상 diff 를 먼저 확보한다. PR 번호를 받았으면 `gh pr diff <번호>` 를 쓴다.
2. 지적 하나당 **한 줄** — 스킬 꼴 그대로(`L<line>: <problem>. <fix>.` · 여러 파일이면 `<file>:L<line>: …` · 심각도 머리 = 스킬 「Severity prefix」). 서론·칭찬·완충 문구를 붙이지 않는다.
3. 심각도 순으로 정렬한다. 보안·데이터 손실이 먼저다.
4. **근거 없는 지적을 만들지 않는다.** 지적이 없으면 없다고 한 줄로 쓰되, 읽은 범위와 반증 시도를 함께 적는다(헌법 §3 검수 규범 — 빈 통과 금지).
5. 변경분 밖의 기존 코드는 리뷰 범위가 아니다. 지나가다 본 것은 따로 한 줄로만 남긴다.

보안·인증·입력 처리·쿼리·파일 경로가 걸린 변경이면 그 항목은 압축하지 않고 평문으로 쓴다.

이 커맨드는 사용자가 부른 PR·diff 리뷰(붙여 넣을 코멘트)다 — 3-세션 분업의 검수 서브 보고(헌법 §3 — 수정안 칸 없음)에는 쓰지 않는다.
