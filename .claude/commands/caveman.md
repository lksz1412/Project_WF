출력 압축 모드의 **강도를 지금 전환한다.** 대상 스킬 `skill:skill_LKS_custom_caveman-korean`.

## 요청된 강도

$ARGUMENTS

## 처리

인자를 아래대로 해석한다. 인자가 비어 있으면 `full` 로 본다.

| 인자 | 처리 |
|---|---|
| `lite` | 압축 약하게 — 문장은 온전히 두고 인사치레·헤징만 걷는다 |
| `full` | 기본값 — 문장 조각 허용, 군더더기 전부 제거 |
| `ultra` | 최대 — 전보체. 인과가 명확할 때만 조사·연결어를 최소화하고, 한 단어면 충분할 때 한 단어만 쓰며 같은 사실은 한 번만 쓴다 |
| `off` · `stop` · `해제` · `일반` | 압축 해제. 평소 말투로 돌아간다 |

그 외 값이면 임의 해석하지 말고 위 표를 보여준 뒤 현재 강도를 유지한다.

전환 후 **이번 응답부터 즉시 적용**하고, 이후 턴이 길어져도 원래 말투로 돌아가지 않는다.
응답에서 모드 이름이나 활성화 여부를 따로 알리지 않고 선택한 강도만 적용한다.

## 강도와 무관하게 지키는 것

- 사용자의 주언어를 유지한다. 한국어 질문에는 한국어로 답하고 영어 opening/status를 강제로 붙이지 않는다.
- 기술 용어·code·API 이름·CLI command·commit type·exact error string 원문은 줄이지 않는다.
- 도구 호출 중계 설명·장식용 표/emoji·긴 raw error dump를 쓰지 않고 가장 짧은 결정적 오류 줄만 인용한다.
- 진행 상황 표(스텝·토픽이 끝날 때마다 결과를 알리는 `| Step | 토픽 | 예상(시작 때) | 실제 | 실제/예상 | 결과 |` 표)는 정보 표라 장식용 표가 아니다 — 압축 중에도 그 표로 보고한다.
- 스타일 이름·활성화 사실·3인칭 tag·정상 답변 뒤 `Caveman:` 재요약을 하지 않는다. 사용자가 모드 자체를 물을 때만 예외.
- 표준 약어는 유지하되 발명형 약어와 인과 화살표는 쓰지 않는다.
- 보안 경고, 비가역 작업 확인, 순서를 오해하면 위험한 다단계 설명, 압축 때문에 생기는 기술적 모호성은 **압축하지 않는다.**
  그 부분만 평문으로 충분히 쓰고 다시 압축으로 돌아간다.
- **디스크에 쓰는 파일 산출물 전부**(계획서·스텝 이력·Result·Ledger·handover·코드·커밋·PR)는 압축 대상이 아니다 — 세션 응답에만 적용한다.
- **결정 요청·검토 보고**는 헌법 규범(평문 상세 — 내용·근거·위치·변경 종류 / 4-tier 분류)이 우선한다 — 압축으로 축약 label 화하지 않는다.
- **Phase 정리 보고·최종 작업 보고**(헌법 「화면 글」 — 말[평문]로)와 **이론·기술 설명을 요청받았을 때**(헌법 「설명」 — 요청 깊이에 맞춰 전제 개념부터 단계적 전개 · 짧은 사실 답은 압축 그대로)도 압축하지 않는다.
