# Code 어댑터 (소스 파일의 시각 구조 — 구획·박스 헤더·상태 마커·번호)

코어 규칙(압축·통일·타이포 원리)은 `core_principles.md`, 검수 라운드·검증은 `verification.md` · `skill:skill_LKS_original_review-chunking` · 헌법 §3. 여기는 **Code 매체 수단** — 소스 파일의 시각 구조(구획 지도·박스 헤더·상태 마커·4단계 번호). **주석 내용·식별자 명명 규율은 규범 원본에 위임**(§7).

**제1원칙 적용**: 코드도 압축 → 시각 배치 대상 — 구획 지도·박스 헤더·마커·번호 = 문장 대신 **공간 배치**로 "어디를 고치려면 어디로" 한눈에(소스 = 세로로 읽는 산문 아님, 구조가 곧 배치).

**pyqt.md 와 분업**: code.md = 소스 파일의 텍스트 구조(전 언어 공통) · pyqt.md = 렌더된 Qt UI 레이아웃(위젯·여백·palette). 한 PyQt 소스는 둘 다 적용(소스 구조 = code.md · 위젯 배치 = pyqt.md). **주석 내용·식별자 명명은 시각 아님 → 규범 원본에 위임**(pyqt.md 도 동일 방향).

---

## 1. 모듈 독스트링 — 경량 (in-file 최소)

| 대상 | 위치 |
|---|---|
| **in-file (파일 상단)** | 역할 1줄 + 공개 API + 의존성 **만** |
| 구획 지도 테이블 | → `SECTION_MAP.md`(in-file 누적 금지) |
| `★` 구현 대상 목록 | → `SECTION_MAP.md`(구획 지도와 함께) |
| 버전·작업 이력 | → `CHANGELOG.md`(코드 기입 금지 · 주석원본) |

- in-file 상단 = 파일 헤더 박스(§2) + 포인터 한 줄(지도·이력 md 위치) + 역할 한 줄 docstring.
- 반전: "구획 지도 반드시 in-file" → **in-file 최소 · 지도는 md**(상단 독스트링 비대 방지 · 규범 원본 정합).

## 2. 섹션 구조 — 박스 헤더 + 번호 체계

박스 헤더 + 계층 번호 = 코드의 **공간 배치 장치**(어느 함수·위젯을 고치려면 어디로 가는지 한눈).

```
################################################################################
### app_shell.py — 메인 셸: 시트 오케스트레이션 + 상태 라우팅
################################################################################
#   공개 API·의존성 · 구획 지도 → SECTION_MAP.md · 이력 → CHANGELOG.md
"""메인 셸 — 시트 전환과 전역 상태 라우팅."""


################################################################################
##  A. 임포트 · 상수                                          [완성]
#    - 외부 의존은 이 구획에서만 import.
################################################################################
#   A.1. 표준 라이브러리
import sys

#   A.2. 모듈 상수
_POLL_INTERVAL_MS = 500


################################################################################
##  B. 메인 셸 위젯 (MainShell)                               ★ TODO(1)
#    - 시트 스택 + 상단 네비게이터 + 상태 배지.
################################################################################
#   B.1. 시그널
class MainShell(QWidget):
    sheet_changed = Signal(int)          # 활성 시트 인덱스
#   B.1.1. 생성자
    def __init__(self, parent=None):
        ...

#   B.2. _build_nav — 상단 네비게이터 바
    def _build_nav(self):
        ...
```

| 단계 | 형식 | 의미 |
|---|---|---|
| 파일 헤더 | `### 파일 — 역할` 박스 | 파일 최상단(마크다운과 반대로 최소 `#` 수 — 박스 안에선 작은 수로 충분) |
| 대구획 | `##  A.` 박스(공백 2칸) | 파일 내 큰 책임 단위 |
| 서브 구획 | `#   A.1.`(공백 3칸) 또는 `##  A.3.` 박스 | 단순 그룹(상수·import) = 한 줄 · 큰 단위(클래스·주요 함수집합) = 박스 |
| 항목 마커 | `#   A.3.1.`(4단계) | 개별 함수·클래스·위젯 · `A.3.1.1`(5단계) 금지 |

| 규칙 |
|---|
| **구분선 길이 = 코드베이스 전체 동일**(권장 80자) — 코어 §2 통일성의 코드 판 |
| 대구획 = 박스 **안**에 짧은 설명(`#    - …`) · 박스 **밖** 설명 라인 금지(두면 시각 분리됨) |
| 항목 마커 = 개별 단위 위 한 줄 · UI 항목은 연결 버튼·창·바 이름 표기 |
| **마커 들여쓰기 항상 0**(라인 첫 칸 `#`) — 본문 들여쓰기와 무관 · 시각 정렬 + grep 양립 |
| 클래스 attribute 그룹 첫 마커 = `class …:` 정의 **위** · 메서드 마커 = 정의 **직전** |
| 부연 = `#    - 텍스트` **단일 패턴**(4공백 + dash + space) · 다단계/정렬 들여쓰기 금지 · 한 줄 초과 시 별개 `- ` 항목 |
| 항목 마커 강제 아님 — "찾아갈 가치 있는" 단위(UI 핸들러·주요/재사용 헬퍼)에만 |

## 3. 상태 마커 (현상태 사실 1단어)

| 마커 | 뜻 (현상태 1단어) | 위치 | 규칙 |
|---|---|---|---|
| `★ TODO(n)` | 미구현 — 구현 대상 | 헤더·독스트링·인라인 | `n` = SECTION_MAP 구현 대상 번호와 일치 |
| `⚠ CAUTION` | 수정 시 확인할 제약 | 독스트링·인라인 | **이유 필수** — 이유 없는 CAUTION 금지 |
| `[완성]` | 구현 완료(현상태) | 헤더 | 한 단어 사실만 |
| `[안정]` | 변경 없음(현상태) | 헤더 | 한 단어 사실만 |

- 상태 마커 = **현상태 사실 1단어**로 한정 · 설계상태 서사·버전 이력·검수 ID 는 코드 금지 → md(주석원본).
- `★` 구체 표현(구현 대상 / 교체 대상 / 미검증 등)은 문맥에 맞게 선택 · 마커는 글리프 + 단어 이중 표기(색 의존 아님).

## 4. 독스트링·인라인 골격 (내용 규율은 규범 원본 · §7)

code.md = **형태(골격)**만 규정 · **무엇을 쓰는가**(내용)는 주석원본.

| 대상 | 골격 |
|---|---|
| 클래스·함수 독스트링 | **최소 = 역할 1줄 + 계약(Args/Returns)** · `★`/`⚠` 는 해당 시만 |
| 정리된 코드베이스 | 시그니처 + 항목 마커가 의미를 나르면 독스트링은 역할 1줄로 축소·생략 가능 |
| 교체 대상 함수 | `★` 표시 + 교체 범위 명확("이 함수 전체" / "이 함수 내 X 블록만") |
| 인라인 | **"왜"만**(무엇 금지 — 코드가 말함) · 구분선은 논리 블록 경계만(남발 금지) · 주석 언어 코드베이스 단일(혼용 금지) |
| attribute 옆 인라인 | 짧은 의미 표기 유지 가능(`Signal(int)  # 활성 인덱스`) |

- 역할 분담: **구조·위치 = 항목 마커(§2)** · **"왜" 1줄 = 본문 인라인**(주석원본이 허용하는 분기·수식 의미 1줄).
- 주석·독스트링 **내용 규율**(현상태 핵심만 · 버전 이력 md · **알파 예외 없음**) = `memory:feedback_code_comment_discipline` · 충돌 시 규범 원본 우선.

## 5. 조건부 재생성 (편집 입도)

| 상황 | 편집 방식 |
|---|---|
| 기본(변경 작음) | 부분 편집(str_replace) 또는 해당 블록만 |
| 신규 요청이 그 구획에 직접 관련 | 구획 전체 재생성 허용 |
| 후속 구획에 영향 발생 | 영향 구획도 함께 수정 |
| `[안정]`/`[완성]` 구획이 간접 영향만 | 최소 부분 수정만 |

- 완성 구획 이유 없이 재생성 X · 재생성 시 사전 고지 · 후속 수정 시 상태 마커 동시 갱신.
- 착수 전 범위 합의 · 배포 전 검증 · 배포 루틴 = `skill:skill_LKS_original_plan-execution`(§7).

| 순위 | 기준 |

| 3 | 언어 표준(docstring·코멘트 형식) — 구조·마커는 이 어댑터 기준 |

- 상위 = 헌법 §0-A 지침 우선순위(프롬프트 > 프로젝트 오토메모리 > CLAUDE.md·memory·SKILL).
- 명명·인코딩 권위 3계층(사용자 코드 → 프로젝트 컨벤션 → 언어 표준) = `memory:feedback_code_ownership_scope`.

## 8. 안티패턴

| 안티패턴 | 증상 | 교정 |
|---|---|---|
| 버전 이력·변경 서사 코드 기입 | 파일 비대 · 이력 중복 | md(CHANGELOG)로 · 주석원본 |
| 구획 지도 in-file 누적 | 상단 독스트링 비대 | in-file 최소(역할·API·의존성) · 지도 = SECTION_MAP.md |
| 초기(알파)라 in-file 이력 허용 | 이력이 코드로 재유입 | 단계 무관 이력 = md(예외 없음 · 주석원본) |
| 이유 없는 `⚠ CAUTION` | 무엇을 조심할지 불명 | 이유 병기 필수 |
| 구분선 길이 제각각 | 구획마다 폭 달라 시각 불통일 | 코드베이스 전체 동일 길이 |
| 부연 다단계·정렬 들여쓰기 | 어느 줄이 항목인지 혼동 | `#    - ` 단일 패턴 |
| 마커가 본문 들여쓰기 따라감 | grep·시각 정렬 깨짐 | 마커 들여쓰기 항상 0 |
| 구획 지도 ↔ 실제 구획 불일치 | 지도가 코드와 어긋남 | 구조 변경 시 지도 즉시 갱신 |
| 완성 구획 이유 없이 재생성 | 불필요한 diff · 회귀 위험 | 부분 수정 · 사전 고지 |
| 식별자 임의 개명 | 사용자 컨벤션 침해 | 사용자 표기 보존 · 명명원본 |
