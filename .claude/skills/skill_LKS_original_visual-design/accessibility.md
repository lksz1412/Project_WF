# 접근성 — 색 · 대비 · 채도 · 이중 인코딩 (시각 매체 코어 · 시각 매체 진입 시 로드)

색은 **렌더되는 시각 매체**(HTML·PPTX·PyQt·Diagram)를 관통하는 접근성 축이라 그 매체 진입 시 로드한다. **비-시각 매체(Code 소스 구조·LaTeX 수식 논리)에는 적용 대상이 없어 로드하지 않는다**(색·대비·SVG 축이 없음). 매체 구현(palette·CSS var·pptx token)은 각 어댑터.

---

## 1. 색 + 도형 이중 인코딩 (제1 규칙)

| 규칙 |
|---|
| **색만으로 의미 전달 금지** — 라벨·패턴·모양 병행(색각이상·흑백·다크테마 보호, WCAG SC 1.4.1 · Level A 직접 적용) |
| 4상태 = **4색 + 4도형**(예 ◇ ▲ ■ ⬟ 또는 ○ ◔ ◑ ●) — 색을 잃어도 의미 생존 |
| 다크테마 회색(Empty)과 disabled 가 거의 구분 안 됨 → 도형 가산으로 방어 |

### 2-1. 대비를 계산 없이 보장 — 명도 번호 차(KRDS 매직넘버)

KRDS(대한민국 정부 디자인 시스템)의 명도 단계 번호(0~100) 차이 → 보장 대비.

| 명도 번호 차 | 보장 대비 |
|---|---|
| **40** | 3:1(KRDS 최소) |
| **50** | 4.5:1(본문 하한) |
| **70** | 7:1 |
| **90** | 15:1 |

- **칸 수가 아니라 번호(0~100) 차이** — 램프 각 단계에 명도 번호를 박아 두면 뺄셈만으로 대비 등급이 나옴(예: 10 배경 위 60 글자 = 차 50 = 4.5:1).
- 전제 미검증 — KRDS 원문이 번호 척도(지각 명도인지)를 밝히지 않음 → 자체 램프에 쓰기 전 몇 쌍을 실제 계산해 검증.
- `web_page.md` 기준 블록의 `--n-0`~`--n-10` 은 **단계 순번이지 명도 번호가 아님** → 매직넘버 적용 불가 · 그 램프는 실측 대비표(`web_page.md` §5)로 판정.

### 2-2. ★ 대비 통과 ≠ 설계 통과 — 채도 예산 (웹 매체)

| 규칙 |
|---|
| 적용 = 웹 매체(웹 페이지·Artifact·HTML 도식·Diagram) · 발표 매체(PPTX)는 대상 아님 — 덱 팔레트는 발표용 고채도(매체 간 이식 금지 = `core_principles.md` §2) · PyQt 크롬은 OS palette 추종이라 대상 밖 |
| **구조색(배경·테두리·본문·제목) OKLCH 채도 C ≤ 0.032**(≈0.03 · `web_page.md` 기준 블록의 실측 상한 = Tailwind gray 계열 수준 C 0.002~0.032 · 더 푸른 slate 계열 C 0.04 안팎은 밖) · OKLCH = 사람 눈의 밝기 지각에 맞춘 색 좌표(명도 L·채도 C·색상 H) |
| **유채 면적 ≤ 5%** — 강조 전용(KRDS Accent) · 데이터·상태색(§3)은 면적 예산 밖 |
| 반례: 덱 블루 `#1428A0` = 흰 배경 대비 **11.41:1 통과**인데 채도 **C=0.1908**(같은 명도 구조색 `#374151` C=0.0306 의 **6.2배**) → 대비 게이트로 못 잡는 결함 · 강조색 수준 채도를 구조 전면에 깔면 강조할 자리가 사라져 위계 붕괴 |

- 토큰(색) 변경 시 대비(웹 매체는 + 채도)를 **재계산해 기록** — 웹 토큰 = 기계 검사 `tools/check_color_tokens.py`(사람 재계산 대체 · 사용법 = `web_page.md` §7) · 그 밖 매체 = 사람이 재계산(PPTX = 어댑터 대비 기록표).
- 회색 하한 실패 사례: `#8A8F98` = 3.25:1 → 본문 실패(비텍스트 3:1 로만 가능).

## 3. ★ 크롬색 vs 데이터색 분리 (매체 충돌 해소축)

| 부류 | 정의 | 색 정책 |
|---|---|---|
| **크롬색** | 배경·텍스트·테두리 | **테마 토큰 추종**(단일 소스) |
| **의미·데이터색** | 상태·시리즈·plot 곡선 | **hue 고정 명시값** — distinct hue 가 본질 · 웹 매체(웹 페이지·Artifact·HTML 도식·Diagram) = 라이트·다크 두 벌(hue 그대로 · 명도 보정 · §6 ②) · 그 밖 매체 = 테마 무관 한 벌(§6 ①) |

- pyqtgraph plot·사용자 시리즈 색은 palette 비추종(명시색 필수).
- 하드코딩 색 금지는 **크롬 한정** — 데이터색은 명시값을 지킨다.

## 4. 의미축 · 배경 · 강조

| 규칙 |
|---|
| 색은 **단일 의미축 하나만** 인코딩(도중 다른 색 스킴 끼우기 금지). 순수 구조 도식 = 중립색 + 텍스트 배지 |
| 색 = **주의 유도**(핵심 수치·선택 항목)에만. 면채움·그라데이션·장식 금지 |
| 기본 배경(카드/박스 면) **통일** — bg 있고 없고 혼용 금지 |

의미축은 1개, 크롬은 그와 별개(크롬 추종은 의미축 계수에 안 들어감).

## 5. alt text

| 도형 종류 | alt |
|---|---|
| 뜻 담은 도형 | 뜻을 넣음(PPTX·PDF·스크린리더 보존) |
| 뜻 없는 도형(구분선·배경카드·띠) | 비움(`altText: ""`) |
| HTML 도식의 비텍스트(화살표·강조 표지) | 화면 밖 숨김 글자(예 "다음 단계"·"핵심:") 또는 `role="img"` + `aria-label` · 뜻 없는 장식 = `aria-hidden="true"` |

## 6. 데이터색 정책 옵션 (웹 매체 = ② · 그 밖 매체 = 사용자 결정 gated)

| 옵션 | 내용 |
|---|---|
| ① 테마 무관 유지 | 테마 무관 데이터색(기능·구분 보존) |
| ② 테마 명도 적응 | 라이트/다크 밝기 보정, **hue 유지** |
| ③ 테마 인지 큐레이트 팔레트 | 테마 인지 의미 팔레트 |

| 매체 | 채택 |
|---|---|
| 웹 매체(웹 페이지·Artifact·HTML 도식·Diagram) | **② 확정** — 한 벌만 두면 다크에서 상태면 위 글자 대비 1.03~1.47:1(SC 1.4.3 미달 · 실측) · 도식 상태색 값 = `html_css.md` §6-1 |
| 그 밖 매체(PyQt plot·시리즈 등) | 기본 **①** — 변경은 사용자 결정 전 미착수 |
