# 웹 페이지 어댑터 (페이지 전체 토큰 · claude.ai Artifact 포함)

코어 규칙(압축·통일·타이포 원리·정렬·매체 간 이식 금지)은 `core_principles.md`, 접근성(대비·이중 인코딩·채도 예산)은 `accessibility.md`, 페이지 안 도식(플로우차트) 컴포넌트는 `html_css.md`, 검증 철학은 `verification.md`. 여기는 **웹 페이지 전체의 토큰과 쓰는 법**(색 램프·다크·한글 타이포·간격·반경·층) — **도식보다 먼저 고정**한다.

**덱·PPTX 팔레트를 그대로 가져오지 않는다**(코어 §2 「매체 간 토큰 이식 금지 — 색 포함」) — hue 만 승계하고 채도·명도는 아래 기준으로 재배정.

**대상 분기**:

| 대상 | 이 어댑터 | 외부 의존 |
|---|---|---|
| 오프라인 자기완결 HTML(개요·보고 페이지) | 전 절 적용 | **이 행이 오프라인 규칙의 원본**(페이지 속 도식도 따름) — 외부 CDN·웹폰트·MathJax 금지(오프라인에서 깨짐) · 수식 = HTML/Unicode(`<sub>`/`<sup>`·Φ·Σ·√) · 아이콘 = 이모지/유니코드 · **외부 의존 0 검사** = http·link·script·img 원격 참조 grep(§7) |

## 1. 색 — 뉴트럴 램프 + 강조 1

| 규칙 |
|---|
| 중성 램프 = **강조색과 같은 hue · 채도 C ≤ 0.032(≈0.03) · 명도만 계단** — 단계 수 11~13(기준 블록 = 11단 `--n-0`~`--n-10` · 값 = §5) |
| 채도 상한 0.032 = 기준 블록(§5)의 실측 상한(Tailwind gray 계열 hex 값과 같은 수준 · C 0.002~0.032) · 더 푸른 회색(Tailwind slate 계열 · C 0.04 안팎)은 상한 밖 · 브랜드 hue 를 싣더라도 이 상한 안에서만(§6-4) |
| 강조색(hue) **1개**(많아야 2) — 토큰 `--accent`·`--accent-hover`·`--accent-bg` |
| 유채 면적 **5% 이하**(KRDS Accent) — 쓰임 = 강조 지점(시각 단위당 한 곳 — 코어 §4) + 링크 글자 + 소면적 브랜드 표지(§6-4) · 코어 §9 카탈로그형 「진채움+흰글자는 표지·구획만」도 웹에선 이 예산 안에서만 |
| 데이터·상태색(차트 시리즈·상태 표시)은 면적 예산 밖 — 명시값 유지(`accessibility.md` §3) · 대비·이중 인코딩은 그대로 적용 |
| 표기 = `oklch()` — Baseline widely available(2023-05~) · 전역 지원 94.25% · Chrome/Edge 111·Firefox 113·Safari 15.4 · HSL 은 같은 L 이라도 hue 마다 밝기가 달라 대비 등급이 흔들림 · 매우 보수적인 환경의 폴백 = 실제 속성(`color:` 등)은 `#RRGGBB` 선언 뒤에 `oklch()` 를 두는 2줄 · **토큰(사용자 정의 속성)에는 2줄 폴백이 작동하지 않는다**(뒤 선언이 그대로 채택되고, 미지원 브라우저에선 그 토큰을 쓴 속성이 계산 때 무효가 돼 상속값으로 떨어짐) → hex 토큰 블록(§5 주석값 — hue 를 바꿨으면 도구 직접 모드 `--fg <oklch 값> --bg white` 가 찍는 hex)을 먼저 두고 `@supports (color: oklch(0 0 0)){ :root{ …oklch 토큰… } }` 로 덮는다(다크 두 블록도 같은 방식) |
| 단계는 토큰으로 고정 — `lighten()`·`darken()` 같은 색 수식 함수로 즉석 생성 금지 · 순수 검정 금지(가장 진한 단계 = 아주 진한 회색) |
| 단계 의미(Radix 12단 용도) = 1 앱배경 · 2 약배경 · 3 요소배경 · 4 hover · 5 active/selected · 6 약테두리 · 7 테두리·포커스 · 8 hover 테두리 · 9 솔리드 · 10 솔리드 hover · 11 약텍스트 · 12 강텍스트 — 기준 블록 대응은 §5 주석 |
| **★ 정보 경계·포커스링 = 3:1 을 실측 통과한 단계에만**(SC 1.4.11) — Radix 가 step 7 을 「focus rings」 라 부르지만 3:1 보장 아님(Radix 보장 = step 11·12 의 APCA Lc 60/90 뿐 · APCA = Accessible Perceptual Contrast Algorithm, 표준 아님 — `accessibility.md` §8) · 실측: 중간 단계 2.53:1 **미달** → 한 단계 진한 쪽(4.83:1)에 배정 = 기준 블록 `--n-7` |
| **장식 단계**(`--n-5` 장식 구분선 · `--n-6` 장식 테두리) = 장식 전용 — **정보 경계·글자·아이콘 금지**(§6-5) |
| **틴트 면(`--accent-bg`) = 3:1 테두리 동반 필수** — 틴트만으로는 SC 1.4.11 미달(덱 `#E7EAF5` on 흰색 1.20:1 · 기준 블록 틴트(§5 `--accent-bg`)도 1.10:1 로 같은 실패) |

## 2. 다크 모드 — 반전 금지 · 전 단계 재배정

| 규칙 |
|---|
| **같은 토큰 이름 · 다른 값 매핑**(Radix mutable alias) — 색 반전 금지 · 라이트 앱 배경 = 흰색 ↔ 다크 앱 배경 = 다크 램프의 가장 어두운 1~2단계 |
| **★ 다크에선 램프 전 단계(기준 블록 11단 전부)를 재배정** — 배경·본문만 바꾸면 중간 단계가 깨짐(실측: 약한 텍스트 라이트 7.61:1 → 다크 **2.48:1** 붕괴) |
| **양 모드 대비를 각각 재계산** — 대비비는 반전 불변 아님(`#374151` 흰 배경 10.31:1 → 어두운 배경 `#111827` 위 1.72:1) |
| 다크 강조색 = 명도↑ 채도↓(기준 블록 `--accent` C 0.215 → 0.140) · 다크 램프 채도도 C ≤ 0.032(채도 있는 회색을 다크 배경에 쓰면 컬러 컴포넌트와 충돌 — Radix 경고) |
| 다크 본문 조합에 순수 검정·순수 흰색 금지 |
| 다크 층 = 그림자 대신 **표면 명도 차이**(어두운 배경에선 검은 그림자가 안 보임 · Material Design 3 방향 — 원문 직접 인용 미확보) |
| **다크 전환 수단 제공** — 첫 화면 = OS 선호(`prefers-color-scheme`)를 따른다(선호 정보가 없는 환경이면 라이트) · 토글 = 지금 보이는 테마의 반대로 강제(`data-theme`) · 정상 시력 사용자는 라이트에서 성능이 더 좋고, 백내장 등 안구 매체 혼탁 사용자는 다크에서 더 빨리 읽음(Nielsen Norman Group 정리) |
| 전환 3상태 = OS 추종(속성 없음) · 강제 라이트(`<html data-theme="light">`) · 강제 다크(`<html data-theme="dark">`) — §5 블록이 셋 다 처리 |
| **강제 전환은 `color-scheme` 동반** — 토큰만 바꾸면 브라우저 기본 컨트롤(스크롤바·input·select)은 라이트로 남음(크로미움 실측: 강제 다크에서 input 배경 흰색 그대로) · 선언 3줄(§5 블록) 전부 필요 — `<meta name="color-scheme">` 나 `:root{color-scheme:light dark}` 한 줄만으론 OS 추종만 맞고 강제 라이트·다크는 못 따라감 |

## 3. 타이포 — 한글 기준 (KRDS)

적용 = 한글 본문(이 패키지 산출물 기본) · 라틴 전용 본문은 줄 길이만 80자(SC 1.4.8).

| 항목 | 값 |
|---|---|
| 서체 | Pretendard GOV → Pretendard → **한글 시스템 서체**(Malgun Gothic · Apple SD Gothic Neo · Noto Sans KR · Noto Sans CJK KR) → system-ui 폴백(스택 = §5 `--font`) · 서체 하나(코어 §3 · 예외 = 코드·식별자 표기용 고정폭 1종 `--font-mono`) — 한글 서체를 system-ui 앞에 둬 라틴·한글이 한 서체로 그려지게(system-ui 가 먼저면 라틴은 Segoe UI 등·한글은 다른 서체로 갈려 굵기·폭이 어긋남) · 웹폰트 로드 여부는 매체 수단(오프라인 = 금지 → 설치된 PC 에서만 Pretendard, 그 밖은 한글 시스템 서체) |
| 본문 | **17px**(하한 16px) — Pretendard GOV 가 다른 서체보다 작게 렌더돼 16px 하한 위에 17px 를 기준으로 둠 |
| 크기 단계 | Body 19 / **17** / 15 / 13 · Heading 40 / 32 / 24 / 19 / 17 / 15 · Display 60 / 44 / 36(표지급만) — PC 기준 px · 목록 밖 크기 금지(코어 §3 소수 이산 단계) · 기준 블록 토큰 = Body 4 + Heading 5(`--fs-*`) · 페이지 안 도식의 글자(크기·서체)는 도식 어댑터를 따른다(우선 규칙 원본 = §4 「페이지 안 도식」) |
| 행간 | **150% 전 단계 일괄** |
| 자간 | 본문·24px 이하 제목 **0px** · Display·대형 제목(32·40px)만 **+1px**(`--ls-l`) · **음수 자간 금지**(KRDS 토큰의 자간 값은 0·+0.1rem[= 1px] 둘뿐 — 음수 없음 · SC 1.4.12 자간 0.12em 확대 내성에 불리) |
| 굵기 | **400 / 700 두 종만** — 위계는 크기 + 굵기(코어 §3) |
| 줄 길이 | 한글 본문 **40자 = `max-width:40em`**(SC 1.4.8 「40 if CJK」 · CJK = 한중일 문자 · `ch` 는 숫자 `0` 폭 기준이라 한글에 부적합 · 전각 1자 ≈ 1em) · 17px 기준 680px |
| 문단 | 문단 간격 ≥ 행간의 1.5배 · 양끝맞춤(`text-align:justify`) 금지(SC 1.4.8) · 사용자가 행간 1.5×·문단 2×·자간 0.12em·단어 0.16em 로 바꿔도 손실 0(SC 1.4.12) |
| 줄바꿈 | (한글 줄바꿈 규칙·이유의 원본 — 페이지 속 도식 포함) `word-break:keep-all` + **`overflow-wrap:anywhere` 병행** — `keep-all` 단독은 긴 URL 에서 넘침 · **표 칸(`td`·`th`) = `overflow-wrap:break-word`**(`anywhere` 는 최소 폭 계산에 들어가 자동 표 배치가 열을 한 글자 폭으로 눌러 식별자를 중간에서 끊음 — 실측 `CLAUDE.m/d` · `break-word` 는 안 들어감) · 식별자 칸은 `white-space:nowrap` · 표가 넘치면 `overflow-x:auto` 감싸개 · **가운뎃점(·)은 `keep-all` 아래서도 줄바꿈 기회**(크로미움 실측) → 한 줄에 들어갈 짧은 `·` 묶음은 `white-space:nowrap` 으로 묶고 길면 의미 경계에서 `<br>` · 줄머리 `·` = 결함 |

## 4. 간격 · 반경 · 타깃 · 층

| 항목 | 값 |
|---|---|
| 간격 | **8pt grid** — 4·8·12·16·24·32·48·64px(`--s-1`~`--s-8`) · 격자 밖 값(13·18·22 등) 금지 |
| 격자 대상 | 간격(margin·padding·gap)만 — 테두리 굵기(아래 행)·글자 크기(§3 스케일)·브레이크포인트·레이아웃 폭(`flex-basis`·`max-width`)은 대상 밖 |
| 테두리 굵기 | **정수 px(1·2·4)** · 소수(예 1.5px) 금지 — 크로미움은 테두리 폭을 장치 픽셀로 내려 배율 1 화면에서 1.5px = 1px(가벼운 경계와 무게가 같아지고 이중선·띠가 얇아짐 · 배율 2 확인에선 가려짐) · 확인 = 배율 1·2 렌더(§7) · 페이지 구획 무게 = §6-2 · 도식 안 굵기 배정 = `html_css.md` §6-1 |
| 화면 여백 | 768px 이상 **최소 24px** · 768px 미만 **최소 16px** |
| gutter | 768px 이상 16~24px · 768px 미만 16px |
| 페이지 최대 폭 | **1200px**(`--page-max`) · 본문 컬럼은 그 안에서 40em(§3) |
| 브레이크포인트 | 360 / 768 / 1024 / 1280 / 1440px |
| 좁은 폭(768px 미만) | 도식 = 코어 §5 「좁은 폭 방향 전환」대로(가로 순차만 전체 회전 · 행 대응은 좌→우 유지 — 원본 = 코어) · 표 = 가로 스크롤 감싸개 또는 행을 카드로 · 컴포넌트 = `html_css.md` §6-2 |
| 반경 | **컨테이너 높이 × 0.125, 짝수 반올림, 최대 12px** → 2(배지·인디케이터) / 4(칩·체크·태그) / 6(버튼·인풋) / 10(카드·다이얼로그) / 12(배너·시트) — `--r-xs`~`--r-xl` · 산식은 **유형별 토큰을 정하는 기준**(그 유형의 대표 높이에 적용) — 같은 유형은 높이가 달라도 같은 토큰(통일성 · 코어 §2) |
| 페이지 안 도식 | (페이지와 도식 어댑터 규범이 겹칠 때의 우선 — 이 행이 원본) 도식 안 글자(크기·서체) = 그 도식 어댑터(`html_css.md` §2·§6 · `diagram.md` §5) · 도식 틀·노드의 간격(틀 안 여백·노드 사이)과 반경 = 이 절 토큰(`--s-*` · 반경 = 노드 `--r-l` · 틀 `--r-xl` · 구역 `--r-m` — `html_css.md` §6 과 같은 배정 · SVG 좌표도 같은 값) — `diagram.md` §2 의 gap·radius 스케일은 페이지 밖 단독 도식의 기본값이라 페이지 안에선 쓰지 않음 · 도식 내부 좌표 격자(4배수)·커넥터 기하(`diagram.md` §4 elbow 반경) = 그 도식 어댑터 |
| 타깃 | 클릭 대상 **≥ 24×24 CSS px**(SC 2.5.8 · 예외 5종 = `accessibility.md` §2) |
| 층 | 6단 의미 — −1 묶음 컨테이너 / 0 배경 / +1 기본·비활성 / +2 주요 상호작용 / +3 툴팁·패널·바텀시트·모달 / +4 긴급 알림 |
| 그림자 | 층 번호의 시각화(장식 아님) · 같은 층 = 같은 그림자 · 층에 배정된 소수 단계만 · `box-shadow` 수치는 프로젝트 재량(KRDS 원문에 값 없음 — 근거 미발견) · 다크 = §2 표면 명도 차이 |

## 5. 기준 토큰 블록 (실측 통과본 — 값 변경 금지)

## 6. 쓰는 법 — 위계·경계·강조·브랜드 (토큰은 그대로, 쓰는 법으로 막는다)

토큰이 게이트를 전건 통과해도 쓰는 법이 틀리면 위계·인상이 무너진다 — 기준 블록으로 덱 4장을 웹 페이지로 옮겨 라이트·다크 렌더를 육안으로 본 테스트베드가 드러낸 약점 4건(§6-1~§6-4) + 저작 중 결함 1건(§6-5)의 규범화.

### 6-1. 위계 — 배경 단계 차이만으로 만들지 않는다

| 규칙 |
|---|
| 위계 수단 순서 = **1차 크기·굵기 → 2차 여백 → 3차 경계** · 배경 단계 차이는 위계 수단 아님 |
| 인접 배경 단계(예 `--n-1`→`--n-2`) = 육안으로 거의 구분 안 됨(테스트베드 관찰 — 위계를 실제로 만든 것은 글자 굵기·크기) |
| 배경으로 영역을 가를 땐 **램프 2단계 이상 건너뛰기 또는 경계 동반** — 정보를 전달하는 경계면 3:1 단계(§1) |

### 6-2. 경계 — 정보를 전달하는 경계는 무게 2단만

| 규칙 |
|---|
| 정보 경계 = **무거운 경계(주요 구획) · 가벼운 경계(카드·표 헤더)** 두 단만 — 둘 다 3:1(SC 1.4.11) 이상 · 양 모드 각각 |
| 방식 A = 큰 구획은 테두리 없이 **여백·제목으로** 가르고, 테두리는 가벼운 경계(카드·표 헤더)에만 |
| 방식 B = 무거운 경계만 한 단계 올림 — 두께 우선(예 1px → 2px, 같은 `--n-7`) · 색을 올리면 한 단계 진한 `--n-8` |
| 금지 = `--n-7` 한 단계·같은 두께로 바깥 프레임·표 헤더·카드 테두리를 전부 통일("더 중요한 경계" 신호 소멸 — 테스트베드 관찰) |
| 장식 구분선(`--n-5`·`--n-6`) = 정보 경계로 쓰지 않음(행 구분선 같은 장식만 · §1) |
| 장식인지 정보 경계인지 애매하면 **정보 경계로 취급**(3:1 단계 `--n-7` 이상) — 경계가 사라졌을 때 내용 구분이 무너지면 정보 경계다 |
| 이 절의 2단은 **페이지 구획**(구획·카드·표 헤더)에 적용 — 도식 내부(틀·노드·구역) 경계 무게는 `html_css.md` §6 이 정함 |

### 6-3. 강조 — 테두리가 주 채널, 배지는 보조

| 규칙 |
|---|
| **강조의 주 채널 = 테두리 굵기 + 색**(예 강조 카드 `--accent` 4px — 나머지 `--n-7` 1~2px) · 라벨 글자색(`--accent`)은 선택 — 강조색 글자는 본문색보다 대비가 낮아 흑백 검사에서 이웃 라벨보다 옅어 보일 수 있음 → 그러면 라벨은 본문색 + 굵게, 강조는 테두리로 |
| **배지(`--accent-bg` + `--n-7` 테두리) = 보조** — 배지만으로 강조 금지(테스트베드 3중 인코딩 중 가장 약함 · 테두리를 먼저 보고 나서야 눈에 들어옴) |
| 강조 지점 = 시각 단위당 한 곳(코어 §4) · 색 + 굵기 이중 인코딩(`accessibility.md` §1) |
| 링크 = `--accent` 글자(4.5:1 — §5 표) + 밑줄 병행 — 색만으로 링크 구분 금지(SC 1.4.1) |

### 6-4. 브랜드 인상 — 채도 면적이 아니라 소면적 표지로

| 규칙 |
|---|
| 강조를 아끼면 강조 없는 구획이 무채색 기본 템플릿처럼 밋밋해지고 "이 조직 것" 인상이 줄어듦(테스트베드 관찰) → **채도 면적을 넓히지 않고** 아래 3가지로 |
| ① 중성 램프에 브랜드 hue 싣기 — 채도는 C ≤ 0.032 그대로(§1) |
| ② 강조색 = 브랜드색에서 **hue 만 승계** — 채도·명도는 웹 기준으로 재배정(코어 §2) |
| ③ 소면적 브랜드 표지 허용 — 예 상단 띠 · 유채 면적 5% 예산 안(§1) · `accessibility.md` §4 「색 = 주의 유도에만」의 명시 예외(웹 매체·이 예산 안 한정 — 그 밖 면채움·그라데이션 금지는 그대로) |

### 6-5. 장식 단계는 글자에 쓰지 않는다

| 규칙 |
|---|
| 장식 단계(`--n-5`·`--n-6`) = **글자·아이콘 색 금지** — 대비 라이트 1.81·2.53 / 다크 2.12·2.99(§5 표) = 본문 4.5:1·비텍스트 3:1 모두 미달 |
| 약한 글자 하한 = `--n-8`(약한 텍스트) |
| 실례: 표 빈 값 `—` 를 장식 `--n-6` 글자로 쓰려다 2.3:1 미달 → `--n-8` 로 교정(저작 중 자체 발견 — 규범을 알고도 손으로 고르면 틀림 → §7 기계 게이트) |
