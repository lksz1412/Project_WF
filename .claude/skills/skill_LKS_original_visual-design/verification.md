# 검증 — 다방법 철학 (얇음 · 검수 진입 시 로드)

매체별 도구는 각 어댑터, 청크·관점·검증 절차 규범은 헌법 §3 · `skill:skill_LKS_original_review-chunking`. 여기는 **철학 + 라우팅**만.

---

## 1. 다방법 검증 — 방법마다 잡는 결함이 다르다

| 검증 방법 | 잡는 결함 | 못 잡는 결함 |
|---|---|---|
| 정적(좌표·소스 grep) | 캔버스 이탈·겹침·오프라인 의존 | 정렬·오버플로·색·간격(시각) |
| 렌더 픽셀 측정 | 폭 동일·computed 크기·오버플로 0·콘솔 에러 0 | 넘침(빠듯한 상자) 일부 |
| 육안(렌더 후) | 형태·리듬·의미 오독 | (수치 근거 없음) |

**결함 종류로 담당 방법을 정한다.** 하나로 전부 못 잡는다.

## 2. 필수 규율

| 규칙 |
|---|
| **전달 전 반드시 렌더로 형태 육안 확인** — grep/소스로는 정렬·오버플로·색·간격 못 잡음 |
| **객관 측정 병행** — 폭 동일 · computed 크기가 의도한 값집합뿐 · 오버플로 0 · 콘솔 에러 0 |
| **색 게이트는 대비만으로 부족(웹 매체)** — 대비(본문 4.5:1·비텍스트 3:1) + **채도(구조색 C ≤ 0.032)** + **유채 면적(≤ 5%)** 3축을 라이트·다크 각각 측정 · 기계 검사 `tools/check_color_tokens.py` · 대비 통과 ≠ 설계 통과(`accessibility.md` §2-2 · 게이트표 = `web_page.md` §7) |
| 넘침은 픽셀로 못 잡음 → 정적 추정(WARN, 빠듯한 상자는 FAIL 승격) + 육안 확정 |
| **건너뛴 게이트 = "통과" 아니라 "미실행"/"부분 완료"로 기록**(미실행 ≠ 통과) |
| 점진 리뷰로 패치워크되면 조각 손질 말고 **구조부터 재설계**(정보구조 → 컴포넌트 시스템) |
| **전건 통과 전 산출물 교체 금지(freeze·last-known-good)** — 매체 정적 게이트 전건 통과 후에만 직전 양품을 새 산출물로 교체 · 부분 통과로 교체 X(실패 시 직전 양품 보존) |
| **검수 실패 = 구조화 보고(subject·evidence·supportedFix)** — 실패는 대상(무엇) + 측정 근거 + 허용 수리로 · 진단 대상 + 영향 지도 「함께 고침」만 고쳐 재검(막연 "고침" 금지) |

## 3. 반복 청크 검수

**적용 = 업무 등급 연동** — A1·A2 본격 시각 산출물 = 아래 검증 · A3·A4(정형·단순 수정·기계) = 자체검수 1회(등급 연동 원본 = 헌법 §3).

매 라운드 관점 하나로 검수 범위(바뀐 단위 + 영향 지도 단위) 전체 1회(시각 산출물 = P4 프리셋 + 가변 5) · 관점·청크 창을 라운드마다 바꿈 · coverage missing 0. 검증 1회 = 10라운드 · **조기 종료 없음(10라운드를 다 본다)** · ③ 구조 변경이 아니면 갈래별 검수(① 바뀐 줄 뜻 확인·유의어 자리 판정 · ② 바뀐 줄 + 지도 「함께 고침」·「확인만」 줄 한 번 검수 + 적대 항목 하나 + 연계 확인 · ④ 실행 게이트 + 바뀐 줄 · 판정 원본 = `memory:feedback_chunked_review` 「검수 구분」) → 다 본 뒤 이번 검증에 붙은 작업 서브 하나가 한 번에 고침 → 재검증(같은 검수 서브가 바뀐 단위 + 영향 지도 단위를 전문 정독으로 한 번 대조 · 800줄 미만 파일은 전문 · 10관점 재실행 아님).

절차·종료 규칙·관점 10개(고정 5 프리셋 + 가변 5)·등급별 강도 = 헌법 §3 · `skill:skill_LKS_original_review-chunking`(여기서 되풀이 X).
