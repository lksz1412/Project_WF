# 카탈로그·레퍼런스형 덱 — 규격·문체·색·피드백 운영 세칙

**적용 조건**: 구성물 N개(스킬·메모리·기능·모듈·명령)를 규격 페이지로 나열해 소개하는 설명서·사양서·카탈로그형 덱. 논증형 덱(결론 하나를 근거로 미는 덱)에는 적용하지 않는다.

**우선순위**: 카탈로그형 덱에서는 이 파일이 `content_rules.md`·`qa_procedure.md`의 아래 조항을 **덮어쓴다**(§12 override 표에 전수 명시). 표에 없는 조항은 기존 문서 그대로 적용한다. 사용자가 페이지 단위로 내린 지시는 언제나 이 파일보다 우선한다.

**정독 시점**: `pptx.md` 3단계(개요) 전에 §1~§3·§12를, 4단계(소스 작성) 전에 전체를, 피드백 라운드 진입 시 §10을 다시 읽는다.

---

## 1. 페이지 골격 (표지·목차·구획·본문 틀)

- **표지**: 대상물 이름 + 버전, 두 요소만. 부제·설명·날짜·작성자 등 잡내용 0.
- **목차**: 부(部) 이름만 나열한다 — 부별 요약·설명을 붙이지 않는다. 좌측 굵은 세로 바 하나가 유일한 구조 표시, 항목 앞 기호(번호·불릿) 0, 항목은 굵은 브랜드색·섹션급 크기. 하단에 표기 규약·참조 문구를 두지 않는다.
- **구획(divider)**: 진한 단색 배경 + `[N부] 제목` 한 줄만. 상단 소라벨(kicker)·장식 줄·부제 금지.
- **본문 페이지**: 상단 브랜드 띠(얇게) + 제목 + 구분선 + 쪽번호. 상단 회색 eyebrow(부 표시 소글씨)를 두지 않는다 — `[N부]` 제목 prefix 가 breadcrumb 역할.
- **자리표시자는 함수로**: 표지·목차·구획·본문 틀을 각각 헬퍼 함수(body/divider …)로 정의해 전 페이지가 같은 좌표 토큰을 지나가게 한다. `defineSlideMaster` 와 동등한 수단으로 인정한다.
- **마무리**: 마지막 부(커맨드·부록성 내용)로 끝나도 된다. 결론·"감사합니다" 페이지를 억지로 만들지 않는다.
- **부 구조**: 부록이 실질 내용이면 정식 부로 승격한다. 내용이 적은 부록 둘을 나누지 않는다(병합). 상위 지침에 해당하는 내용은 상세 나열(메모리·부록) 뒤가 아니라 지침 블록 앞쪽에 둔다 — **내용의 지위가 페이지 순서를 정한다.** 같은 축을 다루는 두 페이지는 병합한다(중복 금지).

## 2. 제목

> **원본** — 카탈로그·색인형 제목 형태(`[N부] 명사 라벨`, 문장형 제목이 결함)와 "제목만 읽기 = 색인 정합" 반전 규칙의 원본 = `skill:skill_LKS_original_visual-design` core_principles.md §10·§9. 아래는 그 규칙의 PPTX 적용(대시 부제·일련번호·포인터 prefix 금지 등 카탈로그 세칙과 색인 정합 검사)이다.

- **형식 = `[N부] 짧은 명사 라벨`.** 결론 문장(action title)을 쓰지 않는다 — 카탈로그의 제목은 색인이며, 문장형 제목은 이 덱 유형에서 결함으로 분류한다.
- **대시 부제 꼬리 금지**: `[1부] 설치 목록 — 층별 구성` 처럼 대시로 요약을 잇지 않는다. `[1부] 설치 목록` 으로 끝낸다.
- **내부 일련번호 prefix 금지**: `[2부] 메모리 1 — 코드 주석 규율` 이 아니라 `[2부] 코드 주석 규율`. 번호 체계는 번호 목록 페이지 한 곳이 담당한다.
- **포인터 prefix(`skill:`·`memory:`) 금지** — 포인터 표기는 본문 텍스트 박스·define 줄에서만.
- **제목만 읽기 검사(카탈로그판)**: 제목 연쇄가 논증일 필요는 없다. 대신 제목만 이어 읽어 목차·부 구조와 1:1로 대응하고 빠짐·중복이 없는지 검사한다.

## 3. 문체·기호·줄바꿈

> **원본** — 개조식 명사형 종결·"과압축 금지(어미 처리이지 내용 삭감 아님)"의 규칙 원본 = `skill:skill_LKS_original_visual-design` core_principles.md §1-A. 아래는 그 규칙의 PPTX 적용(표 셀 곁가지 금지·대시 금지·콜론 병기·paraSpaceAfter 문단 띄움·줄바꿈 세칙·청중 눈높이)이다.

- **종결형 = 개조식 명사형**(카드 필드·표기 대상): "대책을 마련했다" → "대책 마련" · "~하지 않는다" → "~않음". 조건 서술·수치·괄호·기존 명사형은 보존.
- **표 셀 = 핵심 하나를 담은 짧은 요약** — 짧은 단문("출력 압축 강도를 바꾸거나 압축을 끈다") 또는 명사구. **대시 뒤에 부가 조건·예외를 잇지 않는다**("전환·해제 — 인자가 비면 full 로 본다" 식 곁가지 금지). 곁가지가 정말 필요하면 캡션·별도 행으로 뺀다.
- **과압축 금지**: 명사형 압축은 어미 처리이지 내용 삭감이 아니다. 핵심과 그 주변부까지 남긴다. 출력 압축 모드(caveman) 수준의 축약은 오답.
- **설명·부수 내용에 대시(-·—) 금지** → 콜론 또는 괄호. 대시 연쇄 특히 금지.
- **항목 병기 = 콜론 스타일**: `분류 : 원본 스킬` 처럼 `항목 : 값` 으로 적어 형제 항목과 결을 맞춘다. 별도 행·별도 상자로 승격하지 않는다.
- **괄호는 짧은 보조만**: 내용이 길거나 독립 의미면 괄호를 풀어 줄바꿈한 일반 항목으로 전환한다.
- **긴 문장은 의미 단위(쉼표·연결어 뒤)에서 줄바꿈** — 한 줄에 우겨넣지 않는다.
- **줄바꿈 vs 문단바꿈 구분**: 다항목 텍스트를 `\n` 이어붙인 단일 문자열로 넣으면 줄들이 붙어 보인다. 항목 배열 + `paraSpaceAfter`(마지막 항목 제외)로 문단 간격을 렌더링한다. 검증된 현재값 10pt(카드)·7~9pt(밀도 높은 상자), 판정 기준은 수치가 아니라 "렌더에서 문단으로 보이는가".

```js
// 문단 띄움 표준형 — \n 단일 문자열 금지
s.addText(lines.map((t, i) => ({
  text: t,
  options: { breakLine: true, paraSpaceAfter: i < lines.length - 1 ? 10 : 0 },
})), { /* … */ });
```

- **청중 눈높이**: 기본 청중 = 그 도구를 처음 접하는 사람. 정확해도 전문가만 알아볼 서술이면 실패 — 일반어로 다시 쓰되 정확성 유지.
- **논지에 불필요한 낯선 인프라 용어는 정의하지 말고 뺀다**(마켓플레이스·설치 채널명 등 — "말해줘도 모르는" 용어). 정의 대상은 논지에 필요한 용어뿐이다.
- **용어 선사용 금지**: 정의 전에 등장하는 용어는 첫 사용점에서 괄호 풀이 또는 전방 포인터를 단다.
- **내부 은어·관리 표기 비노출**: 작성자만 아는 용어(예: "평문")는 일반어로, "(오버레이)"·"공통/동일" 같은 패키지 내부 구분은 독자용 텍스트에 적지 않는다.
- **가벼운 어감 회피**: "작동 시점" 대신 "적용 시점" 류의 중립 용어.

## 4. 구성물 카드 — 4필드 규격

> **원본** — 4필드 분량 캘리브레이션(트리거·원인·효과 간략 1문장 vs 기능 다항목 구현 설명)과 카드 높이=줄 수 등간격 함수(diet 금지·단일 고정 금지)의 규칙 원본 = `skill:skill_LKS_original_visual-design` core_principles.md §8·§9. 아래는 그 규칙의 PPTX 적용(계열별 라벨 규칙·define 포인터 줄·배경 필드 실사건·카드 헬퍼 구현 규격)이다.

한 구성물 = 한 페이지 = 4필드 카드. 라벨 열(좁게) + 내용 열 구조의 규격 카드를 세로로 적층한다.

| 계열 | 필드 | 라벨 규칙 |
|---|---|---|
| 절차형(스킬·워크플로) | 트리거 / 원인 / 기능 / 효과 | 2~3글자 고정 |
| 규율형(메모리·원칙) | 조건 / 행동 / 금지 / 배경 | **2글자 고정** — 라벨 칸을 줄여 내용 칸 확보 |
| 외부 패키지 | 무엇 / 왜 / 작동 / 자리 | 위 변형 |

- **분량 캘리브레이션**(가장 자주 틀리는 규칙):
  - 트리거·원인·효과(조건·금지·배경) = **간략 1문장**. "언제·왜·무슨 이득"은 짧을수록 좋다.
  - 기능(행동) = **구현을 실제로 설명하는 다항목**: `이름 : 정의` 형식 2~4개, 각 항목 명사구 1줄, 항목 간 문단 띄움(§3). "어떻게 구현했어?"에 답이 되는 수준이어야 하고, 한 줄 요약으로 뭉개면 미달이다.
  - 어절 수 상한은 적용하지 않는다 — 이 필드 캘리브레이션이 분량 기준이다.
- **define 줄**: 카드 위에 원본 포인터 한 줄(`memory:feedback_X` · `skill:…`)을 둔다. "원본 파일은 ~다" 풀어 쓰기로 대체하지 않는다.
- **배경 필드 = 실사건**: 실제 있었던 실패를 짧게 서술하고 "…재발 방지 대책 마련" 류 명사형으로 맺는다. 사건을 지어내지 않고, 실사건인데 원본(메모리 원천)에 없으면 원본에 먼저 기록한 뒤 카드에 반영한다.
- **카드 높이 = 줄 수가 정하는 규격값(§8)**: 단일 고정값(긴 필드가 잘림)도, 내용에 딱 붙인 가변값(같은 줄 수인데 페이지마다 높이가 달라짐 = diet 실패)도 아니다. **줄 수를 세어 등간격 규격에 대입한다** — 줄 수가 같으면 높이도 같고, 한 줄 늘면 어느 카드든 같은 폭으로 커진다. 줄 수 추정(§11)은 긴 필드를 안 자르기 위한 입력일 뿐, 높이를 내용에 밀착시키는 근거가 아니다.

## 5. 표

> **원본** — 시리즈형 표 규칙(동종 2개 병렬 허용·헤더 중앙·코드값 중앙/서술 좌측·볼드 위계 통일)의 원본 = `skill:skill_LKS_original_visual-design` core_principles.md §9. 아래는 그 규칙의 PPTX 적용(2단 헤더 colspan/rowspan·표 좌측선 flush·불필요 컬럼 제거·표 밖 자유 텍스트 금지 등 addTable 세부)이다.

- **헤더 = 문서 전체 기본 중앙정렬**, 본문 셀은 셀 단위 지정: 번호·등급·O/X 등 짧은 코드 값 = 중앙, 내용·파일명·서술 = 좌측.
- **구조는 진짜 구조로**: 2단 헤더가 필요한 표는 colspan/rowspan 으로 구현한다. 평면 N열로 뭉개는 것은 결함이다.
- **표 좌측선 = 제목 텍스트와 flush**(같은 x 토큰). 표가 표제보다 좌측으로 나오면 결함.
- **볼드 위계 통일**: 같은 위계 항목은 볼드 여부를 통일한다(하나만 볼드 = 결함). 한눈에 안 들어오는 구분자(등급명·tier명)는 볼드로 세운다.
- **불필요 컬럼 제거 우선**: 값이 거의 같은 컬럼은 지우고 안내 한 줄을 빈 칸에. 확보된 폭으로 축약했던 이름을 풀네임으로 되돌린다. 컬럼 폭은 내용 기준 균형.
- **표 vs 카드**: 구성물 하나의 상세 = 카드(§4). 소규모 항목 N개 묶음 = 표. 같은 페이지의 동종 묶음 둘은 **같은 형식의 표 2개**로 나란히 두고 병합하지 않는다(2×2 가 되어도 형식 통일이 우선).
- **표 밖 자유 텍스트 금지**: 표도 카드도 아닌 낱개 텍스트를 표 밑에 붙이지 않는다. 카드 상자로 통합하거나 캡션 자격(§7)이 있는지 본다.

## 6. 색·다이어그램

> **원본** — 시리즈형 색(연한 틴트 채움+브랜드 글자, 역할 박스 색 구분 금지)은 `skill:skill_LKS_original_visual-design` core_principles.md §9 및 accessibility.md §1·§4, 다이어그램 의미 정확성(각진 상자·직선 화살표·좌우 흐름·묶음 상자 밖 라벨)은 core_principles.md §5. 아래는 그 규칙의 PPTX 적용(연한 테두리·흰 글자 진배경 전용 등 슬라이드 세부)이다.

- **강조 면 = 연한 틴트 채움 + 브랜드색 글자.** 표 헤더·역할 박스·카드에 진한 브랜드색 채움과 흰 글자를 쓰지 않는다. 흰 글자는 진한 배경(표지·구획) 전용.
- **테두리는 연하게** — 틴트 면에는 그 계열의 연한 테두리. 굵은 진색 테두리 금지.
- **역할·위계 박스를 색이나 명암으로 구분하지 않는다** — 전부 동일 색, 구분은 라벨 텍스트가 한다.
- **변형 대비가 필요한 곳만 색을 가른다**(A = 브랜드 계열 / B = 액센트 계열 같은 강한 대비). 근백색 2종처럼 색으로 구분이 안 되는 조합은 결함.
- **다이어그램 = 각진 상자 + 직선 화살표, 좌우 흐름.** 원형·곡선·삼각·세로 배치를 쓰지 않는다. 설명 대화에서 쓴 비유 명칭을 자료에 기재하지 않는다. 화살표 라벨은 화살표 위/아래 소글씨로 나눠 단다(한 줄에 몰지 않는다).
- **묶음 상자(대상 여럿을 하나로 감싸는 점선 등)는 대상들을 상하좌우 동일 여백으로 감싼다.** 묶음 라벨은 상자 안이 아니라 **상자 밖(위)**에 둔다 — 라벨을 안에 넣어 한쪽 여백만 키우면 네 변이 어긋나 '묶음'으로 깔끔히 읽히지 않는다.

## 7. 변형 표기·캡션·출처·수치

- **변형(에디션) 표기는 제목 뒤 괄호 하나** `제목 (변형명)`으로만. 본문 2분할 상자·하단 참고 줄·"공통/동일" 부수 설명은 전부 두지 않는다. 변형 간 실제 차이 설명이 필요하면 그 차이를 다루는 전용 페이지(설치 목록 등)에 둔다.
- **참고 캡션(하단 회색) 최소화**: 외부 원저작 출처 표기와, 없으면 독자가 길을 잃는 안내에만. 매 페이지에 두지 않는다. 목차·자체 제작물에 참조·출처를 창작하지 않는다(출처 규율 원본 = 헌법 「출처 표기」 절).
- **인용 수치는 조회 시점 명기**: "GitHub 스타 26.6만 (2026.08 기준)". 라이브 원천으로 검증하고, 직접 조회가 막히면 대체 경로로 교차 확인해 기록한다.
- **원하는 수치가 없으면** 지어내지 않고 문헌상 확정 수치로 대체하며 그 사실을 기록한다.

## 8. 시리즈 균일성 (이 덱 유형의 제1 시각 규범)

> **원본** — 레이아웃 의도 축(논증형 리듬 변주 vs 카탈로그·시리즈형 균일성)과 그 반전 규칙(동종 규격 반복이 규범·이탈이 결함·카드 높이 줄 수 등간격·요소 유형별 단일 크기)의 원본 = `skill:skill_LKS_original_visual-design` core_principles.md §9. 아래는 그 규칙의 PPTX 적용(줄 수 등간격 산정식·렌더 줄 pitch 정합·칸 간격 고정 등 카탈로그 구현 세칙)이다.

**균일성이 제1 우선이다.** 카탈로그형 덱에서 가장 중요한 것은 개별 페이지의 멋이 아니라 **전체가 한 문건처럼 읽히는 안정된 규칙성**이다. 포맷 선택이 균일성과 상충하면 (같은 계열 안에서는) 균일성이 이긴다.

- **동종 시리즈 페이지는 같은 규격(같은 헬퍼·같은 필드·같은 기하)을 유지한다.** 한 페이지만 다른 포맷으로 이탈하면 내용이 좋아도 그 페이지는 배제 대상이다.
- **동종 요소의 라벨 폭·상자 높이 산정식·시작 y·테두리를 통일한다.** 한 페이지만 어긋나면(예: 높이 0.94 vs 1.0) 결함.
- **상자 높이 = 줄 수의 등간격 함수.** 최소 줄 수를 바닥으로, 한 줄 늘 때마다 **동일 증가폭**으로 커진다. 내용에 딱 맞춰 조이면(diet) 같은 줄 수인데 페이지마다 높이가 달라져 균일성이 깨진다(§4).
- **내부 여백(밀도)을 통일한다.** 줄 수와 무관하게 상자 위·아래 여백이 같아야 한다 — 1줄 카드를 부풀리지도, 다줄 카드를 조이지도 않는다. 이를 위해 높이 산정의 줄당 값은 **실제 렌더 줄 pitch 에 맞춘다**(추정 pitch 가 실제보다 작으면 다줄이 빡빡해지고, 최소 줄 수를 억지로 올리면 1줄이 부푼다).
- **칸(상자) 간격을 고정 통일한다.** 카드 사이 간격은 전 페이지 같은 값. 남는 세로 공간을 간격에 분배하지 않는다 — 그러면 페이지마다 간격이 달라진다. 위로 정렬·간격 고정, 남는 공간은 페이지 하단에 둔다(성긴 페이지의 하단 여백은 정상이며 균일성보다 후순위다).
- **형제 요소는 계열이 달라도 치수를 맞춘다.** 같은 역할의 요소는 서로 다른 부(部)에 있어도 동일 치수 — 예: 스킬 파일명(포인터) 박스 ↔ 메모리 파일명 박스. 하나가 1줄로 줄면 다른 것도 같이 줄인다.
- **글자 크기는 요소 유형별로 덱 전체 한 크기다.** 제목·라벨·본문은 서로 크기가 달라도, **같은 유형끼리는 전 페이지에서 동일**하다(§9 표의 각 행 = 그 요소의 단일 크기). 같은 유형이 페이지마다 다르면 결함. (표 본문의 바닥선 자동 축소만 문서화된 예외 — §9.)
- **줄바꿈도 사양이다 — 우연한 감김을 방치하지 않는다.** 한 줄로 의도한 문구가 길어져 2줄로 감기면 줄 수 기반 규격이 흔들린다. 문구를 다듬어 1줄로 줄이거나, 못 줄이는 핵심이면 의미 단위로 **잘 나눈 2줄**로 배치한다 — 어중간하게 흘러넘친 2줄로 두지 않는다.
- 단조로움 우려로 규격을 흩뜨리지 않는다 — 카탈로그의 리듬은 부(部) 구획과 페이지 유형(카드/표/도식)의 교대가 만들고, 같은 계열 안에서는 균일함이 값이다.

## 9. 타이포 스케일·자동 맞춤 (카탈로그형 전용)

기존 `content_rules.md` §7 발표용 스케일(본문 27pt 하한)은 배포·정독용 고밀도 카탈로그에 맞지 않는다. 검증된 스케일(13.333″ 캔버스):

| 요소 | 크기 |
|---|---|
| 제목 | 31pt bold |
| 구획·목차 항목 | 29pt bold |
| 카드 라벨 | 20pt bold |
| 카드 본문·표 본문 | 13~15pt (기본 14) |
| 캡션·출처·쪽번호 | 15pt |
| 다이어그램 라벨 | 10~16pt |

- **요소 유형별 단일 크기가 원칙(§8).** 위 표의 각 크기는 그 요소가 **전 페이지에서 갖는 하나의 크기**다 — 카드 라벨·카드 본문은 페이지마다 바뀌지 않는다(제목·라벨·본문끼리는 서로 달라도, 같은 유형끼리는 전 덱 동일). 같은 유형이 페이지마다 다르면 결함.
- **자동 축소 허용(바닥선 안에서) = 단일 크기 원칙의 유일한 예외**: **표 본문에 한해** 꼬리말 선을 넘길 것 같으면 글자 크기 → 행 높이 순으로 한 단계씩 줄여 맞춘다(그래서 표마다 크기가 달라질 수 있다). **하한 13pt** — 그 아래로 내려야 맞는다면 내용을 덜거나 표를 나눈다. `fit`/`autoFit` 옵션 금지는 유지. 카드는 이 축소 대상이 아니다(높이·줄 수로 흡수 — §4·§8).
- 1구성물 = 1페이지 규격이므로 "넘치면 페이지를 나눈다"보다 필드 문구 압축·곁가지 제거가 먼저다.

## 10. 피드백 라운드 운영 (검수 루프)

- **verbatim 대장**: 사용자 피드백은 요약·가공 없이 원문 그대로 시간순 기록하고 각 항목에 처리 결과 포인터를 단다.
- **취합 후 일괄 실행**: 페이지별 피드백이 순차로 오는 라운드에서는 전부 모일 때까지 실행하지 않고 저장·검토만 한다. 개별 건 즉시 실행 명시(GO)만 예외.
- **실행 전 검토·질의**: 배치 실행 전 전체를 검토해 사용자 결정이 필요한 항목만 질의하고 나머지는 질의 없이 일괄 실행한다.
- **파급 규칙**: 한 곳에 내린 표기 지시(용어 교체·정렬·형식)는 문서 전체 동일 항목에 전수 적용한다. "그 페이지만 고침"은 미완.
- **유사 개소 확장**: 언급 안 된 동종 개소도 같은 판단이 서면 함께 수정하되, 이견이 있으면 수정 전에 평문으로 말한다.
- **답안지 벤치마킹**: 사용자가 직접 작성·수정한 페이지는 불변 기준(답안지)이다. 수정하지 않는다. 나머지를 재작성할 때는 (원본 문건 + 답안지) 쌍을 주고 그 증류 관계를 파악해 동일 변환을 적용하는 방식으로 위임한다.
- **선택 신호 > 서술 지시**: 사용자가 대안 중 하나를 고른 기록(체리픽 픽)은 가장 강한 취향 데이터다. 픽과 서술 지시가 어긋나 보이면 최신 결정을 따르되 어긋남을 표면화한다.
- **줄바꿈도 사양이다**: 사용자가 줄바꿈·정렬 위치까지 지정한 지시는 그 위치 자체가 요구 사양 — 반영 여부를 렌더 기준으로 확인한다.
- **매 배치 후 게이트 재통과**: 문구만 고쳤어도 게이트1 FAIL 0 / WARN 0 을 재확인한 뒤 전달한다.

## 11. 빌드 자체 검사 (게이트1 사각 보완)

게이트1은 표 높이를 `rowH × 행수`로만 추정하므로 셀 줄바꿈으로 커진 표와 뒤 요소의 겹침을 못 잡는다. 카탈로그형은 표·카드 적층이라 이 사각에 자주 걸리므로 **빌드 스크립트가 스스로 검사한다**:

- 글자 폭 실측 추정(동아시아 전각 1 · 반각 0.5)으로 표·카드의 실제 하단을 계산하고, 슬라이드별 하단 누적값(`__bottom`)으로 다음 요소를 그 아래로만 놓는다.
- 요소가 앞 요소 위로 밀리거나 바닥선(꼬리말 선)을 넘으면 모아서 **빌드를 exit 1 로 세운다** — 조용히 내보내지 않는다.
- 구현 참고형은 이 패키지로 저작된 덱 소스(`deck.js`)의 `claimBelow`/`claim`/`estLines`/`tableHeight`/`memCards`/`skillCards`/`estCardLines`. 카드 등간격·균일 여백은 `memCards`·`skillCards` 가 공유하는 `높이 = 줄 수 × 줄당값 + 상하여백` 규격과 렌더 pitch 에 맞춘 줄당값으로 구현한다(§4·§8).

## 13. 배포 전 점검표 (content_rules §11 의 카탈로그판)

| 확인 | 위반 시 조치 |
|---|---|
| 제목이 `[N부] 명사 라벨`인가 (문장형·대시 꼬리·일련번호·포인터 prefix 없음) | 제목 재작성 |
| 제목 연쇄가 목차·부 구조와 1:1 대응하는가 | 색인 정합 수정 |
| 동종 시리즈에 규격 이탈 페이지가 없는가 (필드·기하·헬퍼 동일) | 규격으로 재작성 |
| 카드 높이가 줄 수 등간격 규격인가 (같은 줄 수 = 같은 높이 · diet 없음) | 등간격 산정식으로 교체 (§4·§8) |
| 카드 상하 여백·칸 간격이 전 페이지 동일한가 (1줄 부풀음·다줄 조임 없음) | 여백 통일·줄당 값 실제 pitch 정합 |
| 형제 요소(파일명 박스 등)가 계열이 달라도 치수가 일치하는가 | 동일 치수로 통일 |
| 요소 유형별 글자 크기가 전 페이지 단일한가 (표 본문 자동축소만 예외) | 유형별 단일 크기로 통일 (§9) |
| 한 줄 의도가 2줄로 흘러넘친 문구가 없는가 | 1줄로 압축 또는 잘 나눈 2줄로 재배치 |
| 묶음 상자가 상하좌우 동일 여백이고 라벨이 상자 밖인가 | 여백 균등화·라벨 밖으로 (§6) |
| 카드 필드 분량: 간략 3필드 1문장 · 기능(행동) 다항목 구현 설명인가 | 캘리브레이션 재조정 |
