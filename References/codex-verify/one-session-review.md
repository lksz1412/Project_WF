# 접속 한 번에 확인할 순서

목표는 같은 캐릭터의 한 접속에서 화면을 차례로 확인하고, 고칠 자리를 한 기록에 모으는 것이다. 화면·프레임·오류 기록, 초기 설정 확인과 비교는 Codex가 맡는다. **4K 퀘스트 글자 크기는 실제 화면을 평소 거리에서 읽어 본 뒤 판단한다.** 시험은 게임 기본 창의 현재 크기로 시작한다.

## 접속 직전

1. [로컬 0.1.4 시험 결과](../../Codex/results/PHASE_29.5_local-runtime-trial_RESULT.md)와 [승인한 채팅 목업](../../outputs/devil-forever-mobile-orc-rail.html)을 기준으로 본다. 기본 시험은 PitBull4형 `DevilForever-0.1.4.zip`, 유닛 프레임까지 비교할 때는 `DevilForever-0.1.4-one-session.zip`을 쓴다. [ZIP 확인 기록](../../Review/0.1.4/trial-receipt.json)에서 해시를 대조한다. [기능 트리](../../Collection/data/feature-map.md)에서 설정 담당을 확인하고 [상태별 목업](../codex-appearance/24/ux/index.md)에서 시전·파티 배치를 본다. 시작 전에 `AddOns`와 `WTF`를 각각 복사해 목록과 해시를 확인한다.
2. 캐릭터 선택 화면에서 구버전 허용 상태와 Phase 1의 네 애드온 표시를 확인한다. 성능 비교를 하는 날은 측정 도구만 켠 채 입장해 게임 기본 상태를 먼저 기록한다. 모음집으로 바꿀 때는 같은 접속에서 애드온 설정을 바꾸고 화면을 다시 불러온다. 유닛 프레임은 처음에 **PitBull4만 켠다**. `ForeverUnitFrames`, `DevilForever_Castbars`, `DevilForever_FUFDefaults`는 비교 차례에 켠다.
3. 기본 창 상태·퀘스트·전투·파티를 확인할 수 있는 같은 캐릭터로 한 번 입장한다. 초기 채팅창 생성이나 유닛 프레임 교체 때 클라이언트가 요구하면 접속 상태에서 `/reload`로 화면만 다시 불러온다.

## 같은 접속에서 확인

| 순서 | 상태와 기록 | 그 자리에서 확인할 것 |
|---|---|---|
| 1 | `/dfcheck start`, `/dfappearance` | 빌드와 Interface, 물리 해상도·배율, 활성 프리셋, 메뉴·가방·대기열 클릭 범위, 상태띠, 미니맵 시계와 초기 오류 수. 그래픽 설정의 3862×2160 표시와 UI가 실제로 쓰는 물리 크기를 대조한다. 행동 단축바의 빈 슬롯 외곽과 스킬 배정 슬롯 안쪽을 [원배율 목업](../codex-appearance/24/ux/resolution-native-comparison.png)과 비교한다. |
| 2 | `/dfcheck quest` | 게임 기본 목표 창에서 실제 한국어 제목과 목표를 4K의 평소 거리에서 읽어 본다. 긴 줄과 여러 퀘스트가 함께 보일 때도 확인한다. 목표창과 우두머리·미터기·단축바의 위치는 [가독성 목업](../codex-appearance/24/ux/uhd-devil-objectives.png)과 대조한다. |
| 3 | `/dfcheck chat` | 공개·그룹·시스템 역할, 한글 조합·입력·스크롤·탭, 기존 창의 배치와 메시지 범위 유지. 도움말이 단축바 및 입력을 가리는지 확인 |
| 4 | `/dfdetails status`, `/dfcheck petabsent`, `/dfcheck pet`, `/dfcheck combat` | 전투 밖에서 기존 Details 창 두 개가 준비되면 `/dfdetails apply`로 위치를 적용한다. 현재 위치를 다시 쓸 때는 화면을 다시 불러오기 전에 `/dfdetails restore`를 실행한다. 소환 전후를 각각 기록해 버튼과 전용 테두리가 함께 움직이는지 확인한다. [소환수 기술창 표시 비교](../codex-appearance/24/racial-appearance/pet-visibility.png)와 대조한다. 전투에서는 이름표·시전·추천·Cooldown Manager·Details와 보호 프레임 차단을 확인한다. |
| 5 | `/dfcheck party`, 가능한 경우 `/dfcheck raid` | 파티 대상·소환수 줄과 공격대 Grid2·우두머리 위치. 조건이 없으면 그 자리에서 보류로 기록. 파티와 공격대는 별개로 분류 |
| 6 | `/dfcheck theme` | 전투에서 나온 뒤 `/dfp theme <이름>`으로 [테마 목록](../codex-appearance/24/racial-appearance/index.md)의 13종을 한 번씩 전환하고 시작 테마로 돌아온다. [승인한 채팅 목업](../../outputs/devil-forever-mobile-orc-rail.html)을 기준으로 단축바와 채팅틀의 연결, 테두리와 모서리, 셋째 창 오른쪽 아래 문양, 데빌의 흑회색 배경을 비교한다. 밝은 곳에서 채팅 첫 줄과 마지막 줄을 함께 확인한다. |
| 7 | 필요 시 `/dfcheck comparison` | 같은 접속에서 PitBull4를 끄고 Forever Unit Frames와 전용 두 애드온을 켠 뒤 UI만 재로딩한다. 두 변형이 동시에 불러와졌는지 먼저 확인한다. 전투 밖에서 20초가 지나면 `/fuf`의 프로필 메뉴에서 현재 프로필을 해당 해상도의 `DF Compare fhd`, `DF Compare qhd`, `DF Compare uhd`로 복제해 선택한다. 이름에 맞는 `/dffuf layout <해상도>`를 실행한다. `sent-unverified`는 설정 전송을 뜻하므로 좌표·자원·시전바를 실제 화면에서 대조한다. 비교 뒤 원래 프로필을 선택한다 |
| 8 | `/dfcheck report`, 필요한 상태별 `/dfcheck show <상태>` | 모인 관측·누락 상태·실화면의 좌표를 확인한다. 오류와 겹침을 기능별로 묶고, 같은 원인의 수정은 한 번에 정리한다 |

`/dfcheck`는 화면 밑에서부터 올라가는 게임 좌표를 좌상단 기준 물리 픽셀로 환산한다. 읽을 수 없는 프레임은 `absent` 또는 `no bounds`다. 창 하나의 캡처는 통과 판정이 아니다. 기록은 새 시험용 저장 변수 `DevilForever_UIReviewDB`에 들어간다. 채팅 메시지·입력·캐릭터명·계정 정보는 읽지 않는다. 실제 게임을 켜기 전에는 모든 상태가 미검증이다.

게임 기본과 모음집의 프레임 시간은 [측정 도구와 비교 순서](../../Review/0.1.4/evidence/frame-time.md)로 기록한다. 유닛 프레임의 표시 정확도는 [비교할 기능과 장면](../../Codex/results/Step%2069%20%E2%80%94%20실제%20게임에서%20확인할%20성능%20비교.md)을 따른다.

## 다음 판에서 추가로 확인할 항목

위 0.1.4 시험판의 기준 관측과 다음 판의 결과를 구분해 적는다. 아래는 Grid2·PitBull4·SexyMap 기본값 수정과 배치가 함께 들어간 후보에서 실행한다.

| 항목 | 게임에서 할 일 | 완료 기준 |
|---|---|---|
| 설정 저장·복원 | 전투 밖에서 현재 테마 또는 Core 편집값을 기록한다. `/dfp save check30` → `/dfp go`로 저장을 마치고 `/dfp list` 또는 상태에서 확인한다. 테마나 같은 편집값을 바꾼 뒤 `/dfp restore check30` → `/dfp go`를 실행한다. | 다시 불러온 뒤 처음 기록한 값으로 돌아오고 상태에 복원 결과가 남는다. 기존 저장본 이름을 쓰지 않는다. |
| 요청 취소 | 값을 한 번 더 바꾸고 `/dfp restore check30` → `/dfp cancel`을 실행한다. `/dfp status`를 본 뒤 `/dfp go`를 눌러 확인한다. | 대기 요청이 사라지고 화면을 다시 불러오거나 값을 되돌리는 일이 없다. 시험이 끝나면 저장본으로 원래 값에 복귀한다. |
| 테마 번호 | 전투 밖에서 `/dfp theme`으로 목록을 열고 `/dfp theme 0`부터 `/dfp theme 12`까지 전환한다. | 0은 기본 데빌, 1은 얼라이언스, 2는 호드다. 선택한 테마는 즉시 보이고 다시 불러온 뒤에도 유지된다. |
| 프리셋으로 되돌리기 | 저장한 시험 상태에서 편집값 하나를 바꾸고 `/dfp preset fhd`, `qhd`, `uhd` 중 확인할 프리셋을 선택한다. 애드온 값 대기가 표시되면 `/dfp go`를 실행한다. | 지정한 프리셋과 대상 편집의 초기값을 대조한다. 실행 가능한 해상도별로 기록하고, 끝나면 처음 사용한 프리셋과 시험 전 편집값을 복원한다. |
| 게임 기본 쿨다운 관리자 | 화면 중앙 강조와 소리를 켜고 끈 설정을 각각 기록한다. 해당 알림을 지원하는 기술을 사용해 사용 가능·재사용 종료 등의 같은 조건을 비교한다. | 중앙 강조, 소리, 두 옵션의 실제 적용 여부를 따로 기록한다. 눈에 띄는 표시가 Hekili 또는 단축바 강조인지도 확인한다. |
| 파티·적 소환수 | 다섯 명 파티에서 Grid2만 보이는지, 해제 가능한 약화 효과, 사거리 밖, 들어오는 치유의 세 조건을 각각 만든다. 소환수가 있는 적과 없는 적을 번갈아 대상으로 잡는다. | 파티 프레임이 두 벌 뜨지 않는다. Grid2의 테두리, 흐려짐과 예측 치유가 조건에 맞고 적 소환수는 대상 왼쪽에 조건부로 표시된다. 대상·주시의 기존 파생 프레임 자리도 그대로인지 대조한다. |
| 주술사 토템 | 주술사에서 토템을 놓고 남은 시간의 변화를 본다. 토템이 사라지면 표시가 따라오는지 확인한다. 다른 직업은 캐릭터 확인이 가능한 때 따로 기록한다. | 플레이어 왼쪽에서 시간이 읽히며 기존 오라와 Dominos 토템 기술바가 겹치지 않는다. 다른 직업에 새 토템 막대가 생기지 않아야 한다. |
| 기존 SexyMap 위치·크기 | SexyMap을 원래 쓰던 같은 캐릭터와 같은 프로필에서 처음 위치와 크기를 기록한다. 수정판 로그인·UI 다시 불러오기 뒤 같은 해상도·배율에서 대조한다. | 기존 프로필의 위치·크기가 보존된다. 좌표·배율 키 일부가 비어 있는 프로필도 원래 쓰던 자리에서 확인한다. |
