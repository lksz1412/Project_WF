# Step 67 — 행동 추천과 전투 미터기

2026-11-19 · Phase 29.4 · 비교 목록 2–3

## 수행

0.1.2 기본 ZIP에서 Hekili의 추천 스케줄러와 Details의 표시 갱신 함수를 읽어 Lua 5.1 대역으로 실행했다. 추천 계산 전체와 전투 기록 파싱은 실행 대역 밖이다. 게임 기본 쿨다운 관리자는 상태 표시를 담당하므로 추천 엔진과 기능을 따로 판단한다.

## 결과

| 동작 | 같은 10초 대역의 관측 | 판단 |
|---|---|---|
| Hekili 추천 스케줄러 | 프레임 콜백 600회 입력. 추천 진입은 꺼짐 0회, 비전투에 적 대상 없음 7회, 적 대상 또는 전투 상태 20회. 대상 변경 요청을 전달하면 다음 호출이 1.53초에서 0.58초로 당겨짐 | 프레임마다 추천을 계산한다고 볼 수 없다. 설정을 끈 상태의 조회 0회는 보존할 점이다. 실제 추천 엔진에서 다음 계산의 입력과 결과를 비교한 뒤 별도 최적화를 고른다 |
| Details 두 데이터 창 | 기본 0.20초에서 100회, 0.50초에서 40회, 빠른 스트리머 설정 0.016초에서 1,250회 표시 갱신 함수 진입 | 먼저 갱신 간격으로 비용을 낮출 수 있다. 0.50초는 가독성과 위협 반응을 실제로 맞춰 볼 후보 값이다 |
| Details의 사용 중인 공유 전투 자료 | 공유 갱신 표시가 켜진 첫 틱에 두 창 모두 갱신 요청을 받고, 그 뒤 표시가 꺼졌다 | 창 하나를 처리할 때 즉시 공유 표시를 지우는 식으로 두 순회를 합치면 두 번째 창이 같은 변경을 놓칠 수 있다. 시간에 따라 바뀌는 값도 있으므로 변경 표시 하나로 갱신을 막지 않는다 |

Hekili는 구독한 화면만 후보를 계산하고 다음 결과를 따로 준비해 공개한다. Details는 전투 기록에서 전투 자료의 변경을 표시한다. 갱신 간격을 늘린 시험은 미터기 창 진입 횟수에 해당한다. 전투 기록 처리나 Tiny Threat의 갱신 자체를 줄였다는 근거는 없다. [시험 입력과 결과](../../_local_only/perf-review-29.4/action-and-meter.json)

기존 Details와 Tiny Threat를 우선 유지한다. Skada의 포에버용 로드 목록과 반복 타이머를 확인했다. 같은 두 창과 같은 데이터 조건의 실행 비교에 쓰되 숫자만 다른 기본 갱신 설정으로 전체 속도를 판단하지 않는다. [Skada 로드 목록](../../Collection/upstream/skada-v2.6.7/Skada/Skada_Forever.toc)

## 확인 범위

Hekili Driver와 Output 전문, Sim Core 1488–1607행, 자체 Hekili 기본값 전문을 확인했다. Details는 gears 190–222행, control 1831–1952행, class_instance 400–493행, profiles의 갱신 값, 실제 전투 자료 변경 표식을 확인했다. 시험 출력에서 추천 5조건과 미터기 3조건의 확인문을 통과했다. 표시 갱신 요청은 대역의 호출 수이며 실제 표시 비용이나 전투 기록 처리 시간은 별도다.
