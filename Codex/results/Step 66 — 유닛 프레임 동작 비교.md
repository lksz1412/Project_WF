# Step 66 — 유닛 프레임 동작 비교

2026-11-19 · Phase 29.4 · 비교 목록 1

0.1.2 ZIP의 실제 PitBull4와 Forever Unit Frames를 Lua 5.1의 게임 대역에 연결했다. 같은 대상의 대상 프레임 하나에 10초 동안 0.01초 간격으로 입력했다. 처음 화면을 만든 비용은 제외했다. 서비스 이벤트와 위젯은 대역으로 뒀다.

| 상태 | PitBull4 전체 갱신 요청 | FUF 전체 갱신 요청 |
|---|---:|---:|
| 기본 유닛으로 연결할 수 없는 공개 대상 유지 | 66 | 50 |
| 기본 유닛으로 연결할 수 있는 공개 대상 유지 | 0 | 50 |
| 기본 유닛으로 연결할 수 있는 공개 대상 한 번 교체 | 1 | 50 |
| 프레임 자체 숨김 | 0 | 0 |
| 프레임은 표시 상태이고 부모만 숨김 | 0 | 50 |

FUF의 전체 갱신 요청 50회 중 오라 컨테이너 호출은 자체 간격 제한 때문에 17회였다. PitBull4는 공개 식별값을 파티 같은 기본 유닛으로 연결할 수 있으면 전체 갱신을 피할 수 있다. 기본 유닛의 체력·자원 이벤트를 함께 쓰는 방식이다. 동일한 대상도 체력과 자원이 바뀔 수 있어 식별값 비교만으로 폴링을 없애면 표시를 놓칠 수 있다.

읽을 수 없는 식별값이 바뀌는 대역에서는 PitBull4가 명시적인 대상 교체 이벤트를 받았을 때 갱신했다. 이 시험에서 PitBull4 체력·자원 모듈의 자체 이벤트를 대체했으므로 실제 게임에서 수치가 멈춘다고 판정할 근거는 없다.

기본은 PitBull4를 유지한다. FUF는 비교판으로 남기며 부모가 가려졌을 때 갱신 생략과 다시 보일 때 즉시 갱신을 함께 검토한다. 실제 프레임이 보이는지 확인하는 방식은 PitBull4와 FUF의 개별 이벤트 경로에 이미 있다. 전체 프레임 시간 우열은 같은 유닛, 요소, 제한 상태에서 확인해야 한다.

0.1.2 ZIP의 입력과 로컬 사본을 전부 바이트 대조했다. 실행은 16건 통과했다. 읽은 파일과 줄 범위, 어떤 요소가 실제로 실행됐고 어디부터 대역인지, 각 상태의 관측값은 [작업 기록](../../_local_only/perf-review-29.4/unitframes/work_log.md)에 있다. [원본 실행 결과](../../_local_only/perf-review-29.4/unitframes/run-adjxhnkp/result.json)
