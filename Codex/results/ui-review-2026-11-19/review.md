# 화면별 설계 재검토

2026-11-19 · 로컬 설계 검토 완료 · [독립 확인 기록](verification.md)

현재 하단의 기능 구획과 기존 애드온 분담은 유지할 근거가 있다. 먼저 손볼 근거가 뚜렷한 곳은 **새 채팅 목업과 ZIP의 차이**, **실제 글과 버튼이 빠진 상태 예시**, **경험치 가로 공간안과 설치본의 세로 표시 차이**다. 실제 게임에서 겹치거나 읽기 어렵다고 새로 관측한 항목은 없다.

## 판단 기준과 확인 수준

- 사용자 승인 기준: “실제 화면에서 쓰는 그림과 크기”, “글이 길거나 여러 줄 쌓였을 때”, “같은 해상도와 배율”. 장식이 글·버튼을 침범하면 장식을 줄인다. 모서리의 둥근 정도와 두께 차이 자체는 결함으로 세지 않는다. `Codex/docs/ui-design-criteria.md:7–15`.
- **확정**: 직접 읽은 문구·코드, 열어 본 목업의 구성, 총괄의 원시 실행 결과 파일에서 확인한 값. 목업과 실행 결과의 출처를 각각 표시한다.
- **근거 미발견**: 읽은 범위에서 결정을 확정할 원문이나 특정 상태의 증거를 찾지 못한 경우. 기능이 없다는 뜻으로 넓히지 않는다.
- **추정**: 작업 분석자의 사용성 판단과 다음 작업 제안. 사용자 선택으로 적지 않는다.
- **미검증**: 현재 ZIP을 게임에서 불러온 뒤의 글자·클릭·가시성·전투 동작. 이전 접속 기록과 이번 새 ZIP의 결과를 합치지 않는다.

총괄이 생성한 `_local_only/ui-review-2026-11-19/probe.json`을 직접 읽었다. 세 ZIP의 파일 내용 해시는 검토 기록과 일치한다. 이전 목업 렌더 입력 18개는 기본판·한 접속 비교판에서 같고, Forever Unit Frames(FUF) 단독판은 의도상 PitBull4 코드 한 개가 빠진 17개다. 이는 해당 입력의 동일성 근거이며 화면 전체의 실사용 통과를 뜻하지 않는다. `probe.json:590–801`, `Codex/results/audit-installer/reviewed-packages.json`의 `packages` 세 항목. 이하 `probe.json`은 이 실행 파일, `feature-positions.json`은 `References/codex-appearance/24/feature-positions.json`, `ux/index.md`는 같은 24 폴더의 `ux/index.md`를 가리킨다. `evidence.json`은 이 보고와 같은 폴더의 총괄 증거 파일이다.

## 세 해상도와 별도 네 번째 사양

아래 수치는 화면 왼쪽 위를 원점으로 하는 물리 픽셀이다. 해상도 이름 FHD·QHD·UHD는 각각 1920×1080·2560×1440·3840×2160이며, 4K는 여기서 UHD를 뜻한다. 같은 표의 숫자를 Windows 배율이나 게임 화면 단위로 바로 해석하지 않는다.

| 항목 | 1920×1080 | 2560×1440 | 3840×2160 |
|---|---:|---:|---:|
| 행동 버튼 목표 외곽 | 48 | 56 | 80 |
| 프리셋 아이콘 값 | 36 | 44 | 64 |
| 채팅 글자 | 18 | 22 | 28 |
| 단축키 글자 | 16 | 19 | 24 |
| 사각 미니맵 | 192×192 | 224×224 | 304×304 |
| 퀘스트 제목·목표의 목업 값 | 24·20 | 28·24 | 36·30 |
| 메뉴 첫 버튼의 계산 외곽 | 17×21 | 20×25 | 29×36 |

근거: `probe.json`의 `profiles.{fhd,qhd,uhd}.button_and_text_metrics`, `toolbar_buttons.menu[0]`, `quest_heading_body`; `Collection/data/feature-map.md:31`; `References/codex-appearance/24/ux/index.md:17–19,33`. Onyx의 외곽과 스킬 아이콘 안쪽은 서로 다른 값이다. 기존 기록의 Masque 계산 안쪽 43.89·51.20·73.14픽셀과 프리셋 아이콘 값의 차이도 접속 관측 대상이다. 목업만 보고 같은 크기라고 결론내리지 않는다.

**확정**: 사용자 대장 R107은 “FHD, QHD, UHD 세가지 겉보기”라고 기록한다. 반면 이전 접속 결과에는 사용자가 “4종”을 언급했으나 추가 프리셋과 4K 단독 여부가 미정이라고 적혀 있다. 세 가지가 실물에 있다는 이유로 네 가지 요청을 완료 처리하지 않는다. `Claude/results/REQUEST_LEDGER_phase8.md:20`, `References/codex-verify/phase1/result.md:48`, `Codex/results/Step 48 — 검토한 ZIP과 기능 기준 확정.md:21`.

**근거 미발견**: 별도 네 번째 해상도의 확정 이름·가로세로 크기·배율. 3862×2160은 과거 그래픽 설정의 렌더링 크기이고, 같은 기록은 감지한 모니터 3840×2160과 화면 캡처 2560×1440을 따로 적는다. 이를 네 번째 프리셋의 사양으로 바꾸지 않는다. `References/codex-verify/phase1/result.md:11,53–54`.

**확정·한계**: 총괄의 실제 ZIP Lua 시험은 3440×1440을 QHD, 3862×2160을 4K, 1920×1200을 FHD로 고른다. 선택된 기존 프리셋이 그 화면 폭에 맞춰 새로 배치된다는 뜻은 아니다. `_local_only/ui-review-2026-11-19/live-check-gaps.json:3–40`의 `presetSelection`.

**작은 다음 작업**: 세 지원 해상도의 원배율 검토를 먼저 끝내고, 네 번째 사양은 기존 열린 항목으로 보존한다. 자동으로 골라진 프리셋과 실제 지원 해상도를 구별해 기록한다.

## 단축바와 메뉴

**유지 가능**: 중앙 8×3, 긴 윗줄, 좌우 보조 바와 그 아래 메뉴·가방·대기열 구획. 빈 슬롯과 기술 배정 상태를 나누고, 태세·토템·소환수의 기존 표시 조건을 유지하는 방향. `References/codex-appearance/24/mockup-index.md:33–38`, `References/codex-appearance/3/report.md:3–7,48–50`.

**손볼 근거가 있음**: 열어 본 FHD 전투 목업과 원배율 비교판은 빈 슬롯이며, 메뉴·가방·대기열은 자리 표시다. 실제 스킬 그림 위의 단축키·잔여 시간·충전 수가 함께 보이는 예시는 아니다. FHD 메뉴 첫 버튼 계산 폭 17픽셀은 조밀하므로 실제 그림의 구별과 클릭을 우선 확인할 이유가 있다. 크기만으로 클릭 실패를 확정하지 않는다. `mockup-index.md:34,38,50`, `probe.json:401–524`.

**실제 접속에서만 관측 가능**: 실제 슬롯 안쪽 크기, 키·쿨다운 숫자의 충돌, 클릭 범위, 한 직업에서 태세·토템·소환수·빙의가 함께 나타나는 상태. `References/codex-appearance/3/report.md:5,13,54–56`.

**작은 다음 작업**: 각 해상도에서 긴 키 조합과 시간 숫자를 같은 슬롯에 얹은 원배율 예시 한 개씩 준비한다. 게임에서는 같은 슬롯의 빈 상태·배정 상태·재사용 대기를 이어서 기록한다. 장식이 침범할 때 먼저 장식을 줄인다.

## 미니맵

**유지 가능**: 단축바 오른쪽의 사각 미니맵과 192·224·304픽셀의 개별 크기. 시계는 상태띠만 사용한다는 기존 선택. `Collection/data/feature-map.md:31`, `Claude/results/REQUEST_LEDGER_phase25.md:7`.

**손볼 근거가 있음**: 열어 본 원배율 비교판에는 실제 지역 타일·추적 아이콘·지역명이 없다. 사각형의 바깥 틀이 들어간 사실만으로 내부 지도를 읽고 누를 수 있다고 판단할 수 없다. `References/codex-appearance/24/mockup-index.md:50`, `References/codex-appearance/5/report.md:7,11`.

**실제 접속에서만 관측 가능**: 밝은 지형의 대비, 지역명 길이, 아이콘 밀집, 확대·회전·클릭, 기존 SexyMap 프로필 유지, 미니맵 시계 숨김. 기본 사각형과 기존 사용자 테두리는 별도 상태다. `References/codex-appearance/5/report.md:5–11`.

**작은 다음 작업**: 실제 지역명이 긴 곳과 추적 아이콘이 많은 곳을 한 번의 접속에 포함한다. 단축바와 같은 배율에서 지도 내부와 경계의 식별을 함께 기록한다.

## 상태띠

**유지 가능**: 골드·가방·내구도·시계·지연·초당 프레임 여섯 항목을 하단 띠로 모으고 시계를 중복하지 않는 분담. `Collection/data/feature-map.md:32`, `References/codex-appearance/16/report.md:3–5`.

**손볼 근거가 있음**: 열어 본 전투·입력 목업의 띠는 항목 라벨 위주라 실제 값이 긴 상태를 보여 주지 않는다. 원래 보고도 가장 긴 골드 문자열과 여섯 FontString의 실제 폭을 미측정으로 남겼다. 장식 선을 추가하기보다 값의 폭을 먼저 확인해야 한다. `References/codex-appearance/16/report.md:7`.

총괄의 추가 로컬 시험에서는 실제 포맷으로 만든 긴 값 여섯 개와 여백이 맑은 고딕 목업에서 FHD 633·QHD 689·4K 850픽셀로 기본 띠 폭 안에 들어갔다. 따라서 이 예시에서 폭 부족이 재현됐다고 쓰지 않는다. 게임 글꼴·개인 항목·실제 값의 조합은 별도다. `evidence.json`의 `sample_text_widths.status`, `sample_text_widths.font`.

**실제 접속에서만 관측 가능**: 큰 골드 값, 가방 수와 내구도, 시간·지연·초당 프레임 수치가 동시에 표시되는 폭, 항목을 끄고 켤 때 구분선 위치, 전투 중 표시와 클릭 통과.

**작은 다음 작업**: 로컬에서 폭이 맞은 여섯 값 예시를 게임의 실제 글꼴·항목 조합과 대조한다. 실제 폭이 모자란 항목과 구분선만 조정 대상으로 모은다.

## 퀘스트와 도움말

**유지 가능**: 오른쪽 안쪽 퀘스트, 그 오른쪽 우두머리, 아래 미터기·단축바의 역할 구분. 별도 퀘스트·도움말 애드온을 늘리지 않는 기존 선택. `References/codex-appearance/24/ux/index.md:21`, `Claude/results/REQUEST_LEDGER_phase8.md:13–14`.

**손볼 근거가 있음**: 열어 본 4K 목표창은 짧은 예시 네 줄이며 긴 목표·여러 퀘스트·진행 숫자·완료 표시가 쌓인 상태가 아니다. 제목 36·목표 30픽셀은 목업 기준이며 설치 ZIP에 적용 완료된 값으로 표시하면 오해가 생긴다. 총괄의 ZIP 검색 결과에서 자체 코드의 기본 퀘스트 프레임 참조는 경계를 읽는 SessionProbe 한 곳이다. `ux/index.md:17–21`, `probe.json:596–656`의 `first_party_quest_references`, `selected_source_lines`.

추가 로컬 시험에서 긴 한국어 목표 예시의 폭은 FHD·QHD·4K 각각 750·896·1130픽셀, 목표창 안쪽은 324·384·488픽셀이었다. 현재 목업 렌더는 자동 줄바꿈 대신 길이 오류로 멈췄다. 긴 목표를 여러 줄로 다루는 예시의 빈 곳은 확정됐지만, 게임 기본 창도 같은 오류를 낸다는 뜻은 아니다. `evidence.json`의 `sample_text_widths.quest`.

목표창과 우두머리 후보의 가로 틈은 FHD·QHD·4K 각각 16·16·24픽셀이다. 고정 높이의 후보 사각형 사이 틈이며, 실제 목표 목록이 길어져도 유지된다는 보장은 아니다. 도움말 자리안도 실제 마우스 위치별 배치가 아니다. `probe.json`의 `candidate_quest_to_boss_horizontal_gap`, `References/codex-appearance/24/feature-positions.json`의 `layouts.*.interfaceDraft`.

**실제 접속에서만 관측 가능**: 기본 목표창의 실제 글자 크기·자동 확장·접기, 평소 거리의 4K 가독성, 긴 도움말이 입력·버튼·목표창을 가리는지. 사용자에게 이미 읽기 어렵다는 보고가 있었으므로 우선순위가 높다. `References/codex-verify/phase1/result.md:48`, `References/codex-verify/one-session-review.md:16–17,24`.

**작은 다음 작업**: 긴 한국어 목표와 여러 퀘스트가 쌓이는 예시를 세 해상도에서 준비한다. 실제 기본 창에서 가능한 글자 조정 경로를 확인한 뒤, 원래 확인표의 같은 접속에서 위치·크기·가독성을 함께 기록한다.

## 유닛과 오라·시전·소환수

**유지 가능**: PitBull4 아군 우측·적군 좌측의 기존 정렬, 소환수 대상→소환수→기술바→시전바의 열, 소환수 버튼의 기존 자동 표시. 사용자 대장은 R140에서 “유닛 재배치와 스킨을 범위에서 제외”하고 “직업별 설정이나 별도 토글 없이 기존 버튼 표시 상태 사용”이라고 기록한다. 소환수가 플레이어에서 멀다는 이전 제안을 새 이동 승인으로 다루지 않는다. `Claude/results/REQUEST_LEDGER_phase25.md:35–40`.

**오라 보존 기준**: 기존 상단 오라의 위치·개인 설정을 보존한다. 읽은 기록은 새 프로필의 오라 꺼짐과 기존 상단 표시 보존을 구별하며, 상단 상시 표시를 새로 켜라는 확정 원문은 찾지 못했다. 따라서 오라를 임의로 켜거나 위치를 바꾸는 후속 작업을 넣지 않는다. `Claude/results/Step 40 — Codex pet alignment reference check.md:47–53`, `Claude/results/REQUEST_LEDGER_phase25.md:18,37`.

**손볼 근거가 있음**: 열어 본 소환수 원배율 목업에는 기술 아이콘·랭크·키가 없고, 유닛 예시는 짧은 이름과 단순 체력·자원 막대다. 오라가 많거나 시전명이 길 때의 실제 점유 폭은 확인되지 않았다. 초기 정렬을 보존하면서도 이 상태를 확인해야 한다. `ux/index.md:43`, `References/codex-appearance/6-rev/report.md:19`.

**실제 접속에서만 관측 가능**: 기존 프로필의 상단 버프·디버프, 긴 이름·큰 체력 값·직업 자원, 시전과 채널링, 소환 전후 기술 버튼·테두리 동시 표시, 적대·우호 대상 전환. PitBull4와 Forever Unit Frames는 교대 비교하며 동시에 켜지 않는다. `References/codex-verify/one-session-review.md:8,18,21`.

**작은 다음 작업**: 기존 정렬을 고정한 채 오라가 많은 상태와 긴 시전명, 소환 전후만 같은 접속의 기록에 모은다. 공간 부족이 확인되면 기존 선택을 보존하는 수정 범위부터 정한다.

## 이름표

**유지 가능**: 게임 기본 이름표에 외관만 연결하고 이름표 시전바를 유지하는 선택. 체력 막대 180×20·220×24·280×30픽셀, 이름 18·22·28픽셀은 해상도별 후보다. `Collection/data/feature-map.md:49`, `References/codex-appearance/24/ux/index.md:49–55`, `Claude/results/REQUEST_LEDGER_phase25.md:7`.

**손볼 근거가 있음**: 열어 본 4K 이름표 예시는 두 개의 고립된 막대다. 여러 이름표가 밀집하거나 긴 이름·시전·위협 상태가 동시에 나타날 때를 보여 주지 않는다. 고립된 예시의 가독성을 전투 가독성으로 넓힐 수 없다.

**확정·한계**: 총괄이 실제 ZIP 코드를 사용한 4K 대역 시험에서는 전투 중 새 이름표에 크기·글꼴 쓰기가 모두 0회였다. 전투 종료 뒤 쓰기 가능한 요소에는 각각 1회, 결과 280×30·이름 28픽셀이었고, 보호 요소는 전투 밖에서도 모두 0회였다. 이는 쓰기 경로의 시험 결과이며 게임 이름표의 실제 적용 관측은 아니다. `evidence.json`의 `nameplate_test`와 `game_client_ran`.

**실제 접속에서만 관측 가능**: 전투 중 처음 나타난 적·우호 이름표의 실제 크기, 이름·시전 글자의 겹침, 보호 요소 적용 여부, 밀집한 이름표와 밝은 배경의 식별.

**작은 다음 작업**: 같은 적을 전투 시작 전·중·후로 기록하고, 보호 요소에 후보 크기가 적용되지 않는 경우도 함께 남긴다. 밀집 상태의 문제를 보고받기 전에 전체 크기를 일괄 늘리지 않는다.

## 행동 추천과 게임 기본 쿨다운

**유지 가능**: Hekili는 다음 행동, 게임 기본 Cooldown Manager는 상태와 재사용 대기, 버튼 시간 숫자는 게임 기본 설정이라는 분담. Hekili의 별도 창은 원래 토글이 켜졌을 때만 나타나는 조건을 유지한다. `Collection/data/hekili-current.md:3–9`, `feature-positions.json:10–49`의 `conditions`.

**손볼 근거가 있음**: 기본 쿨다운 네 구역은 목업에서 점선 목표이고 실제 콘텐츠가 아니다. 아이콘 수·버프 막대 길이와 개수가 늘어났을 때의 범위를 확인해야 한다. Hekili도 추천이 없는 치유 특성 네 개를 빈 창 오류로 오해하지 않게 구별해야 한다. `References/codex-appearance/24/ux/index.md:59`, `Collection/data/hekili-current.md:13–19`.

**실제 접속에서만 관측 가능**: 편집 모드의 실제 네 쿨다운 창과 추천창을 동시에 표시했을 때의 크기·글·가림, 버튼 강조와 재사용 숫자, 현재 특성의 추천 동작. 후보 사각형에 교차가 없다는 총괄 결과는 실제 아이콘 수와 글 길이의 상한을 증명하지 않는다. `evidence.json`의 `previous_install_archive_visual_checks.profiles.*.candidate_shared_state_intersections`.

**작은 다음 작업**: 실제 켜진 창만 나열하고 핵심·보조·버프 아이콘·버프 막대가 동시에 보이는 상태를 기록한다. 치유 특성의 추천 미지원과 게임 기본 쿨다운의 표시를 별도 항목으로 남긴다.

## 파티와 공격대

**유지 가능**: 파티와 공격대를 서로 다른 상태로 확인하고, 공격대는 Grid2와 기존 마우스오버 매크로를 사용하는 방식. 새 클릭 치유 기능을 추가하지 않는다. 열어 본 FHD 파티·공격대 목업도 두 상태가 분리돼 있다. `Claude/results/REQUEST_LEDGER_phase8.md:8–10`, `References/codex-appearance/24/ux/index.md:62`.

**손볼 근거가 있음**: 파티 목업은 짧은 라벨, 공격대 목업은 이름·역할·상태 지표가 없는 40칸이다. 치유 시 필요한 이름·상태·거리·사망 표시를 넣었을 때의 밀도는 입증되지 않았다. 같은 배율에서 이름과 상태가 기능 구역 안에 남는지 확인할 이유가 있다.

**후보 교차와 실제 겹침 구별**: 총괄의 계산에서 FHD 파티·파티 소환수·파티 대상의 열을 Grid2와 모두 동시에 보인다고 가정하면 교차가 각각 178×132·96×132·120×132픽셀이다. QHD·4K의 같은 후보 교차는 없다. 총괄이 확인해 전달한 기본값은 PitBull4의 공격대 시 파티 숨김과 Grid2의 공격대 표시다. 이 기본값을 전제로 FHD 기본 배치의 실제 겹침 결함으로 판정하지 않는다. 사용자 프로필이 둘을 함께 표시할 때만 추가 확인한다. `probe.json:525–544`, 총괄 확인 위치 `PitBull4/Main.lua:245–255`의 파티 `raid=false`, Grid2 초기값 `party=None`, `FrameDisplay=Raid`. 이 A는 해당 두 원본의 전문 검토를 별도로 수행하지 않았다.

**실제 접속에서만 관측 가능**: 실제 공격대 인원, 긴 이름, 치유 관련 지표, 마우스오버 대상, 사용자 설정의 파티·공격대 동시 표시 여부. 공격대에 들어갈 조건이 없으면 통과가 아니라 미검증으로 남긴다. `References/codex-verify/one-session-review.md:19,24`.

**작은 다음 작업**: 이름이 길고 상태가 여럿인 멤버를 우선 기록한다. 동시 표시가 관측되면 그 상태에서만 파티와 Grid2의 역할·위치를 다시 판단한다.

**작은 다음 작업**: 기존 두 창을 먼저 확인하고 실제 값이 찬 상태를 같은 배율로 기록한다. 폭을 더 늘리기 전에 어느 문자열과 열이 충돌하는지 모은다.

**손볼 근거가 있음**: 기존 전투·공격대 목업의 얇은 가로 세 구역은 공간 대안이며, 설치본의 세로 표시를 대신한 적용 화면이 아니다. 기존 외관 보고는 높이 10·12·16픽셀 가로 띠 안에서 원래 문구를 전부 읽게 하는 기본값 조합이 없다고 기록한다. 이 차이는 게임 실행을 기다려야만 알 수 있는 사실이 아니다. `References/codex-appearance/19/report.md:19–23`, `feature-positions.json`의 `notes[2]`.

**작은 다음 작업**: 후속 적용 비교에는 실제 세로 표시를 기준으로 놓고 가로 대안은 별도 제안으로 표시한다. 이번 검토에서 원본 막대의 재배치·글꼴 크기 변경을 실행 승인으로 바꾸지 않는다.

## 공통 설정 화면과 확인 흐름

**유지 가능**: 공통 해상도·테마·저장·복원은 Core 명령, 키·오라·추천·미터기 세부는 각 애드온이 맡는 분담. 기능 트리에서 입구를 찾을 수 있다. R107은 통합 편집기 대신 AI로 수정하는 방식을 선택했고, R148은 중앙 설정의 필요성을 검토해 달라는 요청이다. 기존 통합 편집기를 복원하거나 새로 만들기로 확정하지 않는다. `Collection/data/feature-map.md:21–23,67–75`, `Claude/results/REQUEST_LEDGER_phase8.md:20`, `Claude/results/REQUEST_LEDGER_phase25.md:50`.

**손볼 근거가 있음**: 실제 공통 설정 화면의 글·버튼·오류 상태를 보여 주는 자료는 이번에 읽은 입력에서 찾지 못했다. 명령과 기능 트리가 있다고 화면의 사용성 검토까지 완료된 것은 아니다. 필요하다면 공통 배치·테마·복원과 개별 옵션으로 가는 입구부터 작은 범위로 판단한다.

한 접속의 13종 테마 확인에서 기록 손실도 주의할 지점이다. 총괄이 실제 ZIP 코드로 데빌→오크→트롤 기록을 호출한 결과는 테마 행 한 개, 마지막 트롤만 남았다. 13종 전환 절차 자체와 13종 증거 보존은 다르다. `evidence.json`의 `packaged_lua_doubles.themeCaptureCalls`, `themeRowsKept`, `lastTheme`; `References/codex-verify/one-session-review.md:20`.

**실제 접속에서만 관측 가능**: 현재 프리셋·기존 개인값, 명령 실행 시 안내와 복원 결과, 전투 중 변경 지연, 사용자 배율을 바꾼 뒤의 화면.

**작은 다음 작업**: 13종 비교는 테마를 바꾼 그 자리의 화면·상태를 각각 보존하는 방식으로 준비한다. 공통 설정 화면을 새로 만드는 대신 현재 입구와 실제 상태 안내의 빈 곳부터 정리한다.

## 채팅은 확정 기준과 ZIP 차이만 다룬다

**유지 가능**: 게임 기본 수신·송신·한글 입력, 자체 외관, 세 채팅창. 기존 창별 분류와 사용자가 옮기거나 닫은 창을 유지한다. 데빌은 문양 없는 검회색, 나머지 문양은 셋째 창만 사용한다. Prat로 다시 바꾸거나 메시지 엔진을 새로 만드는 안을 넣지 않는다. `Claude/results/REQUEST_LEDGER_phase25.md:9,27,32`, `Collection/data/feature-map.md:38–40`, `Codex/docs/ui-design-criteria.md:15`.

**손볼 근거가 있음·확정**: 승인된 새 HTML의 오크 오른쪽 세로 테두리는 기준 문서에서 49→31픽셀이다. 새 렌더 코드는 오크 폭 변환 비율 0.64와 문양 여백 오른쪽 22·아래 10픽셀을 사용하고, 바탕 마스크 안으로 문양을 합성한다. 현재 ZIP은 문양을 `ARTWORK` 레이어에 만들며 오른쪽 여백은 창 폭의 35%, 아래 여백은 높이의 14.5%다. 자르기 70%와 투명도 16%가 같아도 같은 그림은 아니다. `Codex/docs/ui-design-criteria.md:14–15`, `_local_only/mobile-orc-rail-19/render.py:38–61,77–94`, `Collection/AddOns/DevilForever_Appearance/Composition.lua:118–130`; ZIP 안 같은 코드 위치는 `evidence.json`의 `previous_install_archive_visual_checks.archives.*.selected_source_lines`.

새 목업 기준이 설치 ZIP에 반영됐다고 현재 보고할 수 없다. 특히 “바탕→문양→테두리” 순서와 오른쪽 아래 위치는 다음 적용 작업의 직접 대조 대상이다. 테마의 모서리 차이 자체를 없앨 필요는 없다.

총괄의 추가 해시 대조에서 이전 비교판과 현재 기본 ZIP의 테마 관련 103개는 같았다. 구성은 패널 질감 78개·소환수 테두리 13개·문양 11개·Composition 코드 1개다. 따라서 현재 ZIP이 새 목업을 반영했는지는 확인되지 않은 막연한 의심이 아니라, 기존 테마 입력이 그대로라는 근거와 새 렌더 코드의 변경이 함께 있는 차이다. `evidence.json`의 `current_install_matches_older_theme_archive`.

**실제 접속에서만 관측 가능**: 밝은 곳의 첫째·마지막 채팅 줄, 긴 메시지·여러 줄·한글 조합·입력·스크롤·탭과 기존 분류 보존. 최신 묶음의 채팅 시험 28건 통과 기록을 게임 화면의 가독성 통과로 바꾸지 않는다. `Codex/results/Step 48 — 검토한 ZIP과 기능 기준 확정.md:19`, `References/codex-verify/one-session-review.md:17,20,24`.

**작은 다음 작업**: 승인된 HTML 결과와 ZIP의 테두리·문양·레이어 차이를 한 묶음으로 맞출 범위를 정한다. 반영 후 같은 배율의 글 있는 화면과 실제 ZIP을 직접 대조한다. 새 HTML 해시는 `evidence.json`의 `approved_local_mockup`에 고정돼 있다.

## Windows 설치기 화면

**유지 가능**: 폴더·ZIP·작업을 고르고 변경·보존·충돌을 미리 본 뒤 실행하는 순서, 운영체제 기본 글꼴·색과 자동 줄바꿈. `Collection/Installer/UI/InstallerForm.cs:44–68,77–135,231–249`.

**손볼 근거가 있음**: 긴 한국어 경로와 설명이 많아지는 상황은 코드의 자동 크기와 줄바꿈 선언만으로 판단할 수 없다. 최소 창 크기와 디스플레이 배율별 실제 잘림은 이번에 실행하지 않았다. `InstallerForm.cs:49–51,109–129`.

**실제 접속에서만 관측 가능** 항목과 별개로, 설치기는 **실제 Windows 화면에서 관측할 항목**이다. 대기·충돌·복구 필요·완료 상태, 버튼 접근, 긴 목록의 스크롤과 경로 표시를 같은 창 크기·배율에서 비교한다. 게임 접속은 필요 없다.

**작은 다음 작업**: 실제 설치를 수행하기 전에 기존 로컬 시험 환경에서 긴 경로·많은 행·차단 상태의 화면을 확인한다. 본 검토는 설치기 실행이나 대상 게임 폴더 변경을 수행하지 않았다.

## 후속 작업의 우선순위

1. **로컬에서 차이가 확정된 항목**: 테마 입력 103개가 이전과 같은 현재 ZIP과 승인 채팅 목업의 테두리·문양·레이어 차이, 설치본 세로 경험치와 가로 공간안의 표시 구분, 13종 테마 기록의 마지막 행 덮임.
2. **로컬에서 보강할 수 있는 상태 예시**: 글·버튼이 찬 단축바, 현재 렌더가 줄바꿈하지 못하는 긴 퀘스트, 긴 Details·유닛 이름, 이름·상태를 담은 공격대. 새 목업 생성은 이번 읽기 검토의 완료 조건이 아닌 후속 제안이다.
3. **같은 한 번의 접속에서 관측할 항목**: 실제 해상도·배율, 4K 퀘스트 가독성, 전투 중 새 이름표, 오라·시전·소환수, 실제 쿨다운 내용, 파티·공격대 조건, 밝은 배경과 기존 개인 설정 보존. 상태띠는 로컬 예시 폭 633·689·850픽셀이 들어갔으므로 실제 게임 글꼴·값·설정에서 이어 확인한다.

이 순위는 작업 분석자의 판단이다. 기존 사용자 선택을 새로 열거나 제품 변경 승인으로 쓰지 않는다. 읽은 파일·범위·실행 구분과 제약은 같은 폴더의 `work-log.md`에 남긴다.
