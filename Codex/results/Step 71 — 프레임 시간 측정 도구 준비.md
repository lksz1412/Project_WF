# Step 71 — 프레임 시간 측정 도구 준비

2026-11-19 · Phase 29.5

## 수행

같은 파일을 게임 기본 상태와 모음집에서 사용하도록 측정 도구를 별도 ZIP으로 만들었다. `/dfperf start <이름> [초]`로 시작하고 완료 뒤 `/dfperf report`로 이전 결과를 볼 수 있다. 결과에는 중간값, 95번째·99번째 백분위, 최대 프레임 시간, 샘플 수, 시작 시 대표 애드온의 로드 상태를 담는다.

## 연결과 영향

| 자리 | 영향과 확인 |
|---|---|
| 슬래시 명령과 프레임 콜백 | 실행 대상은 새 도구다. 측정 시작 때만 콜백을 연결하고 완료·취소 때 제거한다 |
| 샘플 배열과 저장 변수 | 진행 중 메모리 65,536개 샘플 한도. 기록에는 최근 12개 요약과 대표 애드온 상태만 저장한다. 이전 스키마와 다른 값은 보존 |
| 실제 ZIP과 로드 목록 | 별도 ZIP에 두 파일. 포에버 Interface 16001. 게임 기본과 시험 모음집에서 같은 코드로 측정 가능 |
| 기존 한 접속 확인 | 같은 조건 비교에만 사용한다. 메모리와 프레임 수는 시험 대역에서 확인했다. 출력값은 실제 게임에 접속했을 때 새로 얻는다 |
| 독립 검수에서 확인한 통계·시작 경계 | `start`에서 연결하는 첫 프레임 콜백은 측정 시작점만 잡는다. 이후 구간을 `sample`에서 읽고 `finish`의 정렬 배열에서 중간값을 구한다. 저장 형식과 p95·p99 계산은 유지하고 `/dfperf report`가 불완전한 기존 행에서 멈추지 않게 했다 |

## 검증

ZIP에서 Lua를 읽어 사본과 바이트를 대조한 뒤 8개 시험을 통과했다. 처음 시작할 때 6초 간격 하나를 제외한 뒤 1·1·2·2초를 기록하면 표본 4개와 중간값 1,500밀리초가 저장과 채팅에 함께 표시됐다. 불완전한 이전 행도 원본을 보존하며 조회를 끝냈다. 유휴 상태, 모음집 없는 실행, 백분위, 취소·재시작, 잘못된 입력, 저장·샘플 한도와 기존 저장 기록을 함께 확인했다.
