Step 46에서 확인한 채팅·유닛 프레임·현행 안내의 결함을 수정했다. 같은 작업자가 독립 검수 두 건을 추가로 재현하고 보정했다. ZIP 안의 최종 채팅 파일을 Lua 5.1에 직접 넣어 재시험했다. [작업 단위별 영향 지도와 실행](audit-installer/step47-work-log.md) · [프로젝트 담당자 확인](../../_local_only/phase26-work-r151-20261119/step47-root-review.md)

## 근거·판단

| 수정 범위 | 판정 |
|---|---|
| 채팅 구독 설정 | 두 창과 필요한 API를 확인하고 원래 구독이 실제로 옮겨진 뒤 정리한다. 일부 실패 시 기존 구독·공개 창의 모든 앵커를 복원한다. 기존 수신 복구가 불가능하면 해당 구독을 받을 수 있는 창을 계속 표시하고 실패를 기록한다 |
| 숨긴 기본명 창 | 창 메시지, 입력 초안과 입력 이력을 지우는 초기화 경로를 건너뛰고 native 창 이름·표시 API를 사용한다. 성공과 실패 모두에서 기존 세 데이터를 보존했다 |
| 프리셋과 화면 배율 | 자동 배치 기록이 있고 직접 변경되지 않은 창을 관리한다. 앞 역할이 실패한 뒤 다른 창이 정상 이동해도 전체 상태에 실패를 유지하고 각 역할의 결과를 기록한다 |
| FUF 비교 좌표 | 원래 설정과 분리한 `DF Compare` 프로필에서 세 해상도 좌표를 FUF 명령으로 보낸다. 두 화면 배율에서 vendor 설정 호출 결과 696개를 확인했다. 명령의 게임 내 표시는 `sent-unverified` 상태로 구분한다 |
| 설정과 사용 안내 | Hekili 추천과 게임 기본 Cooldown Manager의 역할, 세 ZIP의 첫판·대체판·접속 비교 용도, 수동 격리 시험과 일반 미리보기의 차이를 기록했다 |

| 확인 위치 | 영향을 대조한 범위 |
|---|---|
| 채팅 | 설정·배치·시험과 native chat Skin/SessionProbe의 역할 ID 조회. 설치 확인과 진단은 `created` 조건을 대조했다 |
| 유닛 프레임 | 기존 FUF 기본값과 추가 두 Lua, 두 파일의 TOC 로딩 순서, vendor 저장 대기와 원래 프로필 복귀. PitBull4 ZIP 속 FUF 전용 폴더가 없음을 대조했다 |
| ZIP과 문서 | `설치안내.md`의 수동 설치 문구를 소비하는 빌더와 비교 ZIP 검사를 확인했다. 원래 ZIP과 첫 후보를 보존했다 |

코드·시험 정독 범위와 발견별 증거는 작업 기록에 있다. 컴팩션 뒤 마스터 플랜 1–164행, 현행 세부계획 1–38행, Step 46 1–39행, Phase 26.1 결과 1–49행, 세션 대장 1–19행, 실행 대장 1–8행을 대조했다. 활성 규칙 1–153행, 소통 1–87행, 흐름 1–66행, 실행 1–291행, 분업 1–292행과 현재 채팅 입력·작업 기록도 다시 읽었다. 세션 원문 11385행부터 사용자 발화는 R151 `ㄱㄱ` 한 건이고 요청 대장과 같다.

## 실행 결과

- 소스와 새 PitBull4 ZIP의 실제 채팅 Lua에서 각각 28개 통과. 이전 사본은 입력 이력 삭제와 앞 역할의 실패 은폐에서 실패했다.
- 실제 FUF ZIP의 Lua와 포함된 vendor 코드를 실행해 21개 통과를 확인했다. 후속 ZIP에 해당 FUF 파일들의 내부 해시 차이가 없었다.
- 채팅 설치 연계와 역할 ID 진단 통과. 세 ZIP의 최종 파일과 내부 해시, Lua 및 필수 의존성 확인 통과. [새 채팅 시험](../../_local_only/phase26-work-r151-20261119/step47-candidate-02/packaged-chat.log) · [ZIP 검사](../../_local_only/phase26-work-r151-20261119/step47-candidate-02/verify-archives.log)
