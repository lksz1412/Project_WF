# Step 50 — Windows 설치와 복원 계약

Phase 27.1 · 2026-11-19 12:18–12:27:40 +0900 · 예상 45–90분

## 수행

Windows 창과 명령줄이 같은 엔진을 쓰도록 실행과 미리보기, ZIP 승인, 폴더 인수, 적용·검증·복원·제거의 경계를 기록했다. PitBull4와 FUF의 실제 ZIP 두 개를 카탈로그와 대조했다. [설치 계약](../../Collection/Installer/Contract.md) · [작업 기록](audit-installer/step50-contract-work-log.md)

## 근거·판단

- 게임 실행 파일이 있는 `_forever_` 폴더에서 `Interface/AddOns`와 같은 볼륨에 백업·작업 기록을 사용한다. 사용자가 고른 ZIP과 미리보기 확인값을 적용 직전에 대조한다. 일반 설치·복원·제거가 모두 동일한 원칙을 사용한다.
- 승인한 ZIP 전체 SHA-256과 내부 파일 해시, manifest 식별자·버전·Interface·폴더명을 확인했다. 이름이 같은 폴더의 인수는 폴더별로 선택한다. 대상 상태를 확인하지 못한 반대 단독판 폴더가 있으면 쓰기 전에 막는다.
- Windows 단일 파일 실행 시험은 Step 49의 결과로 연결한다. 청정 PC, 게임 동작, 개발한 설치기의 실제 파일 처리 결과는 다음 단계의 실행으로 관측한다.

| 영향 위치 | 확인 |
|---|---|
| 계약과 승인 카탈로그 | CLI·화면·엔진·기록 방향을 연결. 두 실물 ZIP과 내부 구조 대조 |
| 마스터와 세부계획 | 작업 경로 표기를 실제 `Collection/Installer/`와 일치. 후속 구현을 두 스텝으로 구체화 |
| 기존 ZIP 생성과 현행 게임 확인표 | 내용과 입력 계약을 검토. 설치기 범위와 실제 게임 시험의 비교판을 구분 |

## 게이트

독립 열 관점 검수에서 중간 두 건을 확인했다. 같은 작업자가 관리 파일 정보와 최신 복원 기록을 분리하고, 사전 차단 시 관리 영역까지 파일 쓰기 0건을 요구하도록 수정했다. 같은 검수자가 계약 1–140행, 작업 기록 보정절 50–72행, 두 파일의 해시와 수정 시험 조건을 대조했다. 최종 중대·중간·경미 0건이다. 사용량 미관측.
