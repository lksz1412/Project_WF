# Phase 27.2 — Windows 파일 엔진 결과

## Summary

두 승인 ZIP을 선택해 미리보기, 설치·갱신, 검증, 제거 및 복원하는 Windows 공통 엔진을 구현했다. 공개 명령으로 실제 파일을 배치하고 이용자 파일과 백업, 작업 기록의 해시를 비교했다.

## Step Range

51–52. [파일 적용](Step%2051%20%E2%80%94%20Windows%20파일%20적용%20엔진.md) · [파일 복원과 관리 제거](Step%2052%20%E2%80%94%20파일%20복원과%20관리%20제거.md)

## Inputs

두 승인 ZIP과 해시 카탈로그, 설치 계약, 파일 시스템의 실제 경로·잠금·이동 시험을 사용했다. 게임 대역은 각 시험에 맞는 새 격리 폴더다.

## Files Created

C# 설치기 프로젝트와 공통 엔진·명령, 적용·복원·장부 검증 시험. 소스 파일별 내용과 읽은 범위는 각 스텝 기록에 있다.

## Files Updated

Step 51의 설치·검증 경로를 Step 52 복원·제거·중단 처리와 연결했다. 실행 대장과 Phase 27.3 입력을 준비했다.

## Read Coverage

각 스텝 작업 기록과 독립 검수에서 파일별 행 범위, 작업 결과 해시와 후속 호출을 대조했다.

## Execution Evidence

공개 명령에서 미리보기와 설치, 양쪽 판 전환, 같은 판·복원 반복, 수정 폴더 보존 제거, 원래 사용자 폴더 복구를 확인했다. 실제 프로세스 강제 종료와 별도 기록 상태를 복원했다. 시험용 조작과 보정 전후 판정은 각 스텝에 있다.

## Validation and Gate

Step 51–52 통과. 손상 복원 기록은 `invalid-record`로 차단했다. 대상·관리 영역 지문 보존과 현재 기록을 같은 검수자가 보정 전후로 확인했다. 최종 미해결 중대·중간 0건이다.

## Open Issues

Windows 화면과 정식 배포 폴더, 최종 바이너리의 실패 시험, 청정 Windows와 실제 게임을 후속 단계에서 확인한다.

## Decision Queue

파일 엔진에서 사용자 파일 원복과 상태 기록의 상세 규칙은 승인 계약의 범위에서 정했다.
