## Phase Range

Phase 29.1에서 프로젝트별 공식 설명과 포에버 파일 목록을 확보한다. 두 표의 순위, 구성품 관계, 실제 지원 파일, 포에버 콘텐츠 범위, 라이선스 표기와 현재 구성의 담당 기능을 확인한다. 공식 설명만으로 부족한 판단은 원래 만든 쪽의 릴리스, 설정 문서, 공개 소스를 근거로 삼는다. 성능은 활성 조건, 상시 이벤트와 간격 타이머, 화면을 열 때만 수행하는 처리, 전투 중 반복 갱신, 데이터·질감 로드를 확인한다.

Phase 29.2에서 기능별 중복, 손실, 실행 비용을 대조한 뒤 각 프로젝트에 유지·기본 추가 후보·선택 설치 후보·참고·제외·판단 보류 중 하나를 권고한다. 본체와 데이터·라이브러리·콘텐츠 모듈은 각각 순위표에 남기고 실제 설치 조합으로 비교한다. 실행 비용 근거가 부족한 후보는 기본 포함 권고를 보류한다. 승인된 검토 범위 안에서 작업자와 독립 검수자를 같은 유닛으로 두고 직렬로 진행한다.

## Non-goals

검토와 권고의 범위다. 코드, 설치기, ZIP, 기능 트리, 게임 폴더, 게임 설정, 원격 저장소의 수정과 실제 게임 시험은 별도 작업이다.

## Implementation Changes

프로젝트당 한 줄에 두 순위, 핵심 기능, 포에버 지원 근거, 기존 담당, 모듈 관계, 동작할 때의 비용 근거와 채택 이유를 연결한다. 후보를 실제로 더할 경우 필요한 폴더, 설정 기본값, 겹치는 창과 알림, 다른 애드온과 같이 켜는 조건을 기록한다. 나중에 게임 측정이 필요한 후보에는 후보를 끈 상태와 켠 상태에서 같은 조건으로 확인할 항목을 적는다. 라이선스와 재배포 가능성은 별개로 확인하며 확인이 필요한 후보는 직접 설치 방식도 함께 적는다.

## 동봉 애드온과 같은 기능 후보의 비교 순서

기능마다 포에버에서 같은 일을 하는 후보를 골라, 같은 캐릭터·해상도·보이는 창·기능 수로 비교한다. 지원 범위와 표시 정확도가 맞는 후보에서 화면 갱신·데이터 복사·저장·전투 중 실행 비용이 적고 설정 유지가 쉬운 쪽을 기준으로 삼는다. 다른 후보에 가져올 가치가 검증된 처리 방식이 있으면 기준 후보에서 그 부분을 구현한다. 채택한 쪽의 반복 비용도 재현한 뒤 줄인다. 같은 입력의 결과, 기존 설정과 복원이 맞는지 비교하며 언어나 줄 수만으로 성능을 판단하지 않는다.

40개 순위 항목이 30개 판단 행에 모두 연결되는지 확인한다. 우두머리 묶음과 가방 묶음은 필요한 구성품이 드러나는지, 퀘스트와 지도 후보는 원래 창의 담당을 침범하는지 반증한다. 근거가 약할수록 판정을 보수적으로 적고 실제 사용 여부는 현장 확인으로 남긴다.

## Assumptions

- 현 로컬 기준판은 0.1.1 기본판과 대체판이다. 실제 게임에서 활성화된 목록은 이번 작업의 근거에 포함하지 않는다.
- 평가 대상은 고유 30개 프로젝트다. 순위 밖 필수 애드온은 해당 후보의 설치 요건으로만 다룬다.
- 기존 조사에서 공개한 날짜 기준 순위를 고정한다. 승인 뒤 순위 재조회 변동은 확인 날짜와 함께 기록한다.

기존 선택을 기준으로 꼭 필요한 기능과 확인 가능한 실행 비용을 함께 검토한다. 두 조건을 충족하는 경우 기본 포함 후보에 올린다. 결과는 권고로 제출하고 실제 패키지 반영은 후속 결정으로 다룬다. 사용자가 의견을 반영한 이 범위와 아래 기본 대책의 실행을 승인했다.

29.3은 별도로 실행을 승인받은 자체 코드 수정과 로컬 0.1.2 범위다. 프리셋 화면 갱신을 묶고 소환수 이벤트는 해당 단축바만 갱신한다. FUF는 외부 명령과 비교 프로필 계약을 유지하며 반복 조회 비용을 줄인다.

| 멈출 일 미리 점검 | 기본 대책 |
|---|---|
| 새 의존성·설치 | 공개 파일 목록과 원래 만든 쪽의 문서로 의존성을 확인한다. 설치 대상 후보를 바꾸거나 새 도구를 설치할 경우 후속 범위에서 다룬다 |
| 네트워크·외부 호출 | CurseForge와 제작자의 공개 페이지, 릴리스와 문서만 읽는다. 자료를 구하지 못한 항목의 근거 수준을 표시한다 |
| 파괴·비가역 작업 | 신규 검토 기록에만 쓴다. 기존 계획이나 시험 패키지의 자료를 바꿀 필요가 생기면 별도 범위로 남긴다 |
| 권한 부족 | 읽을 수 있는 자료로 독립된 후보부터 확인한다. 확보하지 못한 근거는 표시한다 |
| 세션 전환 | 완료된 후보와 아직 확인할 공식 자료를 기록한다 |
| 검증 미수렴·원래 있던 결함 | 판정과 반대되는 증거를 우선 확인한다. 미해결 결함은 기존 배포판 교체 근거로 쓰지 않는다 |
| 푸시·외부 게시 | 로컬 검토 결과를 대화로 전달한다 |
| 실제 환경에서만 관측 가능 | 게임 내 창과 알림 동작 등은 미검증으로 표시하고 해당 후보의 남은 확인을 명시한다 |
| 모델 미가용 | 지정한 역할을 이용할 수 없으면 영향 범위를 기록하고 다른 후보의 근거 정리를 이어간다 |

분업은 한 유닛으로 순서대로 한다. 근거 수집·권고 작성 뒤 독립 검수를 진행하며 두 작업자가 같은 파일에 동시에 쓰지 않는다.
