## 실패 시험과 실제 판정

각 조건은 검증된 ZIP과 새 격리된 대상을 사용한다. 원래 파일의 검증 해시를 인자로 가져오거나 실행 시점에 다시 계산한다. 정상 설치가 낸 실행 ID로 부분 중단과 복원을 시작하고, 복원 전후의 현재 위치와 기록을 대조한다.

- 승인 ZIP 변경·비교판·대상 링크·손상 기록·기한이 지난 미리보기는 대상과 기록 생성 전에 거부한다. 두 단독판의 미관리·수정 전용 폴더와 관리 중인 공통 파일의 변경을 구분한다.
- 준비본 쓰기 또는 같은 볼륨의 폴더 이동이 실패하면 실제 작업 상태를 읽고 올바른 복원 판정에 도달한다. 잠긴 파일·디렉터리와 파일 시스템 권한을 새 대역에서 재현한다. 디스크 공간은 시험 한도 안에서 능동적으로 검사한다.
- 준비 완료 후, 원본 이동 후, 새 파일 교체 후, 활성 기록을 바꾼 뒤 프로세스가 종료되는 네 시점을 따로 확인한다. 이미 완료한 파일 상태와 잊은 작업 기록의 후속 처리도 확인한다.
- 제거 및 복원 단계 자체를 중단한다. 다시 실행 전에 사용자가 끼워 넣은 파일이 있으면 그 파일과 기존 백업의 위치를 남긴다. 제거는 사용자 변경이 있는 폴더는 보존한 채 나머지 관리 항목만 움직인다.

## 청정 Windows 검증 경계

별도 호스트 또는 초기화된 가상 환경에서 일반 계정으로 실행한다. 개발 PC에서 사용한 자체 포함 시험과 현재 PC의 통상 Windows 실행을 각각 별도 근거로 둔다. 환경을 확보하지 못하면 가능한 격리 시험 결과를 기록하고 청정 Windows 수용을 대기로 둔다. 실제 게임의 파일과 로그인 시험은 Step 57이다.
