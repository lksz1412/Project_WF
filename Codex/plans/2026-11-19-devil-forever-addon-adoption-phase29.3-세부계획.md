|---|---|---|
| 63 | 60–100분 | 프리셋 복원과 소환수 단축바 수정. 프리셋은 세 해상도에서 외관 전체 39회 → 1회, 합성 질감 설정 78회 → 2회. 버튼 10개를 떼고 다시 붙이는 경우 다른 단축바 글꼴 작업 0회, 소환수 쪽은 한 번 갱신 |

## Step 63

1. 활성 프리셋 확정 뒤 화면을 그리는 콜백만 내역을 모아 한 번씩 실행한다. 기존 필드별 저장·알림, 두 프리셋의 합집합 통지, 개별 편집의 즉시 적용은 유지한다. 외관·단축바·이름표·채팅 스킨·상태 띠에서 호출 흐름을 확인한다. 채팅 위치는 이미 프레임 단위로 갱신 요청을 합치므로 기존 방식을 유지한다.
2. 소환수 버튼 부착·해제 알림은 소환수 부분만 다음 화면 갱신에 반영한다. 전체 적용에서 소환수 갱신까지 끝났으면 예약을 중복 실행하지 않는다. 전투 중 변경은 전투 뒤로 넘기고 현재 바와 연결된 버튼만 재확인한다. 화면 배율, 테마, 키 변경의 전체 스킨 갱신은 유지한다.

설계 확인을 위해 0.1.1 ZIP에서 Lua를 메모리로 읽고 외관과 Dominos 두 스킨만 임시로 묶음 적용했다. 세 해상도 전환과 개인 크기 편집값 한 건의 복원에서 외관 전체 1회, 합성 질감 설정 2회를 관측했다. 필드 알림은 세 해상도에서 39개씩, 편집값을 지우는 경우 40개를 유지했다. 이는 설계 확인용 대역이며 나머지 스킨, 전투, 로컬 교체판은 구현 단계의 검증 대상이다.

소환수 쪽도 동봉 Dominos의 실제 `ReloadButtons`를 Lua 대역에서 실행했다. 10개를 떼고 10개를 붙일 때 소환수 글꼴 설정은 100회에서 10회, 다른 단축바의 시험 버튼 글꼴 설정은 20회에서 0회, 새로 예약한 소환수 갱신은 1회였다. 이 대역은 저장소의 제품 코드나 설치 묶음을 고치지 않고 두 방법의 호출을 비교했다.

## Step 64

`/dffuf layout`은 시작할 때 캐릭터를 확인해, 이후 같은 캐릭터의 활성 프로필·프로필 객체·저장 변수 객체와 전투 상태만 검사한다. 명령마다 진단 출력용 상태를 복사할 필요가 없다. 동봉 FUF 0.65.2의 `SetKeys`는 내부 함수다. 외부 저장값은 기본값과 상속값을 생략하므로 비어 있는 값을 비교해서 명령을 생략하지 않는다. 외부 코드의 파일과 프로필 동작은 보존한다.

동봉 FUF 명령을 실제로 호출하는 Lua 시험에서 진단 상태 조회 117회와 명령 116회를 관측했다. 메모리에서만 수정한 안은 진단 상태 조회 1회와 동일한 명령 116회를 보냈고, 같은 이름의 비교 프로필을 다른 객체로 바꾸는 시험에서는 첫 명령 뒤 남은 전송을 중지했다. 외부 명령 자체가 만드는 화면 갱신 비용은 별도다.

## 검증

코드를 실제 Lua 대역으로 실행한 뒤 읽기 전용 아스트라가 연결, 동작 의미, 반증을 순서대로 본다. 특히 사용자 설정이 있는 복원, 전투 중 보류, 탭이나 숨긴 창, 소환수 버튼 교체, 중간 오류, 비교 프로필 이름은 같은데 객체가 바뀌는 경우를 확인한다. 초당 프레임 수와 프레임 시간은 기존 한 접속 확인에서 볼 값으로 남긴다. 세 ZIP과 첨부한 설치기는 단계별로 묶음 로드, 해시, 롤백을 확인한다.

## 실행 확인

게임 접속 없이, 자체 Lua와 검증·로컬 패키지에 한정한다. 외부 애드온 추가, 게임 경로 적용, 공개 배포는 기존 검토 범위와 별도다. 이전 로컬 0.1.1을 복원 기준으로 사용한다. 같은 버전의 기존 파일 위에 출력하지 않는다. 의존 도구는 기존 Windows 설치기 빌드 환경을 사용하고 필요 자료가 없으면 독립 시험을 먼저 진행한다. 근거가 부족한 변경은 검증된 묶음으로 발행하지 않는다.
