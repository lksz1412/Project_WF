## 첫판

Windows 11 x64 일반 계정에서 실행하는 **.NET 자체 포함 EXE + PitBull4 기본 ZIP**을 첫판으로 둔다. 한 배포 폴더에서 EXE를 바로 실행한다. FUF 단독 ZIP은 같은 설치기 카탈로그의 해시가 맞는 로컬 파일을 사용한다. 세 해상도와 13개 테마는 게임 안 Core에서 선택한다. 설치는 오프라인으로 진행하며 시스템 Python, PATH, 게임의 `WTF`는 기본 작업 대상에서 제외한다. 비교 ZIP은 게임 시험에서만 사용한다.

| Step | 예상 | 산출물 | 통과 조건 |
|---|---:|---|---|
| 49 | 30–60분 | 설치기 실행 방식 확인과 도구 사양 | 현재 개발 SDK로 x64 자체 포함 실행 파일의 소규모 기술 검증. 런타임 포함 여부, 일반 계정·오프라인 실행, 시작 시간·크기와 실패 사유를 기록. 완성 설치기의 청정 PC 수용은 Step 56 |
| 50 | 45–90분 | 확정 계약, 설치·복구 상태와 후보 ZIP 카탈로그 | 아래 상태별 쓰기 범위와 완료 판정이 하나로 이어진다. 감사로 확정한 실제 ZIP과 변형·해시 연결. 안전한 재실행·원복이 검증 가능한 시험 케이스로 정의된다 |

## 사용자 화면과 명령줄

두 진입점은 같은 엔진을 호출한다. 화면은 `게임 경로 → 설치판 → 추가·교체·충돌·보존 목록 → 적용 → 결과` 순서다. 명령 이름은 아래 계약용이며 실제 호출 문법은 Step 50에서 확정한다.

| 동작 | 입력 | 파일을 바꾸는 조건 | 결과 |
|---|---|---|---|
| 상태 확인·미리보기 | 확인된 게임 루트, 설치판, 승인 ZIP | 대상의 파일은 읽기만 한다 | 현재 판, 관리 파일, 추가·교체·충돌, 필요한 백업과 여유 공간 |
| 설치·갱신 | 확인된 목표와 미리보기, ZIP 해시 | 게임 종료, 쓰기 권한, 대상 잠금 확보, 미리보기 이후 입력과 파일 및 선택판 충돌이 그대로인지 재확인 | 선택판 파일과 이전 판 전용 폴더의 이동 결과를 검증하고 실행별 설치 기록 확정 |
| 검증 | 대상 루트, 설치 기록 | 대상의 파일은 읽기만 한다 | 누락·해시 다름·새 파일·출처를 확인하지 못한 항목 |
| 직전 상태 복원 | 대상 루트와 승인한 실행 기록 | 백업 해시 및 현재 파일 상태가 기록에 맞고 후속 사용자 변경과 충돌하지 않을 때 | 검증된 직전 상태를 복원하고 실제 결과 기록 |
| 제거 | 대상 루트와 설치 기록 | 관리 범위와 해시 검증 통과. 폴더에 사용자 수정 또는 미확인 파일이 있으면 해당 폴더 보존 | 제거·보존된 관리 폴더와 이유 기록 |

## 충돌 기본값

| 상황 | 기본 동작 |
|---|---|
| 같은 디렉터리, 설치 기록 없음 | 해당 폴더를 보존하고 충돌을 표시한다. 필요 시 한 폴더씩 명시 교체 선택과 검증 백업을 요구한다 |
| 이미 동일 판·동일 내용 | 변경할 항목이 없음을 표시한다. 무의미한 백업이나 교체를 반복하지 않는다 |
| 설치된 판이 더 새로움 | 일반 갱신을 막는다. 이전 판 복원은 승인된 실행 기록과 해시를 다시 확인한다 |
| 관리 중인 PitBull4판 ↔ FUF판 전환 | 기존 판에만 들어 있는 폴더 전체의 소유 기록과 파일 해시가 맞으면, 전환 미리보기에 백업으로 이동할 폴더를 표시한다. 같은 복원 기록으로 새 단독판을 적용하거나 이전 단독판을 복원할 수 있게 한다 |
| 설치 기록이 없거나 수정된 반대판 전용 폴더 | 해당 폴더와 나머지 파일을 보존하고 단독판 적용을 쓰기 전에 막는다. 경로와 이유를 표시한다. 게임 내 켜짐 상태나 `WTF`를 자동 변경하지 않는다 |
| 그 밖의 외부 애드온 혼용 | 기능이 겹치는 조합과 확인한 위치를 표시한다. 기존 폴더의 소유권을 추정하지 않는다 |
| 게임 실행, 대상 잠금, 부족한 용량, 링크·경로 불일치 | 대상에 쓰기 전에 막힌 위치와 해결 조건을 표시한다. 다른 경로를 추정해 설치하지 않는다 |
| 해시 불일치나 모르는 ZIP | 검증에서 실패로 표시한다. ZIP 이름이나 옆에 놓인 사용자가 바꿀 수 있는 해시 파일만으로 신뢰하지 않는다 |

## 파일 적용과 중단 복원

`준비 → 적용 중 → 검증 중 → 완료`를 실행 기록에 남긴다. 진행 중 오류는 `복구 필요`로 표시한다.

1. 대상·ZIP·판·복원 지점을 하나의 작업 기록에 묶고, 같은 게임 루트에서 두 쓰기 작업이 겹치지 않게 한다. 게임 폴더로 해석된 경로를 쓰기 직전 다시 확인한다.
2. 같은 볼륨의 별도 폴더에 압축을 풀고 파일별 SHA-256을 대조한다. 절대경로, 상위 폴더 우회, 대소문자 충돌, 경로의 링크와 다른 장치 파일 이름은 입력 검증에서 다룬다.
3. 적용 전 원본 파일과 해시, 켜질 새 파일을 기록한다. 준비본 교체에 앞서 어느 폴더가 어느 상태인지 기록을 확정한다. 교체가 끝나면 설치된 위치에서 재검증한 후 성공으로 바꾼다.
4. 강제 종료 후에는 기록과 실제 파일 상태가 맞는 지점까지 확인한다. 무조건 처음부터 같은 교체를 반복하지 않는다. 이미 원상태면 끝내고, 검증 가능한 중간 상태는 완료 또는 원복한다. 사용자 변경이 겹치면 자동 복원을 멈추고 충돌과 보존 위치를 보여 준다.

기록에는 실행 ID, 실제 대상 경로 식별, 설치판·ZIP SHA-256, 관리 경로별 변경 전후 해시, 원본 백업 위치, 완료/복구 상태가 들어간다. 사용자에게 제공할 공유 로그는 전체 경로, 계정·캐릭터 이름을 가린다.

두 방향의 판 전환을 시험한다. 적용 뒤에는 이전 판 전용 폴더가 `AddOns` 밖 백업에 있고 새 단독판만 설치됐는지 확인한다. 중단 뒤 원복하면 이전 단독판의 관리 파일과 공통 파일이 되돌아와야 한다. 미관리·수정된 반대판 전용 폴더를 발견한 경우 모든 대상에 쓰기 0건을 요구한다. 시험용 비교 ZIP은 설치기 카탈로그에 넣지 않는다.

## 착수 조건

Phase 26.2가 확정한 배포 기준이 필요하다. 26.2 결과로 ZIP이 바뀌면 카탈로그와 시험의 기준 SHA-256도 함께 바꾼다. 클라이언트 동작이 바뀐 항목은 기존 Step 41의 동일 접속 확인표에 연결한다. 구체화 문서는 설치기의 개발·배포·게임 경로 쓰기를 실행한 결과가 아니다.
