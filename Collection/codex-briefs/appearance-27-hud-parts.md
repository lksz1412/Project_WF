# Codex 외관 발주문 — Phase 27 (아래 HUD 그림을 부품으로)

받는 쪽: Codex. 보내는 쪽: Claude 세션. 사용자 결정(R162): 「테마 그림은 내가 코덱스한테 시킬게 너는 코드단, 위치단 같은 쪽을 봐줘.」 — 그림은 Codex 가 그리고, 부품을 맞춰 붙이는 코드와 자리는 Claude 가 이미 넣었다. Codex 가 할 일은 이 문서의 부품 그림을 그려 싣고, 코드 안 「실린 부품 표」에 이름을 적는 것뿐이다. 게임 입력을 자동으로 보내는 도구는 쓰지 않는다.

- 왜 부품인가: 지금 아래 HUD 는 테마마다 2048×256 띠 그림 한 장과 2048×512 받침 그림 한 장을 화면 너비로 늘려 그린다. 가로세로 배율이 달라(fhd 약 2.2 : 1, qhd 2.6 : 1, uhd 2.9 : 1) 둥근 나사가 타원이 되고, 스킬바 1~3 둘레 테두리는 그림 안에 그려져 Dominos 버튼과 Masque Onyx 테두리 밑에 깔려 가려진다(사용자 지적 R158·R160).
- 바뀌는 방식: 부품 한 장의 텍셀 하나 = 그 화면의 물리 픽셀 하나. 코드는 부품을 늘리지 않고, 길이가 남으면 띠 부품을 옆으로(또는 위아래로) 이어 붙인다. 이음매·나사는 실제 채팅·행동·미니맵 칸 경계에, 스킬바 둘레 테두리는 실제 Dominos 바 1~3 사각형을 재서 그 둘레에 버튼보다 위에 그린다.
- 코드: `Collection/AddOns/DevilForever_Appearance/Composition.lua`(부품 크기 표 `PART_SIZES`, 부품 모양 표 `PART_SHAPES`, 실린 부품 표 `PARTS_SHIPPED`). 부품이 하나라도 빠진 테마·화면은 지금 그림을 그대로 그린다 — 부품을 싣기 전에는 화면이 바뀌지 않는다.

## 1. 만들 것

**테마 13 × 화면 3(fhd·qhd·uhd) × 필수 부품 16장(+ 고르면 문장 1장)**. 테마 id 는 폴더 이름 그대로: `devil` · `alliance` · `horde` · `human` · `dwarf` · `gnome` · `nightelf` · `orc` · `tauren` · `troll` · `undead` · `skyborne` · `skyborne-horde`. 한 테마만 먼저 그려 실어도 된다 — 부품이 다 갖춰진 테마·화면만 새 그림으로 바뀌고 나머지는 지금 그림 그대로다.

**자리·이름**: `Collection/AddOns/DevilForever_Appearance/Themes/<테마 id>/Parts/<fhd|qhd|uhd>/<부품 이름>.tga`(새 폴더).

**형식**: 32bit 무압축 TGA(type 2, 알파 8bit — 기존 `DevilForever_Appearance` TGA 와 같은 형식). 캔버스는 표의 「캔버스」 크기(2의 거듭제곱), 그림은 캔버스 **왼쪽 위**의 「그림」 크기 안에만 그리고 나머지는 완전히 투명하게 둔다 — 코드가 `SetTexCoord(0, 그림 너비/캔버스 너비, 0, 그림 높이/캔버스 높이)` 로 그 영역만 쓴다. 텍셀 하나가 화면 픽셀 하나이므로 표의 크기를 바꾸거나 늘려 맞추지 않는다.

### 그릴 때 지킬 것

1. **이어 붙이는 부품**(`band_fill`·`deck_fill`·`surround_edge_*`)은 표의 방향으로 끝과 끝이 매끈하게 이어져야 한다 — `band_fill` 의 맨 왼쪽 열과 맨 오른쪽 열이 붙었을 때 이음 자국이 없게, `surround_edge_left/right` 는 맨 위 줄과 맨 아래 줄이 그렇게. 마지막 한 장은 코드가 그림 왼쪽(세로 변이면 위쪽)부터 잘라 쓴다.
2. 이어 붙이는 부품에는 **빛 번짐·비네트(가장자리 어둡게)·한 방향으로 밝아지는 명암을 넣지 않는다**, 문장·글자·한 번만 나와야 하는 장식도 넣지 않는다 — 반복되면 줄무늬와 같은 문장이 여러 번 보인다. 문장은 `deck_crest` 한 장으로 따로 그린다(안 그리면 문장 없음).
3. **나사는 `rivet` 한 장으로 그 크기 그대로 둥글게** 그린다. 끝 마감(`*_cap_*`)·이음매(`deck_joint`) 안에 나사를 함께 그려도 되지만, 그 부품도 늘리지 않고 원배율로 그려지므로 둥근 채로 둔다.
4. **스킬바 둘레(`surround_*`)는 9-조각 틀**이다: 모서리 4장 + 변 4장, 가운데는 없다(코드가 가운데를 그리지 않으므로 버튼이 그대로 보인다). 두께 = fhd 6 · qhd 8 · uhd 12 픽셀. 코드는 틀 안쪽 변을 Dominos 바 사각형에서 2픽셀 바깥에 둔다 — 틀은 버튼을 덮지 않는다. 바 1~3이 서로 붙어 있으면(지금 배치) 셋을 감싸는 틀 하나, 떨어져 있으면 바마다 하나.
5. 끝 마감·이음매의 바깥 모양(어깨·뿔·톱니 등)은 그림 크기 안에서만, 넘치는 부분은 투명으로. 캔버스 오른쪽·아래 남는 곳은 완전 투명(알파 0).
6. 테마의 지금 그림(`Themes/<테마>/Composition/<preset>_top.tga`·`_deck(_reviewed).tga`)은 색·재질 참고용으로 보되, 늘어난 그림을 잘라 쓰지 않는다(이유는 맨 위).

## 2. 코드가 하는 것 (그림에 그리지 말 것)

- 위 띠: `band_cap_left` 를 x 0 에, `band_cap_right` 를 오른쪽 끝에, 그 사이를 `band_fill` 로 이어 채움. 지금 그림에 있던 「스킬바가 들어앉는 오목한 홈」은 그리지 않는다 — 바 둘레는 `surround_*` 틀이 버튼 위에서 맡는다.
- 아래 받침: 끝 마감 둘 + `deck_fill` 이어 채움. 이음매 `deck_joint` 는 **실제 칸 경계의 가운데**에 놓는다 — 채팅1|채팅2, 채팅2|행동, 행동|미니맵, 미니맵|채팅3 네 곳(경계 중심 x: fhd 439·879·1291·1485 · qhd 621·1243·1719·1945 · uhd 961·1923·2595·2901). 그림에 칸 구분선·이음매를 그려 넣지 않는다.
- 나사: 이음매마다 둘 — 받침 윗변에서 나사 크기만큼 아래, 아랫변에서 나사 크기만큼 위(가로 가운데 = 이음매 가운데).
- 문장(`deck_crest` 가 있을 때): 오른쪽 채팅 칸 안, 칸 너비의 65% 지점이 문장 가운데, 받침 높이 가운데. 투명도는 그림의 알파 그대로(코드가 따로 흐리게 하지 않음).
- 스킬바 둘레: 로그인·`/reload`·테마 변경 때, 그리고 Dominos 가 바를 다시 배치·이동·크기 변경·층 변경·보이기·숨기기 할 때(프로필 바꿈 포함) DominosFrame1~3 의 실제 사각형을 다시 재서 그린다. 지금 배치의 틀 바깥 사각형(x1, y1, x2, y2): fhd (52, 793, 1868, 859) · qhd (226, 1107, 2334, 1185) · uhd (430, 1709, 3410, 1819). 틀은 바와 같은 층(strata)에서 버튼·Onyx 테두리보다 높은 단(level)에 그려지고 마우스를 받지 않는다. 숨긴 바는 틀에서 빠진다.
- 대체: 테마·화면에 필수 16장 가운데 하나라도 `PARTS_SHIPPED` 에 없거나, 게임이 그 파일을 모르거나, 그리다가 하나라도 실패하면 그 테마·화면은 지금 그림을 그대로 그린다(부품도 둘레 틀도 안 그림). 배치를 편집했을 때는 지금처럼 개별 칸.

## 3. 실은 부품 표에 적기

`Composition.lua` 의 `local PARTS_SHIPPED = {}` 를 실은 파일대로 채운다(이름에서 `.tga` 뺌). 예:

```lua
local PARTS_SHIPPED = {
  horde = {
    uhd = {"band_cap_left", "band_cap_right", "band_fill", "deck_cap_left", "deck_cap_right", "deck_fill",
      "deck_joint", "rivet", "surround_corner_tl", "surround_corner_tr", "surround_corner_bl",
      "surround_corner_br", "surround_edge_top", "surround_edge_bottom", "surround_edge_left",
      "surround_edge_right", "deck_crest"},
  },
}
```

다른 줄은 고치지 않는다. 새 애드온·새 TOC 줄은 없다(TGA 는 TOC 없이 실린다).

## 4. Codex 가 돌릴 확인

1. `python -I Collection/tools/hud_parts.py --check` — 0 problems 여야 한다. 보는 것: 부품 이름, TGA 형식(type 2 · 32bit · 알파 8bit), 캔버스 크기, 그림 밖 투명, 이어 붙이는 부품의 끝–끝 이음(첫 줄과 끝 줄 차이)과 한 방향 명암(4등분 평균 밝기 차 24 이하), 테마·화면마다 필수 16장 전부 또는 0장, `PARTS_SHIPPED` 와 디스크의 완성 묶음이 같은지.
2. `python -I Collection/tests/composition/parts.py` 와 `python -I Collection/tests/composition/run.py` — 모두 PASS.
3. 견본 보기(게임 없이): `python -I Collection/tests/composition/parts.py --preview <스크래치 폴더>` 는 단색 견본 부품으로 fhd·qhd·uhd 배치 PNG 를 만든다(빨간 반투명 상자 = Dominos 바 자리). 실제 그림으로 같은 배치를 보고 싶으면 견본 대신 실은 부품을 쓰도록 바꿔 보는 것은 Codex 판단.
4. 게임 안(로컬 Windows): 실은 테마·화면마다 원배율 갈무리 — 나사가 둥근지, 이어 붙인 곳에 줄무늬·이음 자국이 없는지, 이음매가 칸 경계에 있는지, 스킬바 둘레 틀이 버튼과 Onyx 테두리 위에 보이고 왼쪽 틈이 다른 변과 같은지, Dominos 설정에서 바를 옮기거나 숨겼을 때 틀이 따라가는지, 틀을 클릭해도 버튼이 눌리는지(틀은 마우스를 받지 않음), 부품을 하나 빼 `PARTS_SHIPPED` 에서 지웠을 때 지금 그림으로 돌아가는지, 전투 중 `/reload` 뒤에도 같은지.
5. 올릴 자리: `References/codex-appearance/27-hud-parts/`(새 폴더) — 갈무리와 `index.md`(그림마다 파일·화면·테마 한 줄, 실은 TGA 목록과 크기, 고친 코드 줄 = `PARTS_SHIPPED` 만, 못 한 확인).

## 5. Claude 가 나중에 하는 정적 확인

Codex 결과가 올라오면 Claude 가 `hud_parts.py --check`, 두 시험, `extract.py` 뒤 manifest·`genregistry.py --check`, 빌드 dry-run 두 변형(늘어난 파일 수 = 실은 TGA 수)을 돌리고, `PARTS_SHIPPED` 밖의 코드 변경이 없는지 본다. 게임 동작 검증은 아니다.
