# Devil Forever Windows 설치 계약

Windows 11 x64 일반 계정용 오프라인 설치기의 구현 기준이다. Windows Forms 화면과 명령줄 인터페이스(Command-Line Interface, CLI)는 같은 엔진의 입력·미리보기·결과를 사용한다. 계약은 Step 50에서 작성하며 실제 파일 적용·중단 복원·청정 Windows 실행의 판정은 후속 시험에서 남긴다.

## 배포 입력과 대상

실행 파일에 `ReleaseCatalog.json`을 포함한다. 기본 배포 폴더에는 PitBull4 ZIP을 두며, FUF는 승인 카탈로그와 맞는 로컬 ZIP을 고른다. 파일명이 바뀌어도 실제 전체 SHA-256으로 항목을 식별한다. 판 식별자, 표시 버전, ZIP 해시는 각각 기록한다. 같은 버전의 다른 바이트를 동일 배포로 취급하지 않는다.

| 항목 | PitBull4 | FUF |
|---|---|---|
| 식별자 | `pitbull4` | `fuf` |
| 버전·Interface | `0.1.0` · `16001` | `0.1.0` · `16001` |
| 기본 파일명 | `DevilForever-0.1.0.zip` | `DevilForever-0.1.0-fuf.zip` |
| 애드온 폴더 수 | 35 | 37 |

정확한 해시·바이트·폴더명은 [카탈로그](ReleaseCatalog.json)의 값으로 빌드 때 고정한다. `one-session` 비교 ZIP은 게임 시험용이며 설치기의 승인 항목에 들어가지 않는다. 세 해상도와 13개 테마의 선택은 게임 안 Core와 개별 애드온에서 한다.

선택 경로는 `_forever_` 에디션 폴더이며 바로 밑에 일반 파일 `Wow.exe`가 있어야 한다. `Interface/AddOns`가 없으면 설치 미리보기에 생성 항목을 넣는다. 로컬 절대경로를 사용하며 모든 기존 조상과 관리 대상에서 재분석 지점(reparse point)·링크·대소문자 중복을 검사한다. 정규화한 경로와 실제 루트의 식별을 미리보기와 쓰기 직전에 대조한다. 검사하지 못한 경로와 다른 게임판은 적용할 수 없다.

파일 적용 범위는 선택한 에디션의 `Interface/AddOns`와 같은 볼륨의 `DevilForever-installer` 관리 폴더다. `WTF`, 키 설정, 매크로, 캐릭터별 저장 변수와 게임 실행 파일은 애드온 설치 엔진의 쓰기 대상에 포함하지 않는다. 게임이 실행 중이거나 쓰기 권한·잠금·여유 공간을 확보하지 못하면 적용 전 결과에 원인을 낸다. 관리자 권한 상승을 요청하지 않는다.

## 공개 명령과 화면

`DevilForeverSetup.exe`를 인자 없이 열면 화면을 표시한다. CLI는 아래 명령을 사용한다. `--game`은 에디션 폴더다. `--package`를 생략한 설치는 실행 파일 옆의 기본 PitBull4 ZIP을 사용한다. `--json`은 공통 결과 객체를 표준 출력에 출력하며 진행 메시지는 표준 오류에 쓴다.

```text
inspect  --game <경로> [--json]
plan     --game <경로> [--action install|rollback|remove] [--package <ZIP>] [--replace <폴더>] [--json]
apply    --game <경로> [--package <ZIP>] [--replace <폴더>] --confirm <값> [--json]
verify   --game <경로> [--json]
rollback --game <경로> --confirm <값> [--json]
remove   --game <경로> --confirm <값> [--json]
```

`plan`의 기본 동작은 `install`이다. `--replace`는 같은 이름의 미관리 폴더 한 개를 검증 백업 후 인수하는 선택이며 반복 지정할 수 있다. 목록 밖의 이름·중복·다른 경로는 입력 오류다. 미관리 반대판 전용 폴더와 변경된 관리 폴더는 이 선택으로 넘길 수 없다. 복원과 제거에는 ZIP·교체 선택을 받지 않는다.

| 명령 | 공통 엔진의 결과 | 대상에 쓰는 시점 |
|---|---|---|
| `inspect` | 경로·활성판·버전·관리 여부·미완 실행과 복원 가능 여부 | 읽기만 |
| `plan` | 추가·교체·전환 이동·보존·충돌 목록, 필요 공간, 대상 작업과 확인값 | 읽기만 |
| `apply` | 승인한 계획을 다시 계산하고 설치·갱신·판 전환 | 유효한 확인값과 실행 직전 검사를 통과한 뒤 |
| `verify` | 활성 기록과 파일별 누락·변경·추가 파일을 대조 | 읽기만 |
| `rollback` | 미완 실행의 원상태 또는 직전 완료 적용·제거의 이전 상태 복원 | 복원 계획·백업·현재 파일 확인 뒤 |
| `remove` | 원래 관리 파일과 일치한 폴더 이동, 수정된 폴더 보존 | 제거 계획·현재 파일 확인 뒤 |

읽기 명령은 게임 루트 안에 잠금 파일·로그·백업·빈 폴더를 만들지 않는다. 불완전 기록을 발견해도 읽기 명령에서 자동 복원하지 않는다. 엔진은 읽기 결과를 그대로 UI에 반환한다.

화면은 `경로와 현재 상태 → 판/ZIP 선택 → 미리보기 → 적용과 진행 → 결과`로 이어진다. 경로·판·ZIP·인수 선택을 바꾸면 이전 미리보기 확인을 해제한다. 적용 중에는 중복 실행을 막고, 취소가 안전한 준비 구간인지 파일 이동 구간인지 표시한다. 이동이 시작된 뒤에는 현재 작업의 복구 상태를 확정한 다음 창을 닫는다. 강제 종료는 중단 복원으로 다룬다.

## 미리보기와 확인값

미리보기 확인값은 대상 식별, 작업 종류, 선택 ZIP 전체 해시, 정렬한 인수 폴더명, 현재 활성 기록의 해시, 미완 실행의 식별자와 기록 해시, 읽은 변경 대상의 존재·파일 목록·파일 해시에서 계산한다. 복원은 선택한 실행 ID와 검증한 백업 지문을 포함한다. 동일 상태와 동일 입력은 같은 값을 만든다.

`rollback` 계획은 미완 복원 실행이 있으면 이를 대상으로 고정하고, 그런 실행이 없으면 미완 적용·제거를 고른다. 복원 실행은 `revertsRunId`로 원래 실행과 연결하므로 그 두 기록은 같은 복구 흐름으로 센다. 서로 연결되지 않은 여러 미완 실행이나 끊긴 참조는 충돌이며 대상 ID를 추정하지 않는다. 미완 실행이 없고 활성 기록의 최신 완료 동작이 `install` 또는 `remove`이면 그 실행 ID를 고른다. 최신 완료 동작이 `rollback`이고 현재 파일이 활성 payload와 일치하면 파일 쓰기 없이 `no-change`를 반환한다. 이후 파일이 바뀌었으면 충돌로 표시한다. 이후 완료한 새 적용·제거만 다음 복원 대상을 갱신한다. 계획에는 고른 ID와 복원 전후 판을 보여 준다. 확인값이 그 ID를 포함하므로 다음 명령에서 대상이 바뀌면 실행을 거절한다.

쓰기 명령은 대상 식별에서 정한 운영체제 named mutex로 배타 잠금을 확보한 다음 기존 활성 기록과 파일을 읽어 같은 계획을 다시 계산한다. 이 잠금은 대상에 파일이나 디렉터리를 만들지 않는다. 확인값이 다르거나 게임 실행·경로 식별·재분석 지점·디스크 공간·백업 읽기·소유권·반대판 충돌 검사를 통과하지 못하면 `blocked`로 끝낸다. 모든 실행 직전 검사와 확인값 대조를 통과하고 실제 변경이 있을 때만 관리 디렉터리·로그·실행 기록·준비본 생성을 시작한다. 오래된 확인값, 충돌, `no-change`의 게임 대상과 관리 영역은 파일 목록·해시 전후 차이가 0이어야 한다.

이미 같은 승인판이고 관리 폴더 전체가 같은 경우는 `no-change`다. 대상 상태를 그대로 두며 새 실행·백업·완료 기록을 만들지 않는다.

## ZIP 검증과 소유권

승인 ZIP은 읽기 스트림을 열어 전체 길이·SHA-256을 확인한 뒤 같은 스트림으로 압축 목록과 파일을 읽는다. 읽는 동안 다른 쓰기나 교체를 허용하지 않는다. 내부 `DevilForever-install/manifest.json`의 schema·버전·Interface·`unit_frames`·폴더 목록은 승인 항목과 일치해야 한다.

파일 항목은 `Interface/AddOns/<승인 폴더>/...`와 `DevilForever-install/` 아래 문서·검증 파일로 제한한다. 빌더가 넣는 `Interface/`, `Interface/AddOns/`, `DevilForever-install/`의 명시 디렉터리 항목을 허용한다. 경로는 `/` 구분으로 정확히 해석하며 절대경로, 빈 중간 요소, `.`·`..`, 역슬래시, 드라이브·대체 데이터 스트림 표기, Windows 예약 장치명, 금지 문자, 후행 공백·점, 링크·특수 파일, 대소문자 별칭, 파일과 디렉터리 충돌을 거부한다.

`SHA256SUMS.txt`는 자신을 제외한 모든 일반 파일을 정확히 한 번 포함해야 한다. 내부 매니페스트·안내 파일도 검사한다. 설치할 일반 파일은 전수 해시 검증한 후 같은 볼륨의 준비 위치에 놓고 다시 읽어 대조한다. 문서와 ZIP 내부 해시 파일은 관리 실행 기록에 보존하며 `AddOns`에 넣지 않는다.

| 현재 폴더 상태 | 설치·갱신 처리 |
|---|---|
| 없음 | 추가 |
| 현재 관리 기록의 파일 전체와 일치 | 필요한 교체 또는 동일 항목 유지 |
| 같은 이름의 미관리 폴더 | 기본 충돌. 해당 폴더를 명시 선택했으면 현재 파일 전체를 검증 백업한 뒤 인수 |
| 관리 기록과 다른 파일 또는 추가 파일 | 보존하고 적용 차단 |
| 반대판 전용 폴더가 관리 기록과 일치 | 전환 작업의 백업 이동 목록에 포함 |
| 반대판 전용 폴더가 미관리 또는 수정됨 | 전환 전체를 애드온 쓰기 전에 차단 |
| 더 새로운 관리 버전 | 일반 갱신 차단. 기존 복원 기록을 통한 복원만 허용 |
| 그 밖의 애드온 | 보존. 겹치는 기능의 알려진 폴더가 있으면 확인한 이름을 안내 |

관리 중인 폴더의 비교는 파일 일부의 일치로 끝내지 않는다. 예상된 모든 파일과 새 파일·빈 디렉터리·링크의 존재까지 대조한다. 깨진 기록이나 현재 파일만으로 소유권을 새로 만들지 않는다.

## 파일 기록과 상태 전이

`DevilForever-installer/active.json`과 `runs/<runId>/journal.json`을 사용한다. 실행별 `stage/`, `before/`, `displaced/`는 같은 관리 폴더 안에 둔다. 실행 ID는 경로 요소 하나로 검증하고 기록 속 상대 경로는 허용된 관리 영역에서만 해석한다. 기존에 관리 폴더와 이름이 같은 미확인 데이터가 있으면 초기화하지 않고 충돌로 표시한다.

`active.json`에는 schema, 대상 식별, 최신 완료 실행의 `lastRunId`와 `lastAction`, 현재 판·버전·ZIP 해시, 현재 관리 폴더의 파일 목록·해시, 보존한 수정 폴더와 사유를 둔다. 판·파일·보존 정보는 현재 관리 payload이며 최신 완료 실행의 두 필드와 별개다. 설치가 없는 복원 상태도 payload에 `none`으로 명시한다. `journal.json`에는 schema, 실행 ID, 작업·판·ZIP, 대상 식별, 확인값, 전체 이전 활성 기록과 예정 활성 기록, 폴더별 이전·이후 지문, 이동 원본·목적지, 쓰기 의도와 완료 상태, 실패 원인을 기록한다. 복원 실행은 원래 실행을 가리키는 `revertsRunId`도 기록한다.

기록은 임시 파일에 완전히 쓰고 flush한 뒤 같은 디렉터리에서 교체한다. 각 이동의 의도를 기록에 확정한 후 폴더를 이동하고 실제 위치·내용을 확인한 다음 완료 표시를 확정한다. 마지막으로 설치된 파일을 전수 검증한 뒤 활성 기록을 교체한다. 활성 기록이 확정되기 전에 `completed`나 설치 성공을 표시하지 않는다.

| 상태 | 남아야 할 증거와 다음 동작 |
|---|---|
| `prepared` | 모든 준비 파일과 원상태 지문·예정 이동·이전 활성 기록. 아직 원본 이동 전 |
| `applying` | 원본→`before`, 준비본→대상 등 이동별 의도·진척. 실제 위치로 재판정 가능 |
| `verifying` | 모든 예정 이동 후 대상 전체 검사. 성공할 때 활성 기록 교체 |
| `completed` | 대상 지문과 새 활성 기록이 일치. 성공 반환 |
| `recovery-required` | 중단·오류와 현재까지의 이동 기록. 후속 설치·갱신·제거 차단 |
| `restoring` | 복원 이동의 의도·진척과 복원 목표 활성 기록 |
| `restored` | 원상태 지문과 복원 목표 활성 기록이 일치. 복원 성공 반환 |

중단 복원은 journal의 마지막 표시만 신뢰하지 않는다. 대상·준비본·백업·이동 보관본을 읽어 각 폴더의 기대 지문이 실제 어디에 있는지 확인한다. 이동 직후 완료 표시가 빠졌거나, 활성 기록 교체 직후 종료된 경우도 같은 방식으로 판정한다. 완료 판정에는 payload뿐 아니라 `lastRunId`·`lastAction`이 해당 실행의 예정 활성 기록과 같은지도 확인한다. 대상과 그 활성 기록이 이미 완료 목표와 같으면 완료 기록만 확정할 수 있다. 그 밖에는 검증한 원상태로 복원한다. 충돌이나 유일한 원본 부재는 자동 이동을 멈추고 `recovery-required`와 보존 위치를 표시한다.

복원도 새 실행 기록을 만든다. 원래 설치·제거 실행의 백업은 유지하고, 현재 폴더는 복원 실행의 `displaced`에 옮겨 둔다. 복원할 예정 활성 기록은 이전 판·파일·보존 payload에 새 복원 실행의 `lastRunId`와 `lastAction=rollback`을 붙인 전체 객체다. 이전 활성 snapshot의 완료 실행 ID를 최종 pointer로 복사하지 않는다. 복원 파일과 이 예정 객체를 검증한 뒤 객체 전체를 원자 교체한다. 역방향 이동과 활성 기록 교체를 각각 기록하므로 복원 도중 다시 종료되어도 다음 `rollback` 계획은 그 미완 복원 실행을 같은 목표까지 이어간다. 복원을 되돌리려는 중첩 실행을 자동 생성하지 않는다. 완료한 복원은 같은 명령의 반복에서 `no-change`로 처리하며, 새 적용·제거 전까지 또 다른 과거 실행으로 넘어가지 않는다.

## 제거와 충돌 보존

제거 미리보기는 관리 기록과 완전히 같은 폴더만 이동 대상으로 고른다. 사용자 수정·새 파일·미확인 항목이 있는 관리 폴더는 전체를 보존하고 사유를 표시한다. 이동하는 폴더와 기존 관리 기록은 제거 실행에 남긴다. 보존 폴더는 활성 기록의 `preserved` 항목에 유지하여 다음 실행이 이를 깨끗한 제거 또는 미관리 인수 가능 상태로 오인하지 않게 한다.

제거 도중 종료되어도 설치와 같은 위치·지문 대조로 중단 복원한다. 완료 제거의 직전 복원은 제거 전 관리 파일·보존 폴더·활성 기록을 복원한다. 그 사이 사용자가 같은 이름의 폴더를 새로 만들거나 파일을 바꿨으면 그 위치를 덮어쓰지 않고 복원 충돌로 남긴다. 백업과 실행 기록의 정리는 자동 제거 범위에 넣지 않는다.

## 공통 결과와 종료 코드

공통 결과 schema는 `devil-forever-installer-result/1`이다. `action`, `status`, `exitCode`, `target`, `package`, `runId`, `planToken`, `changes`, `preserved`, `conflicts`, `issues`, `recovery`를 사용한다. 현재 명령에 없는 값은 `null` 또는 빈 목록이며 과거 실행의 값을 섞어 반환하지 않는다. `target`의 실제 경로는 로컬 화면과 명시한 JSON에만 나온다. 공유용 복사 내용은 관리 상대 폴더명·판·작업 ID·상태·오류 종류를 사용한다.

| status | 종료 코드 | 뜻 |
|---|---:|---|
| `ready` | 0 | 상태 조회 또는 실행 가능한 미리보기 |
| `no-change` | 0 | 할 변경 없음 또는 이미 같은 복원 목표 |
| `completed` | 0 | 적용·제거의 파일과 기록 확정 |
| `restored` | 0 | 복원 목표의 파일과 기록 확정 |
| `blocked` | 2 | 입력·권한·경로·실행 중 게임·잠금·충돌·구버전 적용 등 조건 불충족 |
| `recovery-required` | 3 | 쓰기 중 실패 또는 미완 실행이 있어 복원이 필요 |
| `differences` | 4 | 읽기 전용 검증에서 누락·수정·추가 항목 발견 |

관리 기록이 없는 정상 위치의 `inspect`는 `ready`와 관리 상태 `none`을 반환한다. 같은 위치의 `verify`는 `blocked`와 `not-managed` 사유를 반환한다. 손상된 기록은 `blocked`, 실제 파일 이동 후 미완 기록은 `recovery-required`다. 실패를 성공 코드로 바꾸거나 기본 ZIP으로 조용히 바꾸지 않는다.

## 후속 시험의 수용 조건

| 실제 흐름 | 수용할 결과 |
|---|---|
| 새 `_forever_` 대역에서 조회·미리보기 | 경로·파일 전후 목록·해시 일치. 관리 기록 생성 0 |
| 실제 승인 ZIP 신규 설치와 같은 설치 반복 | 카탈로그·대상 전수 일치. 반복 시 백업·새 실행 기록 추가 0 |
| PitBull4→FUF→PitBull4와 직전 복원 | 공통·전용 폴더와 관리 기록 일치. 무관 애드온·`WTF` 대역 해시 보존 |
| 설치 A→설치 B→복원→복원 반복 | 첫 복원은 A의 payload와 새 rollback 실행 ID·동작을 확정. 둘째는 `no-change`이며 대상·관리 파일 전후 지문 동일 |
| 미관리 인수·수정 관리 폴더·반대판 충돌 | 명시한 일반 폴더만 인수. 반대판·수정 관리 충돌에서 대상과 관리 영역의 파일 쓰기 0 |
| blocked·오래된 확인값·no-change | named mutex만 사용. 대상·관리 파일 목록과 해시 전후 차이 0. 관리 영역이 없으면 계속 없는 상태 |
| 변조 ZIP·비교 ZIP·입력 교체·경로 탈출·이중 실행 | 거부 사유와 종료 코드. 다른 경로·다른 판에 쓰기 0 |
| 준비·원본 이동·새 폴더 이동·활성 기록 교체 직후 종료 | 다음 계획이 실제 지문으로 완료 여부·복원 목표를 선택. 확인 뒤 원상태 또는 확인된 완료 상태 |
| 복원·제거 자체의 파일 이동과 기록 교체 중 종료 | 같은 목표까지 복원 가능. 중간 사용자 변경은 보존·충돌 표시 |
| 한국어·공백 경로의 EXE와 실제 화면 | CLI와 화면의 결과·선택 일치, 일반 사용자 토큰, 외부 Python·.NET 설치 요구 없음 |

이 표는 후속 실행의 수용 기준이다. 개발 PC 도구 시험과 게임 실제 표시·청정 Windows 실행의 결과는 각 단계에서 따로 기록한다.
